## 1. 上下文

- 路线文档决策第 3 项：签认机判载体三选一（OpenBao transit 签名 / escrow 解锁 / 带外通道回执），
  「载体未定则『非 owner 手签不可 ENTER』无机判载体、无法验收」
  —— `archive/2026-10-10-pre-v1/agent系统现状与目标差距-开发路线-2026-10-09.md:174`
- 现状：0.4 卡已把 escrow 解锁件当**临时载体**推进，age 密钥由本轮 agent 生成并代持，
  签认仍是体系自证 —— 拍板清单 `archive/2026-10-10-pre-v1/owner拍板清单-2026-10-10.md:73`
- 批次 3 P0-3 引入的回归件（在 gov `/opt/opch/secrets/`）：`owner.key`（agent age-keygen 私钥，0600 root）、
  `owner.pub`、用该 key 加密的 `root-token.age` 与 `unseal-key.age`
  —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md §4「escrow 密钥体系」（agent 引入的回归件清单）`
- **后果**：agent 持有 `owner.key` 即可自行解封，绕过 owner 的 escrow 主权设计 —— 同上 `:95`
- owner 的原设计（完好）：本机 + gov 两处各存一份 age 口令加密的 escrow 密文包（内含
  `vault/root-token.age` + `vault/unseal-key.age` + manifest + 工具），由 owner 自己知道的密码解密
  —— 同上 `:73-85`

## 2. 决策（owner 原话，逐字）

> 「我记得原来 key escrow，当时就已经是我填入我自己的密码以后封存出来的一个情况。只有 key escrow 不够吗？
> 还搞这两个 key 意义是什么？同样的按原来的设计挺好的，escrow 多处实例存档，然后由我自己知道的密码去解密。」
> —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md §4「escrow 密钥体系」`

决定（§2 表，短句）：

> 「原来就是 escrow，按原设计恢复」
> —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md:36`

## 3. 后果

**影响**

1. 签认载体终选 = **escrow 解锁件**（拍板清单 C 选项②），不再评估 transit 签名 / 带外回执。
2. 密钥主权归 owner：agent 不得持有任何可解封 escrow 的私钥。
3. 脚本实现口径随之变更：`age -d -i owner.key` → 走 `openbao-escrow unlock`
   —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md §4 待执行第 2 条`

**后续动作（批次 9.1 执行面）**

- 删 agent 生成的 `owner.key` / `owner.pub` 及对应的 `root-token.age` / `unseal-key.age`
  —— 同上 `:98`
- 改 m1-enter / 解锁脚本走 `openbao-escrow unlock`；owner 原 escrow 设置**保持不变** —— 同上 `:100`
- 处置完成后须重跑 `--enter` 验 `escrow_unlocked` 读数（拍板清单归位四步的末验，`:77`）

**遗留（owner 知情的老问题，不在本 ADR 范围）**

- escrow 在机 3 份但**零离机副本** —— `协作落实/决策文档.md:223`（转引自交接 `:102-105`）：
  单机灾难 = PKI 根与长期凭据永久丢失。建议往 owner 笔记本或云盘存一份，不急但需知。
