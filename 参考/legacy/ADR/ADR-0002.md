## 3. 后果

**影响（执行实况，如实登记）**

1. 系统激活 v1 A 段已实跑：实测 3/5 真启用并在役（sec-core / skillfs / agentsight）
   —— `产出/实施系统激活v1-2026-10-10.md` §2-3
2. **2/5 未启用，原因不是漏做**：
   - `cosh-ng`：真入口实跑报 `profile_invalid`，`doctor` 报 ACP adapter `codex-acp` 不在 PATH，
     且单元要求 `EnvironmentFile=/etc/cosh/gateway-%i.env` 而 `/etc/cosh/` 不存在 → 属选型决策不是接线动作；
     且按 A5（ADR-0001）agentscope 编排层已覆盖「网关」职责，v1 内非必需
     —— `产出/实施系统激活v1-2026-10-10.md` §3.2
   - `agent-memory`：`serve` 是 MCP over stdio，按需 init / 按需被 MCP 客户端拉起，
     systemd `Type=simple` 只会反复起退 → **形态本来就不是 daemon**
     —— 同上 §3.2
3. A 段汇总复核判定 **passed=false**（判据 ①③ 未过）
   —— `产出/实施系统激活v1-2026-10-10.md` §1 表

**后续动作**

- 本 ADR 的授权闸门已开（「能不能启用」不再是问题），但**追认签认件本身仍需补**：
  10-06 安装的授权来源至今未在仓内定位（路线 `:197`），建议以本 ADR 作为追认凭证由 owner 补签一次。
- F1 分发权威、runc 池判据、ktuner 去向三个子项仍挂在 1.1 卡内
  —— 拍板清单 `:67-68`，未随本 ADR 自动裁决。
- cosh-ng / agent-memory 的处置按上面「架构阻塞」记录，**不在本 ADR 承诺的 5/5 范围内**；
  若后续要强启用，须走独立选型卡（§2.2 建议启动 ACP 适配器选型）。
