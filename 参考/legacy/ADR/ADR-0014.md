## 1. 上下文

- 原 ADR-0014（2026-10-10 占位）登记了 B7 三方冲突：tailnet 全 mesh + Tailscale SSH 直通 root
  vs 方案 §6 权限逐跳收敛 vs 路线 4.3 验收判据；实机当时是 `src:* → dst:*:*`、
  anuser 免密 sudo、gov 8300 无鉴权全量可读、grant.rego 显式拒绝零命中。
- 2026-10-11 owner 在确认编译包上线计划时拍板（原话要点）：**采用分层收敛**——
  owner 设备保持全通；执行机只放通实际要用的 gov 服务端口；每个角色再在主机内用
  cgroup 级 nftables 收窄；agent 专用账户无特权；anuser / dispatch 逐步去 sudo；
  一切变更先备份、过防锁死探针、可回滚。

## 2. 决策

1. **tailnet 分层**：owner 设备（pandev 等）与边界面（hk / edge-server）保持全通；
   gov 作为源只允许 → anolis:22,8123 + 互联网；执行面 anolis 在其→gov 的 SSH 依赖
   （dispatch 选择器、three_domain、obs bearer）迁移到 `/etc/opch/pg.env` 与治理网关后，
   再收窄到只放通目录端点。
2. **主机内**：agent 任务在 anolis 以无特权 `opch-agent` 运行；每个角色独立 uid、
   独立挂载视图、cgroup 级 nft 放行（exec-plane 已落地）。
3. **去 sudo 顺序**：先迁 dispatch 到 opch-agent（P4 已把策略包执行分流），
   观察无 sudo 调用后再收 anuser 的 NOPASSWD。
4. **变更纪律**：先备份、防锁死探针全绿、看门狗自动回滚，才允许切换。

## 3. 后果

**已落地（2026-10-11，报告 `产出/strategy-compiler/bootstrap/report-tailnet-layer.md`）**
- headscale policy 分层 v2 生效（负控 gov→pandev / gov→hk 已阻断）。
- 8300/8310/8787 实测已绑 tailnet 地址，无需再改；tailnet 内访问由 ACL dst 侧控制。
- OPA `actions_denied` 有了执行者（opa-plane）。

**待做**
- anolis 收窄（依赖项迁移后）；tag 体系（headscale tag 不可逆，暂缓，先留 tagOwners 再引入）；
- anuser NOPASSWD 收窄；dispatch 旧路径去 root（P8）。
- 可观测触发信号（拍板清单 :161 的 6 项）随 P5 看板一并接入。

**风险**
- gov 作为源只剩 anolis 两端口：未来 gov→其他节点的运维需求要显式加规则（回滚见报告 §6）。
- Tailscale SSH 仍按用户（edgenet）全员 root——headscale v0.29.3 的 ssh src 无法按节点收窄，
  要等 anolis 迁用户或新版本能力。
