## 1. 上下文

- 双锚并存：root 锚（`/etc/systemd/system/zcode-headless.service`）与 user 锚
  （`zcode-headless@pan-ding.service` + linger）共享 `~/.config/ZCode` profile，
  且两者的 `ExecStartPre` **互相清 SingletonLock**，各自 active
  —— `archive/2026-10-10-pre-v1/owner拍板清单-2026-10-10.md:275`
- 后果：双锚互清锁 = 脆弱共生；不拍则后续卡不知以哪个为门 7 执行体 —— 同上 `:277`
- 证据链：批次 2 `:164-165`（P3 #11）、批次 2 `:20`（1.2-panding caveat：批次 1 与部署件路径不统一）
- 拍板清单的建议默认是「U（user 锚+linger 已实测耐 logout 语义更净；
  **root 锚退役前先过 1.2-panding 的 terminate-user 真演练** = D4③）」—— 同上 `:279`

## 2. 决策（owner 原话 / 记载）

> 「退役 root 锚，默认用 pan-ding user 锚」
> —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md:44`（§2 D5 行）

**原话性质说明**：以上为交接文档表格内 owner 决定的逐字短句记录（侧聊窗口内给出）。
owner 选了拍板清单建议的选项（U），并把「退役」明确写进决定文本。

## 3. 后果

**影响**

1. zcode 的门 7 执行体形态定为 **user 锚 + linger**；root 锚退出，避免双锚互清 SingletonLock。
2. 与最高权限面收敛方向一致（路线风险第 1 条：盘面无常驻 root 才是正式形态）
   —— `archive/2026-10-10-pre-v1/agent系统现状与目标差距-开发路线-2026-10-09.md:165`。

**后续动作**

- 批次 9.4 执行面：`zcode --version` 仍能从 user 锚跑通；root 锚状态须 disabled + inactive。
- **顺序依赖（如实登记）**：拍板清单建议里的前置条件 —— 「terminate-user pan-ding 真演练」
  （D4③）—— 属 D4 演练同窗项（拍板清单 `:264-271`），若未做真演练就退 root 锚，
  logout 语义未实证。本 ADR 不因执行完成而免除该前置，登记为 openIssue 联动批次 8。
