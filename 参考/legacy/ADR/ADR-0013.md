## 1. 上下文

- 凭据已在 OpenBao 里，但没有 agent 能用：
  - `kv/company/Git-Platform/` 11 条（GitHub / GitCode / CNB / Huggingface / Modelscope）
  - `secret/credentials/` 9 条（cnb、github×2、hk-gateway）
    —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md §8「GitHub token」查证段`
- 只读策略已建：`agent-git-read` | `kv/data/company/Git-Platform/*` 只读
  —— 同上 `:187`（策略出处 `OPENBAO.md:40`）
- **没有签发方能用**：`meters-token` 对 `secret/data/company/Git-Platform` 是 deny，
  `gate-decide-token` 同为 deny —— 同上 `:189-190`
- 即：策略在位，但无人持有能签它的 token，GitHub 通道实质不通（KB 项目 4 通道 ingest 之一）。

## 3. 后果

**影响**

1. KB 本体论项目的 GitHub 抓取通道解锁（交接 §9 要求 raw 能抓 GitHub 仓库）
   —— `archive/2026-10-10-baofinalstate/交接-主会话-2026-10-10.md §9「KB 本体论项目」核心需求段`。
2. 权限面保持最小：只读 `kv/data/company/Git-Platform/*`，不给写、不给 `secret/` 面。
   与现有 deny 策略（`meters-token` / `gate-decide-token`）口径一致，不扩大暴露面。

- **与 B4 PAT 降权是两套凭据**：本 ADR 发的是 OpenBao 内的 KV 只读 token，不是 GitHub PAT；
  B4（PAT 降权与是否下发 anolis）仍独立未决
