## 一 五项推翻级发现（详述）

### 1.1 Trace 域：纯自研主线应改三层组合（本轮最大推翻）

原报告"自研 hash-chain 主线+rekor-private 并列"被三个当轮事实击穿：

1. **Langfuse 被 ClickHouse 收购（2026-01-16 官宣），v3 自托管后端就是 ClickHouse**——与本系统 MES 已选的 ClickHouse 同引擎同构。36.0k★，MIT 核心+ee/ 目录双许可（与 LiteLLM 同构的开核模式，内部自托管使用无障碍）。自托管后原生获得：trace 查询/UI、dataset（从 trace 圈选建数据集，带 `source_trace_id` 溯源与版本化）、LLM-as-judge 评估、**Annotation Queues（人工评审队列）**、Public API/CLI/MCP 导出。这直接覆盖了原报告自建的"按 Run/图节点/工件/时间查询"层 + 转产工具的素材链 + QC 的人工评审腿。
2. **OTel GenAI 语义约定已独立成仓（open-telemetry/semantic-conventions-genai），agent/tool spans 全部 Development 状态、无任何成本字段**——自研 schema 仍必要（成本/预算/工件祖先字段 OTel 没有），但字段命名应对齐 `gen_ai.*`（Langfuse 自称基于 OTel，是行业事实标准），防未来迁移税。
3. **Trillian 进入官方维护模式**（推荐后继 Tessera），而 **Rekor v2 已 GA（2025-10-10）**，后端换 rekor-tiles，官方明示更便宜、更易私有部署——防篡改层应直接用 rekor-tiles 而非自研 hash-chain 或老 rekor。

**修正后组合**：`gen_ai.* 对齐的自研 schema（保留成本/祖先/信任字段）→ Langfuse v3（复用 MES 的 ClickHouse 实例）做查询/评估/HITL 层 → rekor-tiles 私有部署做防篡改层`。自研 hash-chain 降级为对照实验（验证 rekor-tiles 的写入吞吐是否满足 trace 速率）。

### 1.2 Skill 签名验证：报告的硬缺口（架构有要求、选型无承载）

架构 §3.7："Skill 签名校验发生在装载时且不可跳过"。全 18 组件中无对应选型。本轮实锤：**sigstore/cosign 的 `sign-blob --bundle` / `verify-blob --bundle`** 支持 tar 化目录的离线验证（无需公网到 Sigstore），与内容寻址工件哈希天然契合。建议：Skill 打包=tar+SHA256，装载时 broker 侧 cosign 验签后放行——补入建设顺序第 3 步（工具 broker）。

### 1.3 下单台：Temporal 独占改并列 PoC（DBOS 升格）

**DBOS**（dbos-inc/dbos-transact-py，MIT）：纯库形态、状态全存 Postgres（复用现有 PG）、durable queue 原生优先级/去重/pause/fork。对"控制平面永远本地"的宪法，其运维半径比 Temporal（需独立集群+多语言服务栈）显著小。**Restate** 虽单二进制契合度高，但当轮 LICENSE 实查为 **BSL 1.1**（4 年后才转 Apache）——若原报告按 Apache 评估过它，证据有误，排除。仲裁方式：同一订单状态机在 Temporal v1.32 与 DBOS 各实现一遍，比部署 footprint/断连恢复/审批等待语义。

### 1.4 产线定义：dbt 降级，影响面分析改道

- 事实纠偏：**dbt-core 主分支 LICENSE 仍是 Apache-2.0**（raw 实查，Copyright 2026 dbt Labs）；改 BSL 的是新 Rust 引擎 dbt Fusion。原报告若因许可疑虑选 dbt，前提不成立——但也不构成保留理由。
- **SQLMesh**（TobikoData，Apache-2.0，Linux Foundation 治理，3.3k★）：虚拟环境（蓝绿 plan）、表级 diff、列级血缘——影响面分析能力面强于 dbt。
- 裁决：Git+CUE+Flux 主干维持；影响面分析改"CUE 依赖图自研遍历 vs SQLMesh"PoC 二选一；dbt 整体降为可选项。

### 1.5 QC 门禁：needs_human 的人工腿不再纯自研

**Opik**（comet-ml/opik，Apache-2.0，raw LICENSE 实锤，22.7k★，活跃）：自托管形态，**Annotation Queues** 原生提供"trace/thread 级人工评审队列+结构化反馈回流"（thread 级 HITL，2025-10 官方博客）——恰好是"需人工→安灯应答→反馈回流"语义的人工腿承载件。**Inspect AI** 内置 approval 模式（human/auto 可扩展）+ 三种沙箱后端，可作图内人审节点。修正后：三态判定层与误判率统计仍自研（薄层），人工评审承载改 Opik 为主、Inspect approval 为图内节点。

## 二 维持项的关键新证据（加固而非走过场）

### 2.1 模型网关：Bifrost 维持 + Higress 深评结论 + 三项事实修正

全域 14 候选当轮复查（星数/许可/发版/预算语义逐一实查）：

- **维持主选**：Bifrost（8891★，v2.3.0，2026-10-13 发版）仍是唯一同时具备美元预算（VK/Team/Customer 三层独立 fail-closed）+请求时记账+config.json 声明式播种的 OSS 网关。
- **TensorZero 已归档**（2026-06-12，募资 $7.3M 后主动停摆，HN #48516504）——本轮候选池直接出局，也警示"高星新项目"的公司存续风险。
- **Portkey OSS 核心是哑代理**（v1.15.2 后 9 个月无发版，README 中 budget 出现 0 次，预算能力在托管面）；Kong 的 ai-rate-limiting-advanced 仅企业版；APISIX 只有 token 限流且计数靠响应回填（事后）；BricksLLM 停更（2025-01）。LiteLLM 判据级拒绝维持（虚拟键签发/验证不分离+enterprise/ 双许可目录）。
- **agentgateway 升格次选/灾备**：原报告"per-key 仅 standalone、K8s 缺位"已过时——K8s 模式现支持虚拟键（外部自生成密钥+SHA-256 哈希存 ConfigMap，明文密钥不进集群，恰合"只验不签"）+ 请求时 token 预算（429 fail-closed）。仍不换主：预算按 token 不按美元、无三层主体。
- **Bifrost 风险表述升级**：OSS 多节点从"未测"改为"**不存在**"——文档明示 clustering（gossip 最终一致）为企业版能力。单节点部署是硬约束，须在架构上按"网关单点+凭证服务预算兜底"设计。
- **Higress 深评（用户点名）**：higress-group/higress，9580★，Apache-2.0，v2.2.5（2026-10-04），月度发版。AI 能力实锤：`ai-token-ratelimit`（Redis 依赖，全局/按 consumer 两模式，超限 429）、模型路由/协议转换、MCP Server 代理与 HTTP→MCP 转换、语义缓存、consumer 于 ConfigMap 声明（GitOps 成立）。**判定关键的三处短板**：仅 token 计数无任何美元/成本维度；仅单维 consumer 无 VK/Team/Customer 分层记账；token 计数靠 LLM 响应回填（事后而非请求时拦截）。**结论：作为本系统主网关不成立，原报告"国内生态对照件"定位正确**；若未来引入 K8s 多租户北向入口，可考虑"Higress 入口限流 × Bifrost 南向记账"分层，但不进主线。

### 2.2 任务图引擎自研：三视角攻击后的存活（含最险一击）

- **构建系统视角（最险一击）**：Buck2（双周发版，2026-10-15 最新）的 target graph+CAS+REAPI+动态动作（AnalysisActions 已成熟）几乎就是架构要的图引擎——但 **Starlark 图=代码，直接违反宪法 4.4"程序性=数据"**；且当轮两轮检索无任何"Buck2/Bazel 跑 LLM 管线"先例（负证据），运维调试知识全自担。判定：不整用；其缓存/动态动作语义入自研规格参考。Flyte 2 的缓存键设计（函数体+输入内容哈希+salt+域隔离）同样入参考。
- **工作流/持久执行视角**：Kestra（YAML 流=数据，29.7k★）最接近"图=数据"但无 CAS 工件；Airflow 3 的资产感知调度（AIP-74/75/82 已 GA）证明"边=资产"语义存在，若语义层已选 Airflow 可承担更多触发职责、降低自研面——登记为自研规格的对齐参考；Restate/DBOS 见下单台；Resonate 无 release 不可用。
- **agent 原生视角**：kagent 仍 v1.0.0-alpha14（原报告不进建议正确）；AgentScope Runtime **已归档并入 AgentScope 2.0**（agent 原生赛道时效性风险实锤）；Eino（13.3k★）图编排类型系统可作自研 DAG 的类型设计参考；MS agent-framework 的 declarative YAML agents 作参考。
- **调度侧**：Kueue v0.20（JobSet/RayJob 稳定 in-tree，Netflix 生产背书）维持主选；**Volcano v1.16.0 的 per-namespace fairshare（Slurm 式用量衰减）使备择差距实质缩小**——若产线/评测长期共享集群且公平性权重高，必须 PoC 正面对测。

### 2.3 平台级替代：不存在（对自研脊柱的最重要加固）

13 平台逐一体检（五宪法=图=数据/CAS 工件/凭证预算治理/trace 正式接口/本地控制面）：

- 最好的 kagent 仅 3/5（缺 CAS/评估环/预算治理）；Dify（158.7k★）许可=Apache+禁多租户 SaaS+禁改 logo，且图存数据库非 Git 数据；Coze Studio（21.7k★，Apache-2.0）**Releases 为空**无正式发版；Windmill AGPL 传染；**Flowise 已于 2026-08-13 归档**（反面教材）；LangGraph Platform 服务端专有；n8n fair-code 明文允许内部使用但引擎本质是触发式工作流、五宪法✗×5。
- **每个平台"最值钱可拆设计"一句话**已登记（Dify 的 app 级用量归因、Coze 的工作流编辑器、Eino 的类型化图、kagent 的 CRD 化 agent、Kestra 的 YAML 依赖图+失败重放、MS agent-framework 的 YAML agents）——供自研时参考，不作整用。
- **裁决：平台替代路线工作量表面低实际高（补 CAS/预算/评估环=二次开发）+许可雷区+废栈风险（Flowise/Daytona/TensorZero 三例同年归档）；自研脊柱 5/5 by design，维持。**

### 2.4 凭证/沙箱/节点池（维持项的增量事实）

## 四 对补充定位的回应：黑灯工厂底盘的"任务无关复用"审查

按你补充的原则——**先建 agent 软件黑灯工厂，底盘后续复用于实验研究/测评/视频/文章/机器人开发；制造业范式只借鉴，最终以 agent/IT 范式为准**——对修正后组合逐件做了底盘复用审查：

1. **IT 原生栈的全面胜出印证了你的原则**。本轮挑战的结果模式非常一致：凡是"制造业字面对应物"（专用 MES、专用告警、专用工单）都没有胜出；胜出的全是 IT 原生件——ClickHouse（OLAP）、Alertmanager（云原生告警）、OTel（可观测标准）、cosign（供应链签名）、Kueue（K8s 调度）、Langfuse（LLM 观测）。工厂隐喻只应保留在**语义层**（产线/门禁/安灯/关灯的业务命名与不变式），不应渗透到**选型层**。修正后的组合比原组合更"IT 原生"（Langfuse/OTel/rekor-tiles/cosign 替代了自造轮子）。
2. **底盘跨产线复用检查表**（修正组合逐件）：
   - 无条件复用（任务无关底盘）：CAS、Trace（gen_ai.* 对 LLM 生产力任务通用）、凭证/预算、网关、节点池、批量调度、任务图引擎、安灯、MES 聚合、JIT。
   - 按产线换插件（设计使然）：QC 评估函数集、工具集/Skill、图模板——这正是架构§6.2"产线定义仓库"的本意，本轮无反例。
   - **测评产线直接受益**：Langfuse dataset+experiment、Opik Annotation Queues、Inspect AI、GEPA/DSPy 语料管线——修正组合恰好把"测评"从自建变成了现成件拼装（原组合要自建更多）。
   - **实验研究产线**：bench 语料→dataset→实验→trace 的闭环同样由 Langfuse 承载；研究型探索走工作台边，符合四阀门设计。
   - **视频/文章产线**：大工件走 CAS（blob 层无压力）；QC 的人工评审腿由 Opik 承载（视频/文章的"需人工"高频）；JIT 的 pass 需为各线写任务特定 pass（架构已预留产品线插件位）。
   - **机器人开发产线**：软件在环部分与代码线同构；硬件在环超出数字工件范畴，但底盘（Run/凭证/预算/Trace/门禁）仍适用——沙箱槽可能需要加硬件接入 broker（本轮未评，登记为未来项）。
3. **一个由复用要求推出的选型纪律**：凡"绑定单一生产形态"的件全部降级或不选（SWE-ReX 只借设计不整用；Inspect 不作总引擎只作 QC 节点；kagent/agent-framework 只借 CRD/YAML 设计）。本轮裁决与此纪律一致。
