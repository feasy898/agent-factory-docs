## 一 愿景与分工（确认版）

**愿景（修订后）**：一座任务无关的通用 agent 工厂——下单台通过规则化定义后，可生产**评估标准可判定（机器判定或人工判定）的任何 agent 可自主产出的产品**，包括人在环中生产。交付物结构未定的**探索型首单**通过厂内"探索 Run"承载（§三.8），不再把定义环节推出厂外。

**分工（产品责任 vs 过程责任）**——与真实工厂同构，正式确认：
- **工作台（工艺设计科）拥有全部产品责任**：任务描述、流程拓扑（图模板）、检查验收标准（评估函数集 + 客户验收协议）、工件 schema（含半成品/原料定义）。这些定义物全部住在产线定义仓库（Git+CUE+Flux），版本化管理。
- **工厂拥有过程责任**：按定义可靠、廉价、快地执行；重试/返工/分支纪律、JIT 优化提议（人批生效）、安灯自动处置规则——均来自产线定义的预授权。
- **订单只携带差异量**：任务参数 + 半成品工件引用 + 预算 + 约束 + 验收协议。拓扑不能现场改；要改走变更单（§三.7）或转产（新工艺先打样后定型）。

**底盘复用**：代码（首发）/实验研究/测评/视频/文章/机器人软在环——换的只是产线定义，平台层不动。制造业只借隐喻，落地全用 IT 原生件（OTel、K8s、ClickHouse、cosign、vLLM）。

## 二 核心抽象 v2

### 2.1 七个一等公民（v1 保留，四处增补）

1. **Run（执行单元）**——增补两点：
   - **状态机扩展**：`executing / waiting / suspended / terminal` 四态。**waiting**（如卡在人工节点跨夜）成为一等状态并带**资源契约表**：沙箱（pause 单一开关）/GPU（是否回收）/prefix cache（可让出）/Kueue 配额（是否虚占）各自的钉住或回收策略与记账口径，同一张表驱动准入与容量台账。
   - **身份分层**：**WorkOrder ID 是稳定身份**（预算归属、trace 归属、成本归集的键），引擎级 Run ID 降为实现细节；durable 引擎的历史分片（如 Temporal Continue-As-New 换 Run Id 重开事件历史）通过显式**分片映射表**归并到 WorkOrder；"循环将触发事件历史分片"写成图编译期静态检查（估算事件数超限即编译失败），不允许运行时意外断裂。
2. **Artifact（工件）**——增补：①**graph_version 为一等键**（写入工件元数据并纳入寻址，见修正案 7）；②**人工决策签名工件**（见修正案 6）；③**流式工件的切段表示**（见扩展抽象 Channel）。
3. **Task Graph（任务图）**——增补：①**map 原语**（遍历工件集合的动态基数 fan-out，运行时展开 N 个已入库子图实例；组件已审定则实例化不算改拓扑；语义对标 Airflow Dynamic Task Mapping，编译为 durable 引擎 child 批次+并发上限）；②**变更单语义**（见扩展抽象 WorkOrder）；③**探索 Run**（见 §三.8）。
4. **Credential（凭证）**——增补：①**四类资源预算皆入凭证**：token/美元（网关硬闸）、GPU 卡时（准入层硬闸）、沙箱并发（broker 硬闸）、**人时**（人工工位预算凭证：人工时额度+按班次扣减+超支升安灯）；做不到硬闸的资源必须显式标注"记账不拦截"（修正案 9）。②凭证永不进沙箱（broker 短时租借模式，红线修复 SLA 见 §十）。
5. **Trace（事件流）**——增补三点：
   - **分级背压**：决策点/门禁/人工节点 span **同步落盘、fail-closed**；模型/工具 span 走 WAL 异步，**必须维护缺口计数器**，且缺口计数本身写成一等 span——"缺了多少"成为可验证事实（防 Collector 队列静默丢弃发生在签名之前、Merkle 头为残缺 trace 背书）。
   - **human actor span**：人工修订/批准/驳回在 trace 中有一等 span（生产者身份进工件元数据），责任链不断。
   - **产品遥测**：交付后产品的回归重放与漂移采样作为产品级 Run 进 trace（见扩展抽象 Delivery）。
6. **Evaluation（评估函数）**——增补：①**三个位置的完整语义**：工具内即时反馈（编译器/linter 的结构化错误，节点内 agent 循环消费，不设独立节点）/节点间门禁/终态验收；②**客户验收协议**（订单字段）：客户金标集 + 抽样验收权 + 争议仲裁工件流——客户标准是与工厂评估函数并列的一等输入，良率统计双口径（工厂口径/客户口径）；③评估函数**冻结在 JIT 优化空间外**（只读命名空间，变更走人工评审+独立签名链+holdout 回归）。
7. **Tool / Skill（能力）**——增补：每个工具/Skill 声明**三类状态语义之一**（修正案 8）。

### 2.2 六个扩展抽象（红队证明 v1"七个足够"不成立，如实扩编）

| # | 抽象 | 解决什么 | 设计要点 |
|---|---|---|---|
| 8 | **Trigger（触发器）** | 事件驱动/持续订单（"仓库有新 issue 就产分诊报告"） | 事件源声明（webhook/cron/信息源监听/资产更新）→ 过滤 → 派生订单。事件源模型借 Argo Events；定时与重叠策略借 Temporal Schedules（Skip/Buffer 策略+catchup 窗口）；"资产更新→派单"语义借 Airflow Assets（与内容寻址工件天然同构）。订阅本身是受预算约束的常驻轻对象。 |
| 9 | **Channel（流式产物通道）** | 无终态的持续输出（仪表盘、直播字幕） | "当前版本指针 + 保留窗口 + 逐快照评估"；切段内容寻址（每快照是普通 Artifact）+ 发布订阅。API 形态借 Trigger.dev Realtime。终检语义=对窗口内快照序列的评估函数。 |
| 10 | **Resident Agent（常驻 agent 产品）** | 产品=长期在线带记忆的 agent 服务（每日邮件助理） | 长命身份租约（凭证体系扩展：非 Run 级而是产品级租约+可吊销）+ 记忆层（与会话记忆严格分离）+ 部署外壳（K8s Deployment 或借 Restate virtual objects 语义）。延迟要求把它钉在工作台边或独立服务池；其行为产生 trace、受预算约束。 |
| 11 | **Delivery（交付/出库）** | 产出部署为运行中服务并交付出库；交付后责任 | 发布投影（代码平台/模型仓库/媒资库）之上补**出库清单**：长命凭证边界、渠道推送、责任转移点、**产品遥测契约**（回归集+采样回放+漂移告警回连工厂观测阀门）。交付≠出狱：能生也能养。 |
| 12 | **Human Station（人工工位）** | 人在环中作为常规工序（审稿/审片/标注/法务） | 完整语义见 §五。核心：任务账本（唯一事实源）+分派路由+修订（Gate+Transform）+quorum 会审+WIP 上限+人时凭证+SOP 资质门。 |
| 13 | **WorkOrder（订单一等公民）** | 长周期订单变更、部分交付结算、验收协议 | 订单从一次性元组升级为带生命周期对象：版本化定义；**变更单**（差异评估→在途 Run 排水/接力→图级 diff 门禁裁决，底层用 durable 引擎 Signal/Update+Patching）；**部分交付计价导出**（中途失败/取消时已付费工件的商业结算契约）；验收协议（2.1.6）；**graph_version 绑定**（订单绑定的图版本不可变，转产双缓冲：草稿图与生效图并存）。 |

### 2.3 订单语言分层（表达力边界的诚实声明）

订单语言分两层：**目标契约**（结果规格+验收方式[机器评估函数/人工判定/客户抽样]+时限+优先级+预算）与**拓扑实现**（图模板引用+参数）。开放终结目标（"做到我满意为止"的主观品味）**显式拒收**——订单必须给出可判定的验收方式；递归产品（生产产线的产线）显式拒绝。

## 三 宪法 v2：五条原文 + 五条修正案

原五条保留（只传工件引用；数据流图非 actor；trace 正式接口；程序性=数据[统一 harness 内核+四元组，厂商适配进预设包数据]；控制面本地计算可溢云）。修正案：

6. **一切决策皆工件**：人工的批准/驳回/修订与机器决策点同等物化为 CAS 中的**签名工件**（对决策 payload 做 Biscuit 衰减签名），对应节点 span 写该工件引用。Alertmanager/ntfy/Opik 一律退化为投递与检索通道，不是事实源。
7. **版本贯穿**：graph_version 写入每个 span、每个工件元数据、每个发布投影头并纳入寻址；JIT 数据集按 graph_version 物理分片，跨版本比较只走重新评估；生命周期与发布投影以版本键为分区维度（事故按版本批量定位："哪 3 万件是 v17 产的"一条索引查完）。
8. **副作用显式**：每个工具声明三类语义之一——纯函数型（幂等键足够）/状态型（必须先提交为 CAS 工件才能 checkpoint）/一次性外部效果型（必须显式声明+broker 层幂等补偿）。平台维护**副作用账本**：写前意图记录+外部状态核对+补偿 playbook 版本化；resume 前节点亲和性（沙箱所在节点）是调度硬约束。
9. **资源预算皆硬闸或显式降级**：token/美元、GPU 卡时、沙箱并发、人时四类凭证编码预算并设可核销硬闸；暂无硬闸手段的资源必须显式标注"记账不拦截"，不得声称物理划开。
10. **可删除性内置**：涉及个人数据的工件按**工件级加密+毁钥**（crypto-shredding）；trace 个人字段分离存储、可抹除索引，Merkle/rekor 锚定只锚承诺（哈希承诺）不锚内容；数据主体请求（DSR）工位与 legal-hold 位进生命周期引擎——"不可篡改"与"依法可删"并存。

## 四 系统拓扑（v1 保留 + 两个新阀）

双边缘（工厂/工作台）+ 共享平台层不变。四阀门扩为**六阀门**：下单 / 转产 / 安灯 / 观测 / **触发**（事件源→订单，归下单台） / **交付**（出库与产品遥测回连，归观测端）。

## 五 人在环中生产模式（HITL-as-Production）

**语义总纲**：把人当"会改东西、会累、会离职、会被骗、按班次计费的产能资源"，不是慢一点的 API。

1. **人工任务账本（唯一事实源）**：一张表 + 原子认领（UPDATE...WHERE claimant IS NULL）+ 心跳租约/fencing token + 幂等键；图引擎的门、Opik 队列、工作台收件箱全部订阅它——杜绝"Flyte 门开着、Opik 里没有、收件箱两条"的重复派发。
2. **分派路由（人工产能调度器）**：按技能/语言/内容分级/负载路由，队深与等待时长进告警；语义蓝本=Camunda TaskList 的 user-task 字段模型（candidate user/group、claim/release、due date、priority、delegation、escalation boundary timer）**内化到自研工位节点**，不引入 BPM 引擎（Camunda 8 Tasklist 生产商用、Flowable 是第三套引擎——均不引入）。
3. **WIP 控制**：真正的控制阀是**限流上游**——安灯暂停产线从异常机制升级为常态节流；Little 定律下积压无界的解是控制到达率，不是催评审员。
4. **修订语义（Gate+Transform 双语义）**：人工节点产出工件 v+1（署名、含 diff、指向原版、入 CAS+cosign），下游与 QC 绑修订版并回灌 agent 上下文；人机往返有循环预算（防活锁）。
5. **班次日历**：超时按班明日历计时（墙钟是日历文盲）；超时**冻结上游**而非自动决策（生产语境下超时自动批准=无人担责放行）；班次日历表自研（自动排班未来再上 Timefold）。
6. **评审员质量环**：金标盲插（任务注入规则，自研薄层）+ 评审员间一致性（cleanlab CROWDLAB 嵌入 ClickHouse 评审记录管道）+ 双盲抽检 + 班内漂移告警；结果回写路由权重与计件资格。
7. **注入防护**：待审产物是对**人的不可信输入**——评审视图内容净化（渲染层"不可信文本当数据"+隐藏文本检测）+ 检测器借 guardrails-ai / NeMo Guardrails；garak 做离线红队；外包按数据分级脱敏路由。
8. **会审**：quorum 门（k-of-n + 一票否决位 + 角色隔离视图）；并行改稿限批注模式，主责人合并。
9. **人时成本**：人工任务账本计时（净服务时长，剔除排队）+ 费率层级（借 Kimai 四层费率设计）进 trace 事件流水（task_id×评审员×净时长×费率），汇入单位成本。
10. **SOP 与资质**：工位 SOP 是版本化工件，随图版本联动下发；路由只派给通过该版 SOP+金标认证的人；关键技能冗余系数 <2 触发采购/招聘告警（与 GPU 备用容量同级）。
11. **指标三分离**（供 JIT 与 MES）：**机器节拍**（agent+工具时间）/ **人工等待**（按班次日历归属，只进 WIP 与人力台账）/ **返工率**（修订次数÷终态件数）。JIT 目标函数只吃机器节拍与质量分；人工等待是约束不是目标。
12. **安灯应答池分离**：应答队列与生产队列独立资源池（各自上限+应答自身并发上限+超时降级为直接人工不调 agent）——防 200 个"需人工"把全厂准入堵死的优先级反转自激。

## 六 资源与经济学（含用户新增的瓶颈计算基础设施）

### 6.1 四类资源 × 记账路径

| 资源 | 记账 | 硬闸 | 溢出 |
|---|---|---|---|
| token/美元 | Bifrost 请求时记账 + 凭证物理划开 | 网关 fail-closed | 云 API/本地 vLLM 路由 |
| GPU 卡时/毫秒 | Kueue 配额 + DCGM 指标 + OpenCost 分摊 | 准入层配额硬闸 | Karmada 溢出到云 GPU（spot 优先，SpotServe 依据） |
| 沙箱并发/时长 | broker 记账（起箱/排队/时长进 trace） | broker 并发硬闸 | 云沙箱池（CubeSandbox/agent-sandbox） |
| 存储 | zot/bazel-remote 指标进 ClickHouse | 容量水位告警（记账不拦截，显式降级） | 对象存储分层 |
| **人时** | 任务账本净时长×费率 | 人时凭证额度 | 外包池 |

### 6.2 订阅 plan 余量路由器（自研薄层）

维护每个 plan 的滚动窗口余量（5h/周限）+ 腐烂折价；把"余量/刷新倒计时"作为网关路由信号：优先消耗快过期额度，余量尽自动 failover 到按量/本地 vLLM。**双账对账层**：plan 消耗与订单 Biscuit 预算对账（回答"哪笔订单耗了哪份订阅"）。执行层候选：gpt-load 凭据调度（订阅账号感知）可作参考实现。仲裁规则：订阅费视为沉没成本；仅当挤占高优任务或触发按量 failover 才计真实成本；剩余额度>窗口内可耗量 → 机会成本为零，免费路由。

### 6.3 容量规划与采购决策子系统（资源瓶颈计算基础设施）

**定位**：MES 之上的容量规划器。秒-分级弹性归既有件（Kueue/KEDA/Karpenter/Karmada 是 L1 执行器）；本件独占**天-月级规划与"该买而非租"的所有权**。

- **数据源**：复用 ClickHouse MES（trace 全量：起箱延迟/failover/美元记账/等待时长）、Prometheus（vllm:queue_depth、kv_cache、DCGM、Kueue 队列）、OpenCost（分摊+GPU 定价 CSV）、SkyPilot（云现价时序）。**新增采集**：429/failover 事件+**反事实计数**（被路由抑制/拒绝的请求数——没有它只看被优化过的假象）、云价+spot 中断率、plan 余量、资源替换矩阵。
- **指标层**：按 workload class 分组，每资源四元组{需求强度、等待/拒绝率、利用率、SLO 违约率}+单位经济学（GPU-秒/任务、token/任务、TCA 五分法成本归因）+反事实需求。**压力指数** = 0.6×SLO 距离 + 0.4×去组合趋势斜率，0-1 归一，跨资源可比。
- **判定三层**：L1 分钟级（SLO 违约持续→触发现有弹性件，本件不执行）；L2 日级（压力指数≥θ 且**反事实确认**排除路由抑制假象→瓶颈候选）；L3 周级（候选持续或按 lead-time 前置外推将违约→跑 **breakeven**：常驻/预留 TCO ≤ 可迁移负载×未来 N 月边际云支出×迁移摩擦系数，且预期利用率>40%；换卡类按性能/美元折算，公式借 gpu-unit-economics：(折旧+电+opex)/利用率 vs 租价）。
- **输出**：压力指数看板（Grafana）/ 周度容量报告工件（趋势+归因+敏感性表）/ **安灯事件**（L3 必触发人工 interrupt——采购是大额决策，自动层止步于租用与路由）/ 决策日志闭环（建议→采纳→到货复核→预测回测，月度校准 θ）。
- **反身性防护（古德哈特）**：判定只读反事实口径；决策用/调参用指标分离；月度金丝雀探针实测容量（JIT 路由器会主动规避限流→429 下降掩盖容量不足）。
- **退潮模式**：容量规划器双向——不只"该买"，也输出退租/缩容/停机窗口建议；长尾订单密度下按订单密度分层定价（常驻保底+弹性计价）先于产能扩张。
- **队列模型**：起步用近似排队模型（借 arXiv 2609.20957 三参数模型：TTFT/ITL 预测误差 5-16%；2607.28223 的 M/G/k+Little 已在 Kueue 上验证）；what-if 用 llm-d-inference-sim（推理）+ cluster-capacity（K8s headroom）。
- **成本归集契约**：成本沿**工件血缘 DAG** 归集到终态工件（返工无论建模成循环还是重下单都归同一终态工件名下）；分子含 token/人时费率/机时/存储留存/折旧；分母按合格终态件数——跨产线单位成本可比。

## 九 JIT 编译器护栏 v2

只发射配置永不干预执行（v1 保留）。新增三条硬护栏：①**评估函数冻结命名空间**：JIT 可达集合白名单，评估函数只读；换评估走人工评审+独立签名链+holdout 回归比对。②**优化集与评估集物理隔离**：评估集必须是优化过程从未见过的采样（按时间窗或来源分片），防同源过拟合。③**关灯判据联合单调**：人工干预率下降**且**漏检率/误判率不上升才允许提议关灯，任一恶化即拒绝——防优化器"学会触发更少人工评审"系统性关闭唯一能发现自身盲区的机制。目标函数只吃机器节拍（§五.11）。

## 十 运营成熟度（day-2+ 条款）

1. **RTO/RPO 分级**：RPO≈0 资产（trace 签名钥/CAS 主副本/Postgres）本地双副本+异步流式复制到云对象存储（密钥异地托管）；zot/ClickHouse 快照异地；Bifrost 治理态本走 Git 可恢复，但**请求时记账的本地账本**需双实例或无状态化+对账（单点挂掉的分钟级在飞成本蒸发不可追）；E2B 控制面声明可丢弃重建。RTO 承诺：控制面 30 分钟/产线 2 小时。季度 DR 演练（断电/换盘，含 rekor 验证器离线可用性）。
2. **升级**：网关蓝绿+排空；trace schema 只加不改+读取端 N-1 兼容；订单钉 schema 版本+版本化重放解释器；金丝雀产线先行。
3. **自监控**：云上 dead-man switch 心跳；主安灯=工厂级 SLO 看板（数据路径与被监控组件解耦）；合成金丝雀订单 15 分钟一条。
4. **供应链**：签名防伪造之外补**作者作恶**防御——模板仓库分支保护+双人评审+作者/评审强制分离+提交签名；模板晋升灰度（影子流量先行）；模板静态审计（egress/凭证调用面白名单比对）。
5. **多租户判据**：L0 内部单租户（默认）→ L1 多团队（租户分池沙箱+CAS 对象 ACL+网关配额）→ L2 外部（**以"凭证永不入沙箱+5008 隔离"红线修复完成为前置门禁**）。
6. **合规**：合规导出器为一等组件（按交付物聚合 manifest+签名链+rekor inclusion proof 一键出包）；保留矩阵带 legal-hold 位，清理器强制尊重。
7. **冷启动**：种子模板库（3-5 条产线含评审记录）列为工厂交付验收项；操作员 runbook+季度 game day；事故复盘强制回填模板库。
8. **day-2 杂项**：证书轮换入演练日历（OpenBao/k3s）；僵尸沙箱租约+GC；ClickHouse 容量水位告警；NTP 为硬依赖写入部署条款；E2B→CubeSandbox 切换需行为对照回归门。
