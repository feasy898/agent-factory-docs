# 计划 · 20 — 开发质量保证体系（编译器 · 测试 · 红队审查）

> 三道防线全部来自实测（af/poc/poc-cargo-pipeline/REPORT.md 与 af/ci/REPORT.md），不是纸面制度。

## 1. 第一道：编译器即时反馈（cargo 阶梯 L0-L3）

写给 agent（无论 grok 还是 GLM5.3）的迭代纪律：

| 层 | 时机 | 命令 | 实测量级 |
|---|---|---|---|
| L0 | 每轮改完码 | `cargo check -p <改动crate> --message-format=json` | 秒级（AF 增量 0.98s） |
| L1 | 每次 commit 前 | `cargo fmt --check` + `cargo clippy --all-targets -- -D warnings` + `cargo test -p <crate>` | 十秒级（clippy 2.5s） |
| L2 | 合流（进主干） | `af/ci/run.sh` **九门**（step1-8 硬门：fmt / clippy 基线 / 全量 test / CUE 预编译 / scrub 解析 / cosign 断网验签 / cargo deny / neutrality 删包自洽+领域词扫描+golden 登记 + step9 FV advisory（Rocq coqc + Kani INV 镜像，非阻塞）；红队 W1-C53 勘误 2026-10-26：原文「六门」为 10-19 口径，10-25 起九步——L4 完成判据以九门为准）+ `cargo semver-checks`（minor/patch PR）+ `cargo audit` + fuzz 短档 60s | 分钟级 ；**红队 W2-C45 勘误**：K5 判分链路径 lint 仅 phase2-redteam-fixes 分支可用（未合流），合流前不计入主线 step1 组成|
| L3 | 周期/夜间 | 长 fuzz 30min/target + `cargo +nightly miri test` + criterion 基准对比 | 慢档 |

要点：
- **反馈格式统一五字段 envelope**（tool/level/code/location/fix），clippy 的 `suggested_replacement` 直接喂给 agent 自动修。
- miri/fuzz 只覆盖纯 Rust 路径（rusqlite bundled 的 C 代码不进 miri）；semver-checks 只对 minor/patch 有效（major 版 260 lint 全跳过，别指望它）。
- advisory-db 本地化（`--no-fetch --db-path`），避免 GitHub 拥塞抖动。
- 基线纪律：clippy 现存 29 条警告锁在 `af/ci/clippy-baseline.txt`，只许减不许增；fmt 的 235 块预存 diff 在波次 1 一次性格式化清零。

## 2. 第二道：测试纪律

- **改动一个 crate 前先读它的 RESULT.md；完成后回写 RESULT.md（五节式）并 git commit**。
- 每波次收尾跑全量 `cargo test -j 6`（当前基线 174+1 ignored 全绿）——数字变了要能解释。
- 语义测试优先：每条新裁决（薄壳/分库/双轨/装载器）都先落成测试再落成代码改动。
- 时间相关逻辑一律注入时刻（参考 af-calendar DST 测试形态），禁止 sleep 依赖。

## 3. 第三道：红队审查

- **每波次收尾必跑一次红队**：由未参与该波次的模型审（默认 GLM5.3 主审 + step-5-preview 与 MiniMax-M3.1-Flash-Preview 交叉），输入=该波次全部 diff+RESULT 更新，审查维度=设计纪律符合性（四层/漏斗/26 件预算）、错误处理、并发安全、宪法条款。
- 发现的问题分级：阻断（必须修完才算波次完成）→ 记入 RESULT 遗留 → 入否决日志（若涉及引入决策）。
- 红队输出存 `af/poc/../redteam/波次N.md`（波次 0 创建该目录），结论摘要进变更日志。
- 对抗纪律沿用本项目验证有效的形态：要求红队"找会出问题的点"而非"是否合格"；证据必须可复现（命令+输出）。

## 4. 质量事故登记

任何"测试绿但线上错"/"文档与现实不符"事件在 `状态/` 对应文档登记根因与防再发措施；同类二次发生升级为 AGENT.md 纪律修改（走变更日志）。
