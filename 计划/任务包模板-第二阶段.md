# 任务包模板 · 第二阶段

> 编排者下发任务包的标准格式。**不含可执行验收标准的任务包不得下发**（ADR-007）。
> 所有任务包通用约束（除任务包显式覆盖外）：
> - AGENT.md 硬纪律 1–9 全部生效；
> - ADR-009 资源纪律：开工 `df -h / /tmp`（/ 余量<15G 或 /tmp>80% 即停并上报）；构建一律 `CARGO_TARGET_DIR=~/afbuild-<任务名>`；严禁占用 af/target；容器命名 `phase2-` 前缀且用毕即删；不动 AB 测试线与工厂守护进程；
> - 开发规约 ADR-007：先红后绿再重构；模块自包含可独立 `cargo test`；交付带测试（含拒绝用例+稳定错误码）+ 模块 RESULT.md；
> - 收工三步（AGENT.md）：更新 状态/ 对应文档 + 计划/变更日志 追加行 + af 仓改动 git commit（工作树内、任务分支上）。

## 模板正文

```
## 任务包 <ID>：<标题>

### 目标
<一句话：做什么、做到什么程度算完>

### 必要上下文
<文件路径清单（必读）+ 已裁决约束（ADR-xxx 引用）+ 复用点（哪个 crate 的哪个类型/函数）>

### 约束
- <宪法条款/ADR 引用>
- <技术边界（如：不修改 af-workorder 既有语义）>

### 验收标准（可执行）
- <测试命令 + 期望结果；如 `cd <worktree> && CARGO_TARGET_DIR=~/afbuild-<名> cargo test -p <crate> <模块>` 全绿>
- <拒绝用例：输入 X 必须被拒绝且错误码为 Y>
- <交付物路径>

### 禁止事项
- <明确列出（如：不得修改测试代理持有的验收代码；不得引入新外部依赖）>

### 工作树与分支
<worktree 路径 + 分支名；无则由编排者预建>
```
