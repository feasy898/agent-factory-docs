## 2. 证据细节（分档依据）

### S 档（4）

- **astropy-12907**：af 补丁恰为 `cright[-right.shape[0]:, -right.shape[1]:] = 1 → = right`，与 PR #12907 非测试部分逐字节一致（上游另有 changelog 1 行 + 测试 18 行，af 未取）。run 内自述零上游引用；`git log --all` 输出实证历史止于 base（HEAD 为 "SWE-bench" 标记提交），`git log -S` 只命中该行的引入提交——**字节同源但仓内无来源，通道只能是参数化记忆或独立推导**。1 行修复，独立推导概率不低，S 档含保守成分（同 mcode 报告对 requests-1766 的注法）。
- **django-11066 / 11451 / 14672**：三题均为"issue 文本几乎直接给出答案"的规范单点修复（`using=db` / None 守卫 / `make_hashable(...)`），af 补丁与上游逐字节一致且全部 <350s 快标。django-11066 转录显示 agent 先读测试与 runtests 配置再定位 `content_type.save()`，路径自然；无任何上游引用。三题同为 S 保守成分注记对象。

### M 档（1）

- **pytest-8399**：af 把 5 处 xunit fixture 名加 `_` 前缀，与 PR #8399 的改名**逐处一致**（recall 100%），多出的只是每个改写点一条注释——而注释里引用了 **#8404**（上游后续 issue 号，8399 实例的 base 之后）。Jaccard 80% 落在 M 带；参数化记忆签名明确（改动本身也是该 bug 的规范解法，贴 S，按 ≥90% 保守阈值归 M）。

### N 档（11）

要点（详表见 §1 重合率列）：
- **同思路不同实现的强独立证据**：xarray-4075（bool→int cast，插入点 `_dot` vs 上游 `_reduce`，两份注释各自解释 einsum 逻辑与行为）、mpl-22719（空数据告警抑制，早退 vs size 守卫）、sphinx-10466（保序去重 vs sorted(set)）、sympy-13877（`ret = cancel(ret)` 1 行根因修复 vs 上游 pivot 逻辑 24 行重写）。
- **seaborn-3187 是本轮最有意思的发现**：自述多轮复述"上游 v0.13 修法"（format_legend / Scale._legend），但真正游 PR #3187 的做法是**关掉** offset/scientific notation（`set_useOffset(False)`），af 做的是把 offset **补回** legend label——记忆错上游、然后独立解出并通过判分。0% 重合。
- **sphinx-10466 的回忆失败**：转录中 agent 三次试图回忆上游修复（先后猜 PR #10467/#10470/#10471、"Sphinx 5.0 by Adam Turner"），全部猜错（真身 = PR #10466，tk0miya/10104_gettext_duplicated_locations，merge 提交 `51c84e041f` 恰为 base 直接子提交），最终按自己对 root cause 的分析独立实现。
- **pylint-7277 的"上游测试"来自 base**：自述称转录了上游 `test_modify_sys_path` 的 11 个用例，经查该测试函数在 base 的 tests/test_self.py:746 即存在（修复提交只新增 9 行）——引用的是仓内既有测试，不构成未来知识证据。af 守卫与上游同语义（`sys.path[0] in ("", ".", cwd)` 的反写）但结构不同，11% 归 N。
- **sklearn-11578 注记**：af 的实质改动（`LogisticRegression(..., multi_class=multi_class)` 透传）与上游同调用点同参数，仅保留 fit_intercept 写法差——行集 Jaccard 17% 系口径对 1 行语义改动伪差（上游删了 fit_intercept，af 留之）。语义同向、文本非同源、且该修法可从 issue 正文直接推出，按口径归 N，此处如实加注。
- **sklearn-10297 的环境通道排除**：自述"matches upstream sklearn master's behavior exactly"并查过容器内是否装了别的 sklearn——实测 `pip list` 显示唯一 sklearn 就是 /testbed 本身（0.20.dev0），无新版包可抄，27% 重合为独立实现。
- astropy-8707（7%）、pylint-6528（8%，af 主改 pylinter.py，上游主改 expand_modules.py，架构不同）、pylint-6386（4%，af 自建 PREPROCESSABLE_SHORT_OPTIONS，上游走 metavar 通道）均为不同路线独立解。
