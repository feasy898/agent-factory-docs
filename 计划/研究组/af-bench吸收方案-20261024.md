### 1.2 依赖方向：af-bench → af-execline（薄壳调库），禁止反向

**建议：执行逻辑沉入 af-execline，af-bench 降为薄 CLI 壳依赖 af-execline；af-execline 永不依赖 af-bench。**理由四条：

1. **生命周期方向**：af-execline 是存续的统一执行面（ADR-002 crate 表：`crates/af-execline` 吸收 af-bench 的 swev/tb 执行逻辑为库），af-bench 直跑形态是退役对象（ADR-008 裁决 2）。若让 af-execline 依赖 af-bench 库化模块，退役 af-bench 时必须连坐再搬一次核心逻辑，与"退役=薄壳化或移除"（ADR-002:18）冲突。
2. **循环依赖禁令的一次定向**：切流后 af-bench 要降级为"薄兼容壳"调用 af-execline（ADR-002:18）。若吸收期先取 af-execline→af-bench 方向，薄壳化时方向必须反转=二次全量搬移；workspace 内 crate 禁循环依赖，一次定死方向避免往返。
3. **依赖闭合（本任务核对）**：af-execline 现依赖 af-mes + af-workorder（`crates/af-execline/Cargo.toml` deps 节）；吸收需新增 af-credential/af-harness/af-meter/af-stop/sha2（= af-bench 现依赖集）。af-harness 的依赖为 af-credential/af-effect-gateway/af-meter/af-stop/af-trace/af-workorder/biscuit-auth/rusqlite/ureq（`af/crates/af-harness/Cargo.toml`）；且 workspace 内除 af-bench 自身外**无任何 crate 依赖 af-bench**（本任务 `grep -rl "af-bench" crates/*/Cargo.toml` 实测，仅 af-bench 自己命中）→ 两个方向断言成立：① af-execline 加上述依赖无环；② 薄壳化后 af-bench → af-execline 也无环（af-execline 不回指 af-bench）。`cargo deny` sources/bans 门与 cargo 自身均会兜底校验。
4. **改动面更小**：af-bench 现为纯 bin（src/ 无 lib.rs），反向方案要先给 af-bench 做 lib 拆分，改动面反而大。

**影子期 af-bench 的双保险**：对拍的"旧路"不依赖 phase2 分支上的 af-bench 可用——旧路 = 冻结二进制 `/tmp/threetest-bin/af-bench-g3-frozen`（7a87876c，实测在位）或自 guardrail-fix2（94cd192）构建。因此施工序上 P1–P5 期间 phase2 分支的 af-bench **完全不动**（旧路双保险），P6 才做薄壳化（`use af_execline::suite::{swev, tb}` 重导出，CLI 参数面不变）。

### 1.3 迁移纪律（"迁移而非重写"的可检验形态）

- **语句级对照清单**：`SwevExecuteUnit` 每段注明源行号（例：bash 工具注册+反考古护栏+重复命令护栏 ← main.rs:700-735；采样参数覆写 ← main.rs:634-636；Launch 组装 ← main.rs:776-798；gate 计算 ← main.rs:801-813）。评审按清单逐段比对。
- **测试随迁**：af-bench 现有 3 个单测（attempt 序号 main.rs:48-73、护栏常量 tb.rs:334-340）随代码搬入 af-execline 并转绿。
- **已知不对称如实保留**：TB run 目录仍 `remove_dir_all` 覆写（main.rs:1000-1002）而 swev 已是 D-20 递增不覆写（main.rs:594-610）——迁移期不顺手修（修了就不是迁移），登记为 P5 后独立决定（§6 R8）。
- **容器命名防撞先例**：容器名 `afbench-swev-<task>-<profile>`（swev.rs:56-59）唯一生成处自消费、无外部运行时消费者（容器名防撞-交付.md §1 引用面清单实证）；并发对拍互杀问题见 §6 R3。

### 1.4 结果行：双轨制

- **legacy `results.jsonl` 行原样保留**（swe-v 18 键 main.rs:861-890）：现役消费方 bench-mes.py 按行字段取值（tools/bench-mes.py:98-131 读 reward/turns/tokens）、看板沿用在飞口径——切流前不破坏。写入纪律保持 append + 每行 flush（main.rs:644-648, 668-670）。

## 2. ExecuteUnit trait 扩展（桩 → 真实 swe-v 执行单元）

### 2.1 现状与差距

PoC trait：`ExecuteUnit { fn unit_id(); fn execute(&ExecContext) -> Result<ExecOutput, ExeclineError> }`（exec.rs:33-39）；`ExecContext` 仅 order_id/stable_id/line_id/out_dir（exec.rs:16-22）。真实 swe-v 单元需要五件事：容器生命周期、模型调用、取证、判分、结果行（main.rs:625-914 全链）。

### 2.2 trait 形态：单入口不变，两 struct 扩展

**不改 trait 签名**（driver.rs:207-250 的 execute 编排已可用）——最小改动面。扩展：

**`ExecContext` 增字段**（每单执行期输入——"同一档跑不同题"的东西进这里/订单，不进单元声明）：

| 字段 | 语义 | 源 |
|---|---|---|
| `host_alias: &str` | 执行宿主别名（anolis/local），缺省 anolis | main.rs:102 |
| `data_root: &Path` | 题库根（load task_json / eval_script） | main.rs:640, 850 |
| `attempt_dir: &Path` | run 目录（驱动层用 `next_attempt_index` 分配，重跑递增不覆写） | main.rs:698, 760-766 |
| `record_sink: &dyn RecordSink` | results.jsonl 写入器（append+flush 语义） | main.rs:644-648 |
| `trial: bool` | 试验标记（不进决策） | main.rs:11 |

**`SwevUnitSpec`（新 struct，静态声明——"换一档实验要改代码"的东西进这里，随 unit_version 版本化，对齐契约 §1.2 unit.json）**：profile 名→EndpointSpec+key_cmd（main.rs:163-327 表）、采样覆写 temp 0/top_p 1/max_tokens 32000（main.rs:634-636）、两段提示词（main.rs:543, 548-566）、Policy max_turns 250/stop 条件/单题预算 300 cents（main.rs:746-758, 786-793）、容器护栏 6g/512（tb.rs:116-117）、eval 超时 1800s（swev.rs:165）、判分器定位与指纹锚（§3.2）。
判据一句话：**换档案/换档位=换 spec；换题/换宿主/换输出根=换 ctx**。凭证（voucher/line）留在 DriverConfig（driver.rs:43-45）——那是订单门材料不是单元参数。

**`ExecOutput` 增字段**：`verdict: Option<bool>` + `note`（resolved/verifier_note，main.rs:866, 889 语义）；`record: Option<Value>`（本单元落的 af.plan.record.v1 行）；`evidence: Vec<PathBuf>`（三件套实际路径——task_json 引用、eval.log、agent.diff）。

### 2.3 两个可注入缝（TDD 与对拍的关键设计）

```rust
trait HostBridge { fn run(&self, host:&str, script:&str, timeout_sec:u32) -> Result<(bool,String),String>; }
trait AgentRunner { fn run(&self, launch: AgentLaunch) -> Result<RunReport, String>; }
```

- `HostBridge` 真实实现 = 搬来的 tb.rs:42-64（local 直执 / ssh BatchMode 桥接，timeout 包裹，stderr 合并）；测试注入 `FakeBridge` 断言命令构造（docker run 的 --memory/--pids-limit、代理三分支 swev.rs:63-69、环境卫生变量、容器名格式、`docker rm -f` 前置）。
- `AgentRunner` 真实实现 = `Opened::open` + `Opened::run(Launch)`（af-harness run.rs:215-236；Launch 全字段 run.rs:89-108）+ key 紧邻现取与 401 重取器（main.rs:768-773；KeyRefresher 类型 run.rs:85）；测试注入 `FakeRunner` 返回固定 RunReport + 预置 diff——**单测零模型调用、零凭证消耗**。
- `SwevExecuteUnit` 持 `&dyn` 两缝构造。Layer 2 影子对拍（§4）可组"真 Runner + FakeBridge"或全真。

### 2.4 失败路径与清理（从 main.rs 语义固化）

- **cleanup 必达**：现行错误路径都显式 `env_cell.cleanup()`（main.rs:820, 854, 1035, 1061）——搬入时改为 RAII guard（Drop → tb.rs:294-296 的 `docker rm -f`），防新增早退路径漏清容器（anolis 事故教训，tb.rs:101-114 注释背景）。
- **setup_failed / run_failed 行语义保留**（F2 供给失败，契约 §6.2 分类）：setup 失败落 setup_failed 行且字段齐备含 null（main.rs:656-667）；runner 失败落 run_failed 行记实际目录（main.rs:822-834）。这两类行由单元经 `record_sink` 落，订单侧不停终态（driver 的 EX3001 可重试语义，driver.rs:225-237 已有）。
- **gate 是记账不是门控**：no_patch/test_edit 计算（main.rs:801-813 + swev.rs:121-139）原样留在单元内、进 record 行 `gate` 字段；不接引擎 close 门（引擎 close 只认合格终态工件，driver.rs:261-266，两语义不合并）。

## 3. 判分独立性（swev-judge 调用在实现可改写面之外）

### 3.1 指纹事实（本任务实测，含一处勘误）

- 判分 = 外部子进程：`/home/pan-ding/swev-venv/bin/python tools/swev-judge.py <task_json> <eval.log> <agent.diff>`（swev.rs:205-210）；venv 实测 swebench 4.1.0。
- **指纹漂移勘误**：现产 `tools/swev-judge.py` sha256 = `a292547f3bfce825…`，**不等于** D-32 历史锚 `0338566c…`（判分器v2-交付.md:23-24；在飞bench盘点 ③-7-② 仍写 0338566c 口径）。本任务已定位漂移：与 rsi-drill 冻结件（`计划/研究组/rsi-drill-20261022/registry/frozen/swev-judge.py`，实测 = 0338566c）逐行 diff，差异仅为三测试修理组的 requirements-404 回退补丁（swev-judge.py:63-91, 117, 140-141，自注"判分语义零变化"，`reqs_synthesized` 如实上报）；v2 脚本（实测 `3f958c92…`，与 D-32 记录一致）未被启用。**结论：判分语义锚可更新为 a292547f，但必须在对拍报告里双锚并记**（§6 R5）。

### 3.2 设计约束（四条，条条可测）

1. **子进程边界即独立性边界**：af-execline 永不进程内链接/复刻判分逻辑；judge 调用收敛到唯一模块 `judge.rs`，**argv 契约测试钉死**（恰好 3 个位置参数、无额外 env 注入、不经 wrapper shell）——实现面（提示词/循环/工具）怎么改都碰不到判分。
2. **指纹门 fail-loud**：单元装载时 `sha256(judge_script)` 必须等于 spec 声明的锚（默认 `a292547f…`；历史回放对账可用 0338566c 锚 + rsi-drill 冻结件）。不匹配 = 新错误码 EX3xxx 拒跑，不降级、不跳判、不静默换脚本。
3. **判定值只从 judge stdout JSON 取**：resolved/log_parsed 透传与 note 前缀拼装逻辑原样搬（swev.rs:216-227）；Rust 侧不做任何再解释。`diff_touches_tests` 是 gate 记账不是判分（swev.rs:119 注释自证），留在实现面合规。
4. **证据先产后哈希后判，顺序固定**：capture_diff → 写 eval.sh → 容器执行 → 超时落 `EVAL_TIMEOUT_KILLED` 标记（swev.rs:191-200）→ 计算 eval.log sha256（swev.rs:203-204，哈希的是判分器实际读到的字节）→ judge 只读三件套、写不回。顺序本身是测试断言。

### 3.3 与 ADR-008 的对齐

ADR-008 不退役清单明文："swev-judge 判分核（字节冻结，被新执行面以同契约调用）"（008:19）。本方案 §3.2-1/2 即"同契约"的可执行形态；v1/v2 切换是独立裁决（判分器v2-交付.md:146-148 待厂长配对评估），本方案只保证切换点 = judge.rs 的脚本路径参数 + 指纹锚，不动调用方。

### 4.2 三个对拍维度

1. **results 行字段**：`results-old.jsonl` vs `results-new.jsonl`。确定性字段逐位比对（suite/task_id/profile/trial/reward/status/gate/scaffold/reasoning_tier/attempts）；计量字段（turns/model_calls/tokens 三分项/http_retries/agent_wall_ms）**统计比对不逐位**（供给面抖动豁免，http_retries 差异如实记录——供给面观测口径 main.rs:12-13）；新行多出的订单字段（order_id/stable_id）列差集单独核对。
2. **判分一致性**：L0/L1 逐位；L2 硬门复判（§4.1）。
3. **MES 事件序列**：旧路事件族 = bench-mes.py 的 tokens_input/tokens_output/cache_read/turns/wall_ms/reward/infra（tools/bench-mes.py:9）+ 调度侧 started/done/partial/failed（factory-sched.py 节点事件）；新路 = driver 四类 release/start/complete/close（driver.rs:34）+ 单元 usage/reward 事件。对拍口径 = **映射表比对**（started↔start、done↔complete、reward→单元 reward、turns/tokens*/wall_ms→单元 usage），判"映射后 kind 集合齐备 + 每类恰 1 条 + work_order_id 收敛 stable_id（quantity=1 语义不变）"；不做事件字节对拍（event_id 含账本序号，driver.rs:399-409，必然不同）。

对拍工具：`af-execline::shadow` 模块或 `tools/shadow-diff.py`（读两 results 文件 → 字段级/判定级/事件级三张差异表）；原始产物归档 `工具状态备份/shadow-<日期>/`。
