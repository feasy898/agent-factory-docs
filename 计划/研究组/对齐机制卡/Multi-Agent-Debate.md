## ① 核心机制

Multi-Agent Debate 要解决的是单代理 CoT 的两类病：采样多样性与自我纠错不足——单链推理的错误高度相关，自洽性（self-consistency）只能在同类错误中投票，多样答案无法互相暴露盲区。核心执行模型是一个**并行采样 → 公开反驳 → 再修订 → 收敛**的重复博弈循环：N 个辩手代理（可同构可异构、角色各异）先在**互不可见**的状态下独立给出初解；随后每一轮，每个代理把其他代理上一轮的答案（去标识、随机排序、限长）读入自己的上下文，被要求批判性评估并输出修订后的自身答案；重复 K 轮后，用末轮答案的多数投票或读取完整辩论记录的 LLM 裁决器产生唯一终答。Kahneman-Tversky 式的"对抗式辩论"是其变体：两个辩手互相说服，由偏好真值的裁判选胜者而非按票数。

## ② 组件清单

| 组件 | 类型 | 职责 |
|---|---|---|
| 辩手代理 Debater | 角色节点 | 独立出解、逐轮修订自身信念 |
| 角色/Persona 提示 | 配置模板 | 注入领域视角，保证解法多样性、抑制相关性错误 |
| 问题与检索证据 | 初始工件 | 全代理共享的初始输入 |
| 同伴解消息 | 消息 | 每轮广播的他人答案（匿名、乱序、截断） |
| 局部信念状态 | 状态 | 每代理自己的当前答案，逐轮覆盖更新 |
| 辩论记录 Transcript | 共享黑板工件 | 全轮消息日志，供裁决、审计与早停判定 |
| 多数票聚合器 | 聚合节点 | 对末轮答案做统计投票 |
| 裁决器 Judge | LLM 裁决节点 | 读完整 transcript 选定/合成终答（对抗式辩论必需） |
| 轮次控制器 | 控制节点 | 驱动 K 轮、轮内并行 |
| 一致性评估器 | 判定器 | 计算答案分布，判定是否收敛早停 |
| 消息随机化器 | 变换算子 | 打乱同伴消息顺序，抑制位置偏好 |
| 检索/工具 | 工具节点（可选） | 事实类问题取证据 |

## ③ 数据与上下文流

第 1 轮上下文 = 系统提示（角色）+ 问题 +（可选）检索证据，输出被限长的"短解"。第 k 轮（k≥2）上下文 = 系统提示 + 问题 +（可选）证据 + **自己上一轮解** + **他人上一轮解列表**（匿名、乱序、按预算截断/摘要）。可见性边界：代理通常只看到同伴的**答案文本**，默认看不到对方的系统提示与内部 CoT；聚合器只需末轮答案，裁决器则可见全部 transcript（是否带角色名可配置）。状态存放：局部信念在代理节点内私有，全局 transcript 在共享工件数上追加；每轮末由控制器统一推进，轮内各代理并行执行，故同轮内互不可见。

## ④ 失败处理与停止条件

- 固定轮次上限 K（经验 3–5，2–3 轮后收益趋平）→ 到顶即止。
- 一致性早停：末轮答案分布集中度或两两一致度超阈值 → 提前收敛。
- 无多数/平票 → 回退裁决器；裁决器亦失败 → 取置信度最高或随机。
- 上下文溢出 → 截断或摘要同伴消息后重入。
- 集体错误（全部代理收敛到同一错误）→ 框架内无法自动检出；靠角色多样化、预注入反驳视角、独立外部证据缓解，建议作为监控告警项。
- 错误代理污染群体 → 对抗式辩论依赖偏好真值的裁判；可加预验证正确性过滤。
- 震荡不收敛 → 轮次上限兜底 + 重复内容检测。
- 成本超预算 → 中止并返回当前多数结果。
- 输出解析失败 → 限次重解析，仍失败则交由裁决器自由文本判定。

## ⑤ 预算与评估方式

Token 成本 ≈ N 代理 × K 轮 ×（提示 + 输出），其中"把 N−1 条同伴解塞回上下文"是主导项；故论文强调短消息式输出约束，论证辩论在更少 token 下可优于多次 CoT 采样（具体倍数存疑）。轮次与并行策略同上。评估（Du et al. 2023）：算术（MGSM/GSM8K）、常识推理（StrategyQA）、事实问答（TriviaQA，带检索设置，确切数据集集合存疑）；基线为单代理 CoT、自洽性、标准辩论；消融含代理数 3/4/5、轮数、角色多样性开关、注入错误代理的鲁棒性、匿名与排序的影响；指标为准确率与 token 消耗对比。对抗式辩论（Irving et al. 2023）：TruthfulQA 上偏好转向更善说服的辩手，需真值偏好裁判，指标为偏好/准确率。ChatEval 类工作用角色扮演+辩论+裁判，指标为胜率与评分。

## ⑥ DSL 表达点清单

**(a) 可映射为"标准拓扑+组件"的机制**

- 扇出—广播—扇入的轮次循环 = N 辩手节点并行出解 → 全连接广播同伴解 → 局部状态更新 → 轮控制器迭代 K 次（对应"Debate=全连接轮次循环"）。
- 角色多样性 = 同构节点模板 + Persona 参数化分支。
- 多数票聚合 = fan-in 统计节点（等价 self-consistency 聚合器）。
- LLM 裁决 = Judge 节点读取 transcript 工件输出终值。
- 共享黑板交接 = transcript 作为追加式共享工件，轮间持久。
- 匿名与随机排序 = 消息变换算子（去元数据 + shuffle）。
- 局部信念覆盖写 = 每代理 memory write 策略。
- 检索 = 工具节点挂载，证据注入上下文。
- 上下文装配 = context assembly：问题 + 证据 + 他人解 + 自解。

**(b) 预计需要 DSL 逃逸舱的机制**

1. 语义级共识判定（用 LLM 判断"是否已达成一致"）→ 运行期 LLM 谓词，停机条件无法静态声明。
2. 顺序随机化的不可复现性 → 需 nondeterminism/seed 算子。
3. 运行时自适应轮数、震荡后改写提示的退火策略 → 运行期改写调度参数。
4. 运行时修改辩论拓扑（代理掉线、临时增反驳者、锦标赛式配对）→ 运行期图变异。
5. 运行时打分/权重（裁决时按可信度加权、权重由 LLM 给出）→ 运行期数值注入。
6. 针对性点名反驳与个性化提示的运行时拼装 → 运行期 prompt 程序。
7. "同伴不可见内部 CoT"的逐节点可见性矩阵 → 若 DSL 无可见性裁剪声明则需逃逸。
8. 工具结果回灌给同伴的共享工件写入裁决 → 运行期写权限仲裁。
9. 多级回退链（平票→裁判→截断→中止）→ 异常/回退拓扑非纯静态图。
