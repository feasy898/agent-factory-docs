## ① 核心机制

ReAct（Yao et al., 2022；arXiv:2210.03629；ICLR 2023）针对大模型"会推理却不会行动、会行动却会幻觉"的缺陷，提出在同一轨迹内**交错**生成自然语言推理（Thought）与具体动作（Action），并把环境返回的观察（Observation）立即回灌上下文，使推理被事实约束、行动被显式推理引导。核心执行模型是**单智能体单节点自循环**：上下文 = 任务指令 + 少量人工标注的少样本轨迹 + 当前完整轨迹 → LLM 一次性输出「Thought + Action」→ 动作交由外部环境/API 执行 → 观察以纯文本追加 → 再次进 LLM，直至模型发出终止动作或触达步数上限。主战场为 HotpotQA（Wikipedia API 多跳问答）、ALFWorld（文本世界家务）、WebShop（网页购物），并在 Fever 事实核验上做扩展（存疑：Fever 是否计入主表）。结论：推理与行动互为条件，纯 CoT 与纯 Act 均弱于交错。

## ② 组件清单

| 组件 | 类型 | 职责 |
|---|---|---|
| Policy LLM（PaLM-540B / InstructGPT 等） | 角色 | 唯一决策者，读上下文产出 Thought+Action |
| 少样本轨迹模板 | 静态提示 | 示范交错格式与动作词表 |
| Action Space | 工具 | `search_entity/lookup`；`look/inventory/goto/open/examine`；`search[...]/click[...]` |
| Environment / API | 工具后端 | 执行动作，返回自然语言观察 |
| Observation 通道 | 通信 | 纯文本回灌，无结构化 schema |
| Trajectory | 记忆/工件 | 追加式保存 (Thought, Action, Observation)，兼作状态与记忆 |
| finish/answer 动作 | 终止判据 | 模型显式宣告完成并给答案 |
| Max steps | 预算 | 硬迭代上限，超限截断判失败 |
| 温度 0 解码 | 推理配置 | 保证可复现 |

无多智能体、无独立规划器、无外部长期记忆、无奖励模型、无共享工作区。

## ③ 数据与上下文流

每回合上下文顺序固定：任务说明 → 少样本示例 → 当前轨迹全量历史（含观察）→「Thought:」提示符。LLM 一次输出 Thought 与 Action，解析器从自由文本切出动作串交环境执行；Observation 原样追加到轨迹尾部，不归一化、不改写。**状态只存在于上下文窗口**：无数据库、无独立 state store、无跨智能体交接，唯一的工件就是这条被 LLM 反复重读的轨迹，故"记忆"= 全量轨迹回灌，token 随步数线性膨胀。最终答案出现在最后一个 finish 动作或末段 Thought。

## ④ 失败处理与停止条件

- 语义停止：输出 finish/answer 类动作即终止。
- 硬停止：达任务级最大步数则截断，样本判失败（步数具体数值存疑）。
- 自省纠错：后续 Observation 与先前推理冲突时，新 Thought 显式改口（"我错了…"），事实覆盖旧结论，但**轨迹不回写**，错误历史仍可见。
- 工具/环境失败：返回"无结果"字符串，由下一轮 Thought 决定换查询或换动作；代码侧无重试计数与回退表。
- 推理失败（论文点名的失效模式）：Thought 出错会把后续 Action 全部带偏（error propagation），无外部纠错器。
- 观察失败：Observation 被误读。全文无独立"反思修复"回路（Reflexion 类机制是后续工作）。

## ⑤ 预算与评估方式

预算三件套：步数上限、上下文窗口（轨迹全量回灌）、温度 0 稳定复现；论文记录各任务 token/step 量级并比较 GPT-3.5 与 PaLM-540B 成本（具体数字存疑）。基准与指标：HotpotQA 用 EM/F1 且需答案与支撑句同时正确；ALFWorld 用家务任务成功率（对专家轨迹、纯 Act 基线）；WebShop 用成功率与综合奖励（对人类、纯 RL/纯 Act）；Fever 用 EM（存疑：是否为主表实验）。消融：ReAct vs CoT-only（无观察约束）vs Act-only（无推理）vs 推理与动作分离（先想后做不交错）；示例数量 1/3/6 的影响；温度与停止序列设置；并给出失败案例——推理与动作空间难以同时表述的任务上优势缩小。

## ⑥ DSL 表达点清单

**(a) 可映射为"标准拓扑+组件"的机制**

1. ReAct = **单节点循环 + 工具节点回边**（policy 自循环，工具结果连回 policy）；无 DAG 分支、无流水线阶段、无多智能体。
2. 动作调用 = 工具 schema + 位置参数（`search_entity(entity)`、`click[button]`）。
3. 观察返回 = tool_result 文本注入的标准"工具→上下文"通道。
4. 轨迹 = 追加式工件（append-only transcript），即循环体的 message 数组。
5. 记忆 = 无外部记忆库，上下文窗口即唯一记忆。
6. 停止 = 终止动作触发条件出边（finish → 结束节点）。
7. 预算 = 循环节点 max_iterations 计数器。
8. 角色/提示 = 单一 policy 角色；少样本示例为静态 prompt 常量；"推理先于动作"为边序约束。

**(b) 预计需要 DSL 逃逸舱的机制**

1. **动作空间运行时才确定**（ALFWorld 文本动作词表、WebShop 的 click 按钮由页面 DOM 决定）：工具集静态声明表达不了，需运行时工具注册表逃逸舱。
2. **自由文本双向解析**：Action/Thought 由同一段生成文本启发式切分，非固定 slot schema，需非结构化输出解析器逃逸舱。
3. **一次生成多段**（Thought+Action 同批）：常见"一次调用一动作"模型表达不了，需组合式生成/生成后再分派逃逸舱。
4. **思考可被覆盖**：模型后续否定先前推理，但不可变工件模型只能追加，需可写 scratchpad/断言区逃逸舱。
5. **语义级终止判据**："我认为已完成"由 LLM 判定后需外部解析，静态条件边难表达，需模型判定终止逃逸舱。
6. **错误恢复策略运行时决定**（重试/换查询/回退）而非预定义 error route，需动态策略逃逸舱。
7. **上下文全量回灌与裁剪**：轨迹线性增长，需运行时 prompt 组装器（截断/摘要）。
8. **有状态交互环境契约**：ALFWorld/WebShop 需 env adapter（状态保持、回合同步、非法动作反馈），非普通无状态工具。
