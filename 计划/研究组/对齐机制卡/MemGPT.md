## ① 核心机制

MemGPT（Packer 等，arXiv:2310.08560）要解决的是：LLM 上下文窗口既有限又"被动"，模型无法像操作系统那样主动管理自己的记忆。它把 LLM 当作 CPU，把**主上下文（main context）当作 RAM**（固定额度、分区存放：系统指令 + 核心记忆 + 消息缓冲 + 近期函数返回），把**外部上下文（external context）当作磁盘/交换区**（归档记忆向量库、完整对话历史检索、外部工具），把**函数调用当作系统调用（syscall）**。执行模型是中断驱动的步循环：用户消息或定时任务到达即视为一次"中断"，模型在每一步可发出多个记忆管理函数调用，宿主执行后把结果作为 function response 追加回上下文，模型再继续；直到不再产生函数调用才输出回复并结束该步。关键洞见是把"自编辑记忆"变成**函数调用副作用**而非提示词技巧：模型通过 `core_memory_append/replace` 直接改写下一轮提示词里的常驻区。该项目后产品化为 Letta。

## ② 组件清单

| 组件 | 类型 | 职责 |
|---|---|---|
| 主上下文 main context | 记忆层 | 固定 token 预算的"RAM"，含系统指令、核心记忆、消息缓冲、函数返回 |
| 核心记忆 core memory | 记忆层 | 主上下文内的可自编辑常驻区，分 persona / instructions / key / human 段 |
| 消息缓冲 message buffer | 记忆层 | 主上下文内的近期对话与调用历史，按条数或 token 窗口滚动 |
| 归档记忆 archival memory | 外部存储 | 向量库，支持 insert / search，跨会话持久 |
| 会话召回 recall | 外部存储 | 对完整消息历史的检索（conversation_search） |
| 记忆管理函数 | 工具 | core_memory_append、core_memory_replace、archival_memory_insert/search、conversation_search |
| 步循环 / 调度器 | 循环 | 触发一轮生成 → 解析函数调用 → 执行 → 回灌 → 再生成，直到无调用 |
| 中断机制 interrupt | 通信 | 用户输入/外部事件可抢占并插入当前上下文，触发新步 |
| 上下文组装器 | 状态 | 每步按固定模板拼装提示词：指令 + 核心记忆 + 缓冲 + 调用对 |
| 宿主执行层 | 工具/状态 | 真正执行函数、访问存储、施加调用次数与超时上限 |
| 评估套件 | 评估 | 深度记忆检索、文档 QA、对话式记忆任务及消融配置 |

## ③ 数据与上下文流

1. **触发**：用户消息由宿主直接 append 进消息缓冲（不等模型决定），并作为一次中断唤醒步循环。
2. **组装**：每次调用 LLM 前，宿主按固定模板重拼上下文——系统指令 → 核心记忆三/四段 → 最近 N 条缓冲消息 → 之前的 function call / function response 对。这是外部内容进入上下文的**唯一合法通道**。
3. **调用与回灌**：模型输出函数调用 → 宿主在外部存储上执行（写入核心记忆或向量库，或检索）→ 结果以 function response 消息追加到上下文 → 再次调用模型。
4. **状态落点**：核心记忆的"权威副本"在宿主侧会话状态中（改写即时生效并随会话累积）；归档记忆与会话召回存在外部存储，跨会话持久；消息缓冲随会话滚动。
5. **可见性**：同一会话内所有步共享同一核心记忆视图（它就是提示词的一部分）；外部存储对模型不可见，只能通过函数返回值被"看见"；模型改写核心记忆后，下一步及之后所有步骤立即看到新版本。

## ④ 失败处理与停止条件

- **步终止判据**：模型返回不含函数调用的 assistant 消息 → 本步结束并回复用户。
- **步内调用上限**：宿主强制每步最多 N 次函数调用（论文实验中作为可调参数，典型为 1–4 次），超限则强制收束作答。
- **全局预算上限**：最大步数/总 token 花费硬超时，避免"反复调用—检索—再调用"死循环。
- **函数执行异常**（检索超时、存储不可用、参数非法）：以错误文本作为 function response 回灌，让模型自纠或改走备用路径。
- **上下文超预算**：首选由模型先写外部再驱逐主上下文条目（分页）；若模型不驱逐，宿主降级裁剪最旧消息，保证不溢出。
- **写入失败/超长**：`core_memory_append` 写入超限或失败时回灌错误，要求模型改写压缩后再写。
- **检索空结果**：返回空集，模型应改写查询或直接作答（论文未设计独立的回退栈）。
- 无独立的"自省—修复"外循环；纠错主要靠工具错误回灌后的下一轮再生成。

## ⑤ 预算与评估方式

- **预算**：主上下文固定额度（实验用 2k/4k/8k token）；消息缓冲按条数或 token 窗口滚动；溢出内容进归档记忆；每次函数返回值占主上下文预算，构成隐性成本；步内调用数与总 token 双硬限。
- **基准**：合成**深度记忆检索**（多层嵌套 KV，需跨多文档、多跳取回，深度可达 10 层）、**文档 QA**、**长对话记忆**（多会话跨轮召回）。
- **基线**：full-context（全量塞入长上下文）、function calls / RAG 检索、ReAct。
- **主要结论（数值存疑）**：4k 主上下文的 MemGPT 深度记忆检索表现约等于 27k 级 full-context 基线；在对话式记忆任务上以更小上下文反超更长上下文的 full-context。
- **消融**：主上下文大小（2k/4k/8k）、每步允许函数调用次数、是否开放记忆管理函数/自编辑核心记忆、是否开启外部检索。
- **指标**：任务准确率/精确匹配 + token 成本；部分结论用 GPT-4 判分做定性评估。

## ⑥ DSL 表达点清单

**(a) 可映射为「标准拓扑 + 组件」的机制**

1. 中断驱动的单节点 ReAct 式循环 = 节点「思考—调工具—观察」+ scheduler 的 event trigger 入口。
2. 主上下文/外部上下文分层 = 记忆节点的分层属性（resident tier vs paged-out tier）+ 上下文组装阶段。
3. 自编辑记忆函数 = 带 **write-back 副作用**的记忆写边（append / replace 双算子），区别于普通工具。
4. 归档记忆检索、对话召回 = 只读检索边，结果以 observation 回注上下文。
5. 向量库 / 消息库 = 外部 state provider 引用（跨会话持久存储）。
6. 每步调用上限、上下文上限 = 运行时守卫（budget guard）属性，可静态声明。
7. 消息缓冲窗口 = 环形/滑窗记忆策略，静态可配。

**(b) 预计需要 DSL 逃逸舱的机制**

1. **运行时自改写核心记忆**——模型自己重写提示词片段并即时改变后续所有步骤的输入；图结构不变但上下文内容在运行时自生成，只能靠 runtime state mutation 逃逸舱。
2. **运行时自由选择下一工具**——可调用集合与调用序列由模型在运行时决定，不可静态枚举，需 dynamic tool dispatch 逃逸舱。
3. **自然语言终止谓词**——"直到模型不再发出函数调用"无法用固定步数循环表达，需 predicate-based loop 逃逸舱。
4. **动态注入量与预算分配**——检索返回条数、长度运行时才确定，主上下文预留多少给外部结果不可静态计算，需 context assembly 逃逸舱。
5. **语义化分页/驱逐**——"先写外部再删主上下文"的顺序由模型判断，驱逐条件是语义条件而非静态规则，需 conditional eviction 逃逸舱。
6. **任意时刻插入的中断**——用户消息可抢占正在进行的生成并改变步边界，异步抢占语义需 escape hatch。
7. **跨会话一致性**——外部存储写入与后续会话读取的一致性语义超出单次拓扑声明范围，需 session-external store 逃逸舱。
