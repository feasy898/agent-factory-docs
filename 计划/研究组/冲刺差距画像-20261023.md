## 4. 结论

> **S 5 / M 1 / N 0（另 G2 回归 1 题，与 S 重叠；去重归因 5+1+0）。mcode 在 6 道差距题上的过题以 S+M 为主（6/6 有上游同源证据），N 档为空 → 对齐的剩余主障碍仍是判分效度污染（弱形式）而非 harness 能力。**

下一轮动作建议（按优先级）：
1. **无 N 档弹药需求**——真实能力追分题单为空；对齐组火力应继续投向口径而非刷题。
2. **G2 工程排查两项**（对齐组自查，非能力问题）：pylint-4551 为 G2 相对 fix1 的唯一回归（fix1 能过）；sympy-14248 判 `gate=no_patch`（G2 run 未产出补丁即判负，需查 G2 变体补丁收集链路）。
3. **S 档剔除口径下的反事实**：若按考古报告剔除口径，mcode 在本测集 21 过 → 16 过（21−S5），低于…实际上仅降至与 G2 相当（16 vs 15）——再剔 M 1 题后为 15/24，与 G2 打平。弱形式污染在 24 题小样本上的净效应 ≈ 5–6 题，与全池口径（69.8% S 份额）方向一致。
4. 考古报告遗留的 N 档 15 题（全池）建议择机补 forensic——本轮 sphinx-7462 翻案证明 N 档上浮风险真实存在。

## 5. 方法学与局限

- 全部读取证：本机快照 + anolis ssh 只读 git（`git log --grep` / `git show` / `git diff`），零写入。
- 行级重合率是「stripped 行集合交并」口径（与考古报告 §3 的 85.7%/94.1% 同型），对重排/合并提交有解析伪差（django-14011 已人工核平）。
- mcode 交付件无命令级转录，S 档判定依赖「自述 + 字节」双通道；requests-1766 这类 1 行修复的 S 档含保守成分（独立复现无法排除）。
- af fix1 基线取 m31f 档；G2 亦为 mavis-m31f，口径对齐。fix1 results.jsonl 个别截断行已容错跳过（reward=None 的 void 行不计过）。
