# W2 多 agent 首单路径裁决（2026-10-24）

- 裁决者：第二阶段编排者
- 依据：MARBLE-侦察-20261024.md（ulab-uiuc/MARBLE@8d60fa1 静态侦察 + TaskBench/JARVIS 快查）、计划 00-总纲 §0、ADR-005、A1 验收标准
- 影响面：W2「MARBLE 工件投递改造 + bench→WorkOrder 转换器 + 首笔多 agent 订单」的路径选择

## 裁决

**多 agent 首单走自建路径：AFB 原生多 agent 图（挂软件工程/研究报告包场景），不引入 MARBLE 运行时。MARBLE 整体改造退出第二阶段范围；TaskBench 降为任务内容与离线判分的 schema 参考。ADR-005 相应修订（修订文随下一次 af 仓提交批入 docs/adr/）。**

## 理由（侦察证据 → 裁决映射）

1. **改造最大头 ≈ 自建的全部工作量**。判分离线化（侦察结论改造第 1 件）要求为接入子集逐任务固化里程碑 + 写确定性 checker——这正是自建任务集本身的工作；做完这件事还背着约 4.9k 行外部框架（marble/agent + engine + graph + memory + llms 合计 4308 行，evaluator 618 行，4308+618=4926；MARBLE-侦察-20261024.md `wc -l` 口径）的维护成本与对话语义耦合。投入产出倒挂。
2. **三项根本冲突需动其骨干**。消息语义=双 agent 5 轮自由聊天、跨 agent 数据流=截断 1000 字符串拼接、任务关系=社交三元组（侦察 ④ 表 #1-#5）——与宪法「只传工件引用、数据流图非对话拓扑、判分可离线」逐条相抵；改造面集中在 engine/base_agent/evaluator 核心，等于重写骨干只留皮。
3. **单一入口原则**。引入 MARBLE 引擎=工厂内第二套执行拓扑，与用户裁决「以后不存在两个入口」同构冲突；MARBLE 的 litellm 端点、判分模型配置又是一套独立供给面。
4. **af 原生多 agent 语义已就位**。AFB 的 nodes/edges/stores/envelope/artifact_contract 即多 agent 协作的领域语言；15 对齐稿中 MetaGPT/CAMEL/GPTSwarm/Multi-Agent-Debate/Agensh 五协作目标 L1-L4 全链 15/15 编译通过（G3 矩阵 v2）。缺的只是一个真实任务集，不是一个外来执行引擎。
5. **首单验收在 af 面原生满足**。独立判分（零 LLM 自评）、MES 记账、OTel trace、工件落盘——af-order→af-execline 全链已由 F-首单/F-第二单单 agent 订单实证；MARBLE 路径要先完成三大改造才够到同一起跑线。

## 处置明细

| 项 | 处置 |
|---|---|
| W2「MARBLE 工件投递改造」 | **取消**（从 W2 任务清单移除） |
| bench→WorkOrder 转换器（40 计划 §3.2 协议） | **保留，目标改 TaskBench**：DAG 任务（dailylifeapis 275 条 dag 拓扑等）→ AFB 图，工具节点挂 af 组件 mock 实装，离线 F1/编辑距离判分。用于后续扩量与外部口径对照，非首单前提 |
| MARBLE 500 任务库 | 保留为第三阶段素材（届时若需外部 benchmark 口径再议接入改造）；/tmp/marble-scout 130M 归档至 ~/bench-data 或按 /tmp 纪律自然过期 |
| 多 agent 首单任务 | 自建：2-3 agent AFB 图（planner→coder→tester 或 debate/map-reduce 形态），挂软件工程包（G4 产出），判分走真实测试执行独立判分；详见 F-第三单/F-第四单任务书 |
| TaskBench 定位 | 由「备选运行时」改为「任务内容 + 离线判分 schema 参考库」（其 node=工具产工件、link=依赖边 与工件流宪法同构，作 DAG schema 蓝本） |

## 对验收的影响

A1「含单 agent 与多 agent」不变：多 agent 单=AFB 多 agent 图经同一门面下单、同一执行面执行、同一判分链裁定——这恰是任务中立性与单一入口的更强证明（外来 benchmark 引擎做不到同通道）。
