## 5. af 反考古护栏语义审计（追加令）

代码：`af/crates/af-bench/src/main.rs:568-576`（ARCHAEOLOGY_PATTERNS 六模式：`cat-file --batch-all-objects`/`git fsck`/`--lost-found`/`git log --all --grep`/`find / -name`/`find / -type`）、`:711-720`（bash 工具闭包内子串匹配→**输出前注入劝退语、真实输出仍完整返回**，命令照跑）；另有同命令重复≥3 次熔断（:722-728）。结论：

- **语义=通道级劝退，非内容级拦截**：不检查补丁与上游相似度，不阻止写"与上游相同的修复"；命中只注入一条消息。**"af 在内容层压制模型知识"不成立**。
- 但注入语是**事实性假话 + 战略误导**：「the upstream fix is not in this repository … this line of work never pays off. Implement the fix yourself」。实测 sphinx-7462 的 /testbed `.git`：packed-refs 已剥到 base（master→base、tags 截断），但 `count-objects` **in-pack=103400 对象**——全史对象物理在场，`cat-file --batch-all-objects` 实录列出 37951 blob。护栏说"不在库里"，实际未来修复就压在对象库里。
- **触发面与效果（6 题 G2 轨迹实测）**：每题命中 2-4 次（多命中在合法的 `find / -name` 广搜上）；sphinx-7462 af agent 在注入语在场的情况下仍扫完 37951 blob、定位 `_parse_annotation` 的 11 个历史版本（11 hits 实录），**但预算耗尽未能收敛**（agent.diff 仅 1238B，f2p 0/2）。护栏既没拦住挖库，也没把挖库的时间省下来——失败模式=考古烧预算（与护栏设计初衷 51/145 run 的病理一致）。

- **合并终句：25pp 差距主体 = 环境型未来信息不对称（弱形式污染的通道重定位：git refs → 预装未来包 + PyPI 镜像 + 权重知识自由变现），非 git 工作区污染（A 否证），非纯 harness 能力差（权重知识两线对等），非护栏内容压制（C 否证、仅次要加重）。按 SWE-bench 官方方法论 af 的 era 容器才是干净口径，mcode 的 21/24 官方与 110/120 干净锚均含环境泄漏增益。主攻建议：①mcode 线补"环境净化"变体（era 容器内解题或断网+清预装）拿真干净锚；②修 af 死代理（swev.rs:80-88 的 8123 指向不存在的 squid）使两线网络等价；③护栏假话文案改为如实陈述+限时劝退；④等价环境重测后，django-14011 型"独立实现"残余差距才是真 harness 能力主攻面。**
