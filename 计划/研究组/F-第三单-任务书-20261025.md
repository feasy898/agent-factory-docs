# F-第三单任务书：失败→分类→重试路径（2026-10-25 执行）

- 编制：2026-10-24 晚（编排者）；执行：待派发执行批
- A1 依据：稳定性验收要求 ≥5 单跨 ≥2 天，**含 1 次失败→分类→重试路径**——本单即该路径的载体
- 前置：F-首单/F-第二单已过（resolved=true，L2 硬闸门，独立判分）；CI 七门合流批已落地

## 一、订单设计

1. **首跑单（注定失败的预算探针）**
   - 通道：`af-order submit` → release → start，走真实执行环（patch B 的 `--task/--profile/--data-root` 三件），**零 zcode 干预下单**。
   - 题目：自冻结 SWE 题集选 1 题（与首单 django__django-11099、第二单选题不同族，避开已解题）。
   - 关键参数：`--spend-cap-cents` 设为该题正常预估消耗的 **1/3 以下**、`--max-turns` 同步压低——让 agent 在容器内**真实**触顶失败（预算熔断/run_failed），**禁止构造假败**（不注水、不喂错题、不人为断网）。
   - 预期：订单以失败态收场（complete(failed) 或 judge 判 resolved=false），这是**合格结果**，不是事故。
2. **失败分类（订单面）**
   - 对失败单做独立归因（判分器输出 + 执行面 ledger + escape/审计事件），映射失败分类账口径（A 缺组件 / B 语义缺口 / C 工程缺陷 / D 环境因素，见 研究组/失败分类账.md）记录于订单目录与 F-第三单交付文。
   - 分类动作不改动任何工厂代码——本单只验证「失败被如实记录、正确分类、可指导重试」。
3. **重试单**
   - 同题重新 `af-order submit`，正常预算；成功标准=独立判分 resolved=true + MES 记账齐全 + trace 完整（invoke_workflow→invoke_agent→chat→execute_tool）。
   - 重试单在分类记录之后发起（时序留痕：分类→决策→重试），证明失败信息真的指导了重试而非碰运气。

## 二、验收判据（编排者终验）

| # | 判据 | 证据 |
|---|---|---|
| 1 | 失败真实且被捕获 | 首跑单执行面记录 + 判分器独立输出（无 LLM 自评） |
| 2 | 失败分类落档 | F-第三单交付文：分类号 + 归因链（判分/ledger/事件三源） |

| 5 | 跨天 | 首跑 10-25（与 10-24 的 F-首单/二单构成 ≥2 天跨度） |

## 三、纪律

- 失败本身不许规避也不许伪装：预算参数照任务书执行，跑了就是跑了。
- 判分三件套契约不触碰；golden/冻结题集零改动。
- 失败单不删除、不隐藏：订单目录与 MES 记账全量保留（失败是 A1 验收资产）。
- 若首跑单意外**成功**（预算估错）：如实记录，换更狠的预算参数重跑首跑单，直至取得真实失败样本；不许把成功单冒充失败路径。
