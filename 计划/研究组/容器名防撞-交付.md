## 2. 设计与决策

**新容器名**：`afbench-<instance>-swev-<task>-<profile>`

- `instance` = `--out` 目录路径字符串的 sha256 前 8 位十六进制（`swev::instance_id`）。
  选型理由：①稳定——同一臂的 `--out` 由调度器恒传（factory-sched 全绝对路径），跨重启同哈希；
  ②无新参数、无 I/O、无失败分支（不 canonicalize，避免目录被删/竞态的边缘分支）；
  ③不同 out 天然不同名——失败模式单向安全（最坏多出一个实例名，不会退化成同名互踩）。
- `task_id` 的 `__`→`-` 消毒口径与旧实现逐字一致（不改判分/取证任何语义）。
- **默认带前缀，不设兼容开关**。依据即 §1：无精确名消费者，旧引用全是通配/占位/历史；
  且工厂常态多线并行，默认关=把"根治"降级成"记得传参"，违背立项目的。
- 测量语义零改动：只动容器命名；提示词/采样参数/判分口径/结果行字段全部未动
  （真实验证结果行键集与 fix3 代际一致，含 `judge_mode`、`scaffold=v3`，代号不变）。

**diff 摘要**（daef39c，7 files，+1259/-833，其中 ci/out 产物 +1199 行）：

- `crates/af-bench/src/swev.rs`：新增 `instance_id()` / `container_name()` 两个纯函数；
  `setup()` 增 `instance: &str` 参数（唯一调用方）；新增 4 个单测。
- `crates/af-bench/src/main.rs`：`run_swev` 在任务循环前按 `args.out` 计算一次 instance 传入
  （同进程所有任务共用，与旧行为"每任务同名"相比仅多一段哈希）。
- `ci/out/`：CI 七门产物入库（全绿）。

## 3. 测试证据

### 3.1 单元测试（cargo test -p af-bench：8/8 过，4 个新增）

- `instance_id_stable_per_out_dir`：同 out 稳定 / 不同 out 必异 / 8 位小写十六进制；
- `container_name_shape_and_docker_charset`：名形 `afbench-<i>-swev-<task>-<profile>` 且落在
  docker 合法名字符集内；
- `cross_line_same_task_never_shares_name`：同题同 profile、instance 不同 → 容器名不同（根治点）；
- `task_id_double_underscore_sanitized_like_before`：`__`→`-` 口径不变。

### 3.2 并发防撞实测（anolis，伪任务零成本，新旧二进制对照）

方法：伪任务 `zz-cnametest__fake-1`（镜像用 anolis 已在册的 pylint-6386 镜像，零拉取）；
profile `qwen30b-local`（端点 127.0.0.1:11435 无监听→连接拒绝不重试、立即失败，**不烧任何
额度**）；本机起暂停式 TCP 监听拉长 agent 窗口（30s 后关闭，两进程各自以传输错误收尾）；
A 启动 +3s 后启动 B（复现"后者 setup 落点时前者 agent 在飞"的事故时序）；0.2s 粒度轮询
anolis 容器名+短 id。

| 对照 | 旧二进制（main f373113 构建） | 新二进制（daef39c 构建） |
|---|---|---|
| A 容器 | `afbench-swev-zz-cnametest-fake-1-qwen30b-local` = 76a9344aed18 | `afbench-d1a2e924-swev-…-qwen30b-local` = bac553de5118 |
| B setup 后 | **同名被换成 B 的容器 561d3a5119a9**（A 进程仍活着，容器被偷天换日） | B 自起 `afbench-358eba79-swev-…-qwen30b-local` = a1180f45ea03 |
| 并存证据 | 轮询只有 1 个名字，id 在 837.67s→839.23s 之间被换 | **33 个连续快照（≈6.6s）双前缀容器同时在飞**，id 稳定不动 |
| 收尾 | 双双 run_failed（端点传输错误，符合预期） | 双双 run_failed（同因）；各自 cleanup 自己的容器，**anolis 零残留** |

旧方案机理复现完成：后启动线的 `docker rm -f` 精确击杀先启动线的 agent 容器——即 14:4x 事故
与 fix2 A/B 硬排除的根因；新方案下该 rm 物理上不可能命中异名容器。

## 4. 换装建议（随硬换位窗）

1. **换装即生效、无迁移动作**：容器名只在 setup 时生成；换装后新臂自然带前缀，在飞旧名容器
   跑完自清（旧二进制每次 setup 也先 rm -f 旧名，不会因换装泄漏）。
2. **双名并存期**（换装瞬间）：新旧容器名可能同时在飞，巡检/护栏抽样按名 grep 时用
   `afbench-*-swev-*` 或先 `docker ps | grep <task关键词>`（护栏rollout手册已按此修订）。
3. **换装后验证三连**（建议纳入换装 checklist）：①新臂容器名形如
   `afbench-<8hex>-swev-<task>-<profile>`；②`docker inspect` 护栏值 6442450944/512；
   ③跨线同题双跑不再需要人工硬排除（D-22/D-37 的运营避雷终结）。
4. **勿与 fix3 判分路径混淆**：main 代际 judge_mode=clean（本机干净判分容器，judge.rs 自有
   唯一后缀命名，与本次改动无关）；本次不改判分落点。
