## 4. 给审计者的高危条目提示

1. **B-14/B-15（route 互斥/覆盖）— 最高优先**。全语言唯一条件边产生点的正确性论证（提案B :245「只有这一处需要正确性论证，而它被归一化算法免费保证」）。互斥+覆盖是**构造性宣称**：若 lowering 实现与 §1.5 算法有任何偏差（如规则排序、¬ 展开遗漏），互斥覆盖双双失守且无第二道防线（:48 明文禁止执行面再仲裁）。Rocq 归纳证明即可闭环，建议第四档首个落地。
2. **B-18（幂等键）+ B-17（消费幂等）— 恰一次效果的两根支柱**。唯一性依赖 attempt 分量单调（规范 :12 总则 3），而其机制强制在执行面 TCB（矩阵 :49）；「传输层 at-least-once 是假设不是保证」（矩阵 :59）。审计盯执行面 attempt 生成与重放去重实现，不能只审声明面。
3. **D-05（from_state 的 unreachable!）— 结构债务点**。`Transition::from_state` 对 Cancel 是 `unreachable!`（state.rs:42），正确性依赖「Cancel 是唯一多起点跃迁」这一隐性前提；未来新增多起点跃迁时该函数会 panic 而非编译失败。建议审计时核对新增跃迁是否触碰此假设（D-05 已把前提显式化）。
4. **A-04（E2304 多引方向）— 唯一可能存在静默缺口的 INV 条目**。若 af-dsl 对端口被多 section 引用不报错，§5 规则文字与实现之间有未被失败分类账覆盖的缺口（既有测试 206 例是否覆盖多引形态，本战役未查——只译不证纪律下未跑 af-dsl 测试套件）。建议第四档 Kani harness 直接以多引 AST 探针。
5. **B-13（map 聚合序）— 执行面最易踩的坑**。完成序混入聚合会直接破坏逐位可复现纪律（规范 :40 明文「不是完成序」），且失败类实例的聚合边界按 failures[] class 声明变化——审计执行面聚合器时先取该工单的 failures[] 声明再断言。
6. **C-01（确定性口径）**。golden ×2 逐位断言是 G2 放行判据（G1裁决 :31）又是「测试义务非功能保证」（矩阵 :41）——审计者确认该断言在 CI 持续兑现的同时，留意口径张力（歧义 #11）的后续裁决。
