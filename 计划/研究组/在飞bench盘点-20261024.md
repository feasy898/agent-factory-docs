## ④ 切流安全窗口建议（如何不打断在飞）

1. **窗口选择**：当前（13:4x）是罕见的全空窗——本机 0 判分进程、anolis 0 容器、cb/mcode/factory2 全排空、anolis 负载 <1.1。但**不要现在切**：三出题组在飞，其跑批（af 侧用冻结二进制 7a87876c、mcode 侧走容器执行面）随时会起。**建议窗口 = 三测试扩量收官后的第一个确认点**（条件③-1 四项检验全过），且避开整点（cron obs-patrol 17 分触发前后 1min）。
2. **停机顺序（依赖序，错序会被 keepalive 复活）**：
   `main-sched → exp-sched → cb-run` 先停（派发者先死，防新工作量）；
   确认 running=0 后停 `factory-keepalive`（**必须先于其看护对象**，否则 30s 内把 sched/cb-run/8124 全部拉回）；
   再停 `anolis-proxy-8124`（确认 mcode 线不再用后）、`ch-mes-local` 锚点；
   **观测面（factory-watch → dash → cron obs-patrol）最后降级**，保证切流全程有安灯。
3. **12 条 pending 臂的防火墙**：停 main-sched 前若未走③-5 裁决，先把 /tmp/factory-graph.json、factory-status.json **原子拷贝归档**（keepalive graph_guard 会在图缺失时从备份自动恢复——D-25 机制，直接删图会被复活成"盲跑"状态）。
4. **禁触清单**：本机 dockerd 不重启、不删 docker0（硬纪律 8/9）；anolis ollama 不停（qwen30b-local 若补跑还要用）；mingda MES 主链与 gov 生产面零接触；img-gc HALT 哨兵未经运营者不撤。
5. **记账与回滚**：每停一个对象记一条 MES 事件 + 巡检日志行；每个动作保留"回滚一行"（keepalive 重启一行、sched 重启一行、图从备份恢复一行），与 mes-ttl/anolis-ch 退役单同款格式。
