## 结论（三态建议）

### **需改造后接入**（MARBLE 维持主选，TaskBench 的图格式可作改造参考）

理由一句话：任务规模（5 场景×100）、拓扑定义、环境抽象、litellm 多后端、MIT 协议都满足门面派发需求；但**判分链几乎全 LLM-as-judge 且里程碑无静态 oracle**、**消息语义是纯文本双聊**、**跨 agent 数据流是截断字符串**——与 ADR-005 的『只传工件引用、数据流图非对话拓扑、判分可离线』三条要求逐条冲突，须改造。改造面集中在 engine/base_agent/evaluator + 任务格式，核心代码约 4900 行，属中改造，不是重写。

若改造三件事（工作量从大到小）：
1. **判分链离线化（最大头）**：500 个任务没有任何静态里程碑 oracle——现 KPI 是判分 LLM 临场从 agent 结果文本里"识别"里程碑（`marble/evaluator/evaluator.py:130-168`），graph 模式下甚至整段被注释、只写 -1（`marble/engine/engine.py:294-317`）。要离线判分必须先为接入子集人工/半自动固化里程碑与验收断言，再写确定性 checker（coding 场景可挂真实测试执行，DB 场景已有 labels/root_causes 可直接对答案）。
2. **消息语义改工件投递**：拆掉 `new_communication_session` 双 agent 5 轮自由聊天 + LLM 总结（`marble/agent/base_agent.py:392-548`），换成 artifact store + 引用投递原语；同时把 engine 四种 coordinate 模式里所有"任务=字符串、结果=截断 1000 字符拼接"的传递点（`engine.py:1082-1085`、tree 递归 `engine.py:985-994`）改为传工件引用。
3. **任务格式加 artifact DAG**：现 `relationships` 是社交语义三元组（`["agent1","agent2","collaborates with"]`，`multiagentbench/coding/coding_main.jsonl` 第 1 行），不是数据依赖边；需在任务 JSONL 中新增 工件节点/依赖边 schema，并让 engine 按 DAG 就绪调度取代固定轮询（`engine.py:323-428` 的 while 循环）。

## ① 任务格式与规模

- **格式**：JSONL，每行一个完整任务。顶层键：`scenario / task_id / coordinate_mode / relationships / llm / environment / task / agents / memory / metrics / engine_planner / output`（用 `python3 json.loads` 逐场景首行验证；DB 场景多一个 `communication` 键）。配套 `multiagentbench/jsonl2yaml.py` 可转成运行用 YAML config（`marble/main.py --config_path` 加载，`marble/main.py:29-46`）。
- **规模**：5 场景 × 100 行 = **500 任务**。`wc -l` 实测：`bargaining/coding/database/minecraft/research` 各 `*_main.jsonl` 均 100 行。agents 每任务 2~4 个（coding 首任务 3 agent，各有 profile 角色设定）。
- **里程碑 KPI 怎么定义**：**仓库内没有静态 oracle**。
  - `marble/utils/milestone.py:6-59` 的 `generate_task_milestones()` 用 GPT-4o 把任务拆成里程碑——但全仓库 grep 无任何调用者，是**死代码**。
  - 实际 KPI 链：`Evaluator.evaluate_kpi()`（`marble/evaluator/evaluator.py:130-168`）把 task + agent 结果字符串（截断 7200 字符，`:139-142`）发给判分 LLM，让它返回"已达成里程碑" JSON 数组，`total_milestones` 与 `agent_kpis` 按此累计。
  - **发现一个实锤 bug**：KPI prompt 要求里程碑对象带 `"agents": ["agent1",...]` 键（`marble/evaluator/evaluator_prompts.json` Graph.KPI），而解析器读 `milestone.get("contributing_agents", [])`（`evaluator.py:162`）——键名不匹配，`agent_kpis` 恒为空。接入时要顺手修或换掉。
- **oracle 在哪**：只有两处非 LLM oracle——
  - **DB 场景**：任务自带 `task.labels / task.root_causes / task.number_of_labels_pred`（`multiagentbench/database/database_main.jsonl` 首行：labels 5 项、root_causes=["INSERT_LARGE_DATA"]），可确定性对答案（但 `evaluate_task_db` 现在只把预测存下来不判，`evaluator.py:284-300`，判分后置在 `scripts/database/batch_eval.py`）。
  - **Minecraft 场景**：外置 `build_judger.py` 写 `data/score.json` 的 `block_hit_rate/view_hit_rate`（`marble/environments/minecraft_env.py:151-155` 拼命令、`data/score.json` 样例），engine 读 `../data/score.json` 判停与打分（`engine.py:270-279,465-471`）——注意是**硬编码相对路径**，目录不对就静默按 0 分。

## ② agent 协作机制

- **拓扑如何定义**：任务 JSONL 的 `relationships` 三元组列表 → `AgentGraph`（`marble/graph/agent_graph.py:36-59`；tree 模式遇 "parent" 关系建父子链）。执行拓扑由 `coordinate_mode` 四选一：**star（中心 planner 派活）/ graph（每 agent 自规划自执行）/ chain（agent 选下家传话）/ tree（根节点递归派子任务）**，分发在 `marble/engine/engine.py:1041-1052`。
- **消息语义**：**纯自然语言对话**，无任何工件概念。
  - agent `act()` 时 LLM 可调 `new_communication_session` 工具发起与目标 agent 的会话（`marble/agent/base_agent.py:169-195,254-266`）；`_handle_new_communication_session()` 让两个 agent 轮流纯文本聊 **5 轮**（`turns=5`，`base_agent.py:263,392-497`），最后再让 LLM 总结聊天史（`:499-531`）。消息收发是进程内 `msg_box` dict（`send_message/receive_message`，`base_agent.py:319-355`）。
  - **graph 模式下 agent 间唯一"数据流"**：每轮各 agent 的 act() 返回字符串，engine 全部**截断到 1000 字符**后拼接成 summary（`engine.py:1069-1088`）；tree 模式子结果 `json.dumps(result)[:500]` 塞进父任务 prompt（`engine.py:985-994`）。这正是 ADR-005 要消灭的"对话拓扑"。
- **共享内存**：`SharedMemory` 只是带锁 dict（`marble/memory/shared_memory.py:9-53`），且 **engine 从未把它注入 agent**——`_initialize_agents` 建agent 时不传（`engine.py:157-165`），BaseAgent 自己 new 一个私有实例（`base_agent.py:73`）；engine 级 memory 只喂给 EnginePlanner（`engine.py:90-96`）。agent 间真正共享的只有环境：coding 的 workspace 文件夹、DB 的数据库。
- **现成的工件雏形**：coding 场景 agent 通过工具函数写 `workspace/solution.py`（`marble/environments/coding_env.py:44-47` 建共享目录；`coding_utils/coder.py:10-56` 写文件，含"文件已存在则拒绝"的防冲突）——即共享文件系统工件通道已存在，可作改造底座。但注意 `create_solution_handler` 从**硬编码路径** `marble/configs/coding_config/coding_config.yaml` 读任务而非用传入参数（`coder.py:31-45`），接线时要改。

## ③ 判分链（离线能力——本厂硬要求）

- **现状以 LLM-as-judge 为主**：`evaluate_communication / evaluate_planning / evaluate_kpi / evaluate_task_research / evaluate_task_world / evaluate_code_quality` 全部调 `model_prompting()` 发给判分模型（`marble/evaluator/evaluator.py:67-228,509-618`），判分模型取 `metrics.evaluate_llm`（默认 `gpt-3.5-turbo`，`evaluator.py:44-45`；minecraft 任务 JSONL 里显式写 `{"model":"gpt-3.5-turbo","provider":"openai"}`）。解析失败时静默给默认分（score=3、code_quality 全 1，`evaluator.py:384-389,493-498`）——**打分可靠性要打折**。
- **graph 模式半残**：graph_coordinate 里 communication/planning/KPI 的 LLM 判分调用整段被注释、只 append -1（`engine.py:294-303,306-317,389-413`）；KPI 判分只在 star/chain/tree 生效。选 graph 模式接入时协作分无效。
- **离线/本地替代可行性：可行**。
  - 所有 LLM 调用走 **litellm** 单点（`marble/llms/model_prompting.py:39` `litellm.completion`），换成 OpenAI 兼容本地端点（vllm/ollama）只改模型字符串与 base_url。
  - 仓库自带本地化参考栈：`marble/docker-compose.yml` 就是 **vLLM 服务 Llama-3.3-70B**（开 `--tool-call-parser=llama3_json --enable-auto-tool-choice`）+ nginx 负载均衡，证明作者自己就是本地跑的。
  - 判分调用不带 tools、prompt 短，本地小模型即可承担；agent 端因 `act()` 依赖 function calling（`base_agent.py:224-234`），本地模型需支持 tool call。
  - 完全离线（无 LLM）判分只在 DB（labels 对答案）和 Minecraft（judger）两场景现成；其余场景要按上面"改造第 1 件事"自建确定性 checker。

## TaskBench 快查（备选核对）

- 仓址勘误：`microsoft/TaskBench` 404，实际位于 **`microsoft/JARVIS` 仓库的 `taskbench/` 子目录**（NeurIPS 2024 D&B）。已稀疏浅克隆取证（45M），非纯远程浏览。
- **图格式与工件流同构度：高**。样本为 JSONL（`taskbench/data_dailylifeapis/data.json`），每行含 `instruction / tool_steps / tool_nodes / tool_links`，拓扑分 `single/chain/dag`（dailylifeapis 4318 条 = chain 2786 + single 1257 + dag 275；huggingface 7458 条；multimedia 5555 条）。节点 = `{"task": 工具名, "arguments": [{"name","value"}]}`，边 = `{"source","target"}` 数据依赖（实测解码 dag 样本）——**node=工具调用产工件、link=工件依赖边，与本厂『工件引用+数据流图』天然同构**，可直接借作任务 DAG schema。
- **判分全离线**：node-F1 / link-F1 / argument-F1 / 编辑距离 / rouge / bertscore（roberta-large，HF 模型下载一次后本地可跑），LLM 只在建库期用（`taskbench/evaluate.py:206,255,473-482`）。
- **致命差异：单 agent**。一次推理由一个 LLM 产出整张工具图（README/inference.py 单 `--llm`），无多 agent 派发、无协作维度——不能单独满足门面需求，只能当格式与离线判分的设计参考（这与 ADR-005 定位一致）。JARVIS 根 LICENSE 为 MIT（Microsoft）。
