## 1. 测试目标与原则

### 1.1 三个目的（本计划的存在理由）

| 目的 | 回答的问题 | 主要判据 |
|---|---|---|
| **真实接单** | 客户下单 → 无人值守生产 → 交付合格工件 → 成本可核算，这条链真的通吗？ | L1 端到端订单通过率（含 pass^k 稳定性）、每单三账本成本、SLA 达成 |
| **细粒度能力** | 每个机制与抽象（预算硬闸/止损/副作用网关/凭证收紧/工件血缘/…）在隔离条件下有效吗？失败模式是什么？ | L0 各机制注入测试验收信号全绿；失败模式有标签、可进安灯分类 |
| **冷启动** | 第一天，task graph 从哪来？JIT 语料从哪来？评估器考题从哪来？ | §4 三件套（图候选 / trace 语料 / 金标题库）就位并跑通首单 |

三者关系：冷启动给出起点 → 细粒度体检保证机制不失真 → 真实接单是最终验收。此外本计划还承载**产品验收**：三无关（任务/运营者/部署形态无关）是底座的存在前提（拍板版 §2.1），其检验方式以 L2 场景固化（L2-13/14/15），不外包给其他文档。

### 1.2 十条原则

1. **验收信号客观可复现优先**。信号强度排序：终态断言/测试脚本（SWE-bench、Terminal-Bench、τ²-bench、AgentDojo）＞ 短答案精确匹配（GAIA）＞ 二元规则逐条核验（DeepResearch Bench 式）＞ LLM-rubric（WritingBench、GDPval）。凡 LLM-judge 必须固定 judge 模型版本 / prompt / 温度并写入 Trace，且保留 Human Station 人工抽检通道（研·产线质量：judge 不可复现是最大风险源）。三态映射以 Inspect AI cascade scorer 为参考语义（研·评估器已读其 `src/inspect_ai/scorer/_cascade.py` 核实：廉价级→模型级逐级短路，任级弃权下传，全未决 = scoring_failed，decided_by 留痕）——弃权/冲突 → 需人工，全未决 → 需人工。
2. **质量与成本同权报告**。每份基准报告必含三账本：token、美元、墙钟（研·预算：Artificial Analysis 口径，正是拍板版机制 8 Meter 的最小字段集）。没有误差棒的分数不支撑升迁/降级决策（研·评估器：Adding Error Bars）；同任务 token 跨运行最多差 30 倍、模型自预测成本相关性仅 0.39（研·预算）——**单次测量不构成成本估计，成本结论必须多次采样**。本条管单条结论；**纲领总开销由 §3.4 预算包络管辖**。
3. **bench 运行分两档，只有一档进决策**：
   - **管道内运行**：bench 任务以 WorkOrder 进单（§3.2 转换协议）、消耗预算凭证、产生 Trace、成本入 Meter 对账——其结果可进升迁/降级与配方决策；
   - **CI 静态快检（烟雾档）**：InjecAgent 等零环境静态集可直跑，只作阻断性红灯（环境坏了/模型坏了的烟雾信号），**不进任何升迁/降级决策**。工具链形态：af 的 CI 六门是 cargo 门（20-质量 §1 L2 行），Python bench 快检**不混入 `af/ci/run.sh`**，独立为 bench-quick 档（uv/容器化、短超时），失败亮红灯不计入机制健康结论；
   - 绕过这两档的裸跑数据不进任何决策。
4. **评估器先考己再考人**。任何评估函数（含 judge）上线前过准入考卷（JudgeBench + Dark Current 克隆对零假设门 + Evaluator Stress Test，§3.1 L0-9）。
5. **版本钉死进 Trace**。数据集版本、Docker 镜像 digest、测试套件哈希、judge prompt 哈希作为 Trace 关键事件同步落盘（宪法 #7 版本贯穿）。τ²-bench 必须 ≥1.0.1（官方声明前后分数不可比，研·协同/工具）。
6. **抗污染与防刷分**。长期回归集按 Terminal-Bench continuous benchmark 模式维护（淘汰饱和任务，研·端到端）；按 LiveCodeBench 机制定期注入「当月新题+已知答案」（研·评估器）；金标考题答案与 JIT 优化集物理隔离（GAIA 保留 300 题答案是设计参照，研·产线质量）。
7. **分层依赖，绿灯推进，试跑有定义**：L0 单机制不绿，L1 结果不得进决策；允许「**试跑**」= 经工厂管道运行、结果标注 `trial`、只用于管道自身 debugging 与转换协议校准，**不进升迁/降级决策**。决策消费门槛按维度：安全决策 ← L0-4/5/6/7；预算与止损决策 ← L0-2/3；评估器上岗 ← L0-9/10；产线接单结论 ← 该产线的 L0-8 级工具体检。频率：L0 常驻（每波次收尾 + 夜间档）、L1 周期档（配方/模型池变更触发）、L2 里程碑档（挂波次 DoD，见文末附）。
8. **外部依赖最小化**。日常门禁只用本地可复现 bench；依赖外部评分服务（GDPval）或闭源模拟器（Vending-Bench 2）的只做季度/年度校准锚，不进门禁（研·端到端/产线质量可达性结论）。
9. **不赌**：止损规则的验收标准是「每条规则对应一个确定性 bound（步数/金额/重复计数）」——IAL-Scan 的有效边界判据（研·预算：模型输出式退出不算有效边界，仅 prompt 劝阻不算止损），对应拍板版机制 6「重试是赌注，不赌」。
10. **证据必须可复核**（20-质量 §3 同款纪律）：本计划引用的每个 bench 事实可回查 `设计/benchmark调研/` 对应文件；「未核实」标注不得在实测（§6.2 必查清单）前转化为「可用」。

## 2. bench 选型矩阵

采用方式定义（与调研口径一致）：
- **直接采用**：本地可复现 + 验收客观 + 维护活跃，接进工厂管道即用；
- **改造采用**：方法 / 数据 / 协议可移植，但环境、任务语义或评分需重写后才能进管道；
- **仅参考**：只取方法论或结论，不接数据集。

**档位一致性规则**：同一 bench 因用途不同跨表出现时，**主档以首次出现为准**，次用处行内互注（例：τ²-bench 主档在 §2.1 直接采用，§2.5 的中断-恢复变体为改造采用）；§2.9 的「禁止升档使用」按主档执法。

### 2.2 安全与对齐（三道防线）

先立三道防线映射（研·安全给出的结论，与工厂宪法直接对齐）：
- **Credential 凭证收紧** → Permission Denied（改造）+ CAPE-Bench（仅参考·自建配对）+ LivePI（场景复刻）；
- **副作用网关** → OverEager-Gen（仅参考·方法论必读）+ ToolSandbox（改造·milestone 判分）+ 自建幂等恢复注入集（§3.1 自建件 B）；
- **Tool/Skill broker 验权** → MCPTox（改造）+ ASB（直接）+ AgentDojo（直接）+ InjecAgent（直接）。

| bench | 方式 | 理由 | 注意 |
|---|---|---|---|
| **AgentDojo（97 任务 / 629 安全用例）** | **直接采用 · 安全主干** | 唯一「完全本地可复现 + 确定性验收函数 + 攻防参数化」三全；utility/security 双指标都是对环境终态的形式化断言；注入任务以脚本驱动工具调用，可录成 trace 回放语料喂 JIT 冷启动（研·安全） | MIT，pip+容器本地跑；全量跑走管道内档（§3.1 L0-5），不属 CI 快检 |
| **Agent Security Bench（400+ 工具 / 27 攻防方法）** | **直接采用 · 攻防矩阵** | 工具攻击覆盖面最宽的现成语料；memory poisoning 一路可压测工厂 Trace/记忆注入（研·安全） | MIT，本地跑 |

| **R-Judge（569 条交互记录）** | **改造采用** | 质检/审计工位的校准集：先验证评估器能识别这 569 类记录，再让它评产线工件（研·安全） | NOASSERTION 许可 |
| OS-Harm / SafeAgentBench / ToolEmu | 仅参考 | 前两者需 GUI VM/具身仿真器，与黑灯形态不匹配（研·安全）；ToolEmu 用 LLM 模拟工具 = 无真实副作用，安全结论不可信（研·安全明示） | 只取分类法与「危险检测器验收」口径 |

### 2.3 多智能体协同

## 3. 分层测试计划

### 3.0 总览

```
L0 单机制体检 ——机制/抽象在隔离条件下被注入测试验证（常驻：每波次收尾 + 夜间档）
   ↓ L0 绿是 L1 结果进决策的前提；L1 可先试跑（trial，不进决策）
L1 模拟接单   ——端到端 bench 任务转成 WorkOrder 进单，走完整工厂管道（周期档）
   ↓ pass^k 稳定才做
L2 全厂联调与压力 ——多产线并发 + 投放闸/安灯/人工工位/熔断在压力下的行为
                  + 产品验收（三无关）+ 交付/订单高级语义（里程碑档）
```

分层理由：L0 隔离归因（单机制失败≠工厂失败）；L1 验证机制组合后的端到端行为；L2 验证压力、异常与产品级前提下的联动。L0/L1 的 bench 运行本身产生 trace 与三账本数据，直接喂 §4 冷启动。

**自建件规格（三件，皆因无现成 bench——研·预算/安全/工具明示的缺口；规模数字为规格建议，非调研事实）**：

- **自建件 A · 预算违规注入集**：用 ToolMaze 确定性扰动引擎形态构造两类任务——①必然超支（任务真值成本 > 凭证预算，如需三倍 token 的数据处理）≥30 条；②必然循环（同一工具同参数连续失败）≥20 条。协议用 BAGEN rollout-replay：注入 oracle 前缀，**断言闸门行为而非 agent 行为**。预期失败模式清单直接搬 BAGEN 结论（模型自报预算不可信 → 硬闸必须外置）。验收：超支任务在阈值处被拦截且状态一致；循环任务触发重复计数指纹；早停的 token 节省与成功率损失按双列报告。
- **自建件 B · 幂等恢复注入集**：按 UndoBench 三阶段（变异前 / 部分变异 / 已提交未确认）注入故障，反事实配对（有检查点恢复 vs 无），oracle = 线级副作用历史。验收：条件恢复成功率 ≥ 配方阈值；重复外部副作用率 = 0。
- **自建件 C · 授权配对用例**：按 CAPE-Bench 设计——每个用例只有一个关键事实决定动作是否被授权，授权/未授权成对出现，含「事后补授权」诱导。验收：越权率 ≈ 0、谎报率 ≈ 0，配对差异显著可测。

### 3.4 基准预算包络与执行优先序

原则 2 管单条结论的采样纪律，本节管**纲领总开销**——基准纲领自身必须受预算硬闸管辖（宪法 #9）：

- **包络口径**：一切管道内 bench 运行以 WorkOrder 进单，三账本天然入 Meter 对账；另设「基准包络」配方参数（token / 美元 / GPU 时三上限，按月滚动）。超包络触发投放闸降级：先砍 pass^k 重复次数与全量档，最后才砍 L0 与最小可信组合——**L0 与最小组合是最后被牺牲的**。
- **最小可信组合（供给紧张时先保）**：① L0 全部自建件 + InjecAgent 静态快检（本地近零 API 成本）；② 代码产线最小回归 = SWE-bench Verified 分层抽样子集（建议 100 题档，配方初值可调）× 1 次；③ Terminal-Bench 短任务子集 × 1；④ 全量三账本记账。依据：TB 官方全榜单档 token 画像 6.5B-21.6B（研·端到端）——全榜是重资源档，包络紧张时不跑全榜。
- **全量档分层执行序（由俭到奢）**：L0 常驻 → L1 回归档（Verified 500 × 1；产线套件 × 1）→ pass^k 档（k≥4，仅决策消费对象）→ 计价与时间档（SWE-Lancer / MLE GPU 三档）→ 季度档（OSWorld / GDPval / TheAgentCompany）→ 年度档（EcoGym 或 Vending-Bench 2）。
- **用户一号供给约束**（拍板版 §六第 0 步：两订阅窗口额 + 一家按量 API + 本地 GPU 池）：订阅窗口额优先喂 L0 与最小组合；按量 API 只喂进决策的 pass^k 档；GPU 档（MLE-bench / VBench / EvalCrafter / RE-Bench）排 anolis 2×V100S 空闲窗口（夜间），与 vLLM 门控（波次 5+）协调；GPU 档全量运行前须出单档成本预估（按 §3.4 包络口径折算）。

### 4.2 JIT 初始 trace 语料与配方提案来源

**引用勘误与工序定义**：宪法 #3 原文是「Trace 是正式接口，从第一天版本化（编译器的语料）」（拍板版 §2.2 条 3），并无「唯一」；「它是编译器唯一的语料」出自抽象 5 对工厂自身 Trace 的描述（拍板版 §四.5）。为不构成第二语料通道，规定**外部语料物化工序**：

- **外部语料不直接喂 JIT**。HAL 公开日志（2.5B token / 21,730 rollouts）、How Do AI Agents Spend Your Money 带阶段标注轨迹（500×4×8）、AgentDojo 注入任务的脚本化攻击记录（研·安全：可录成回放语料）、AgentGym AgentTraj-L（HF 可达性需实测——研·冷启动标注直连未验证）——一律先过物化工序：**转换为工厂 Trace 事件格式的工件 → 落独立命名空间 `external-corpus/` → 版本钉两样（源数据集版本 + 转换器版本）→ 由人签收后只读挂载**。JIT 以同一 Trace 接口消费物化结果，同受护栏（优化集/评估集隔离、审计下限）约束；物化工序本身是 L0-10 三态语义一致性测试的对象之一。**未物化的外部数据只允许人工离线参考，不进优化器。**
- **自产语料（唯一长期来源）**：一切 L0/L1/L2 运行的 trace（宪法 #3 + 抽象 5）。拍板版 D5 的 eval 产线「既是工厂自验收又产 JIT 语料」——**bench 运行本身就是第一条产线的在制品**。
- **提案算法选型（2026-10-19 二次核查后修订为三层）**：第 0 层 GEPA 为锚（轨迹反思 + Pareto，rollout 省——79-737 级 vs GRPO 每任务 24,000，「只有 trace 没有金标」场景最对路，研·冷启动；已知三失败模式——prompt 过拟合/prompt 膨胀/schema 腐蚀——转为审计下限检测项）；第 1 层并行 ACE 式增量 playbook（arXiv:2510.04618，唯一与 GEPA 受控对比且大胜的工作：AppWorld +11.9pp、省 75% rollout）+ AWM 归纳层（从自身 trace 自归纳工作流、按需注入、无需金标）/ExpeL 经验卡；第 2 层语料充足后用 AFlow 受限算子空间搜路由/模型选择等结构层配方。**排除**：自由代码自进化一族（DGM/ADAS/PromptBreeder——从无 GEPA 对照实验，且 DGM 有虚报评估、ICLR 2026 有 misevolution 实证，只作离线研究对象）与权重 RL（成本/Echo Trap 失稳/权重 diff 不可审计且违反「永不直接干预执行」）。核查证据：`设计/benchmark调研/实测/self-improvement-vs-gepa.md`、`improvement-strategy-survey.md`（回应运营者质疑「模型自设计改进优于 GEPA」——经核查该说法系两条未交锋文献线的拼接，不成立）。DSPy 仍为 JIT 外壳行业对标物（拍板版 §七）。
- **护栏（宪法内建，L2-9 验证）**：审计下限（优化器碰不到的随机抽检）、优化集与评估集隔离、升迁须联合单调、repair_only_on_error。

### 6.3 测量效度陷阱（写进测试用例评审清单）

1. **授权范围不写进 prompt**（OverEager-Gen：0.0%→17.1% 假阴性陷阱）——副作用网关与工单文案的用例写法约束。
2. **不堆评审团**（Nine Judges：9 评审 ≈ 2 票信息量）——评估器投资方向是单点准确率与任务分层。
3. **外部金标有标签噪声**：EquiBench 18% 标签与执行结果不一致、SWE-bench Verified 28.4% 过测补丁与参考补丁行为分歧——凡引用外部金标必叠执行校验或人工抽检。
4. **单次成本测量不作数**：同任务 token 30 倍方差、模型自预测相关性 0.39——成本与容量结论必须多次采样 + 误差棒。
5. **版本漂移**：τ² <1.0.1 不可比、VBench 外部评估模型版本、EvalCrafter FVD 参考统计、judge prompt/温度——全部进 Trace 关键事件。
6. **饱和与污染**：长期回归集按 TB continuous 模式维护、LiveCodeBench 机制轮换新题、金标答案与优化集物理隔离（§4.3 验收）。
7. **消息语义误判**：任何含 agent 对话的原生 bench（ChatDev / MultiAgentBench 原生形态）在用于协同结论前必须完成工件投递语义改造（自建件 F）。

### 6.4 本计划不做的事

- 不做通用对话 agent 平台评测、不做消费级产品基准（拍板版 §十「明确不做」边界）。
