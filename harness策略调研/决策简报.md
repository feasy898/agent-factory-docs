# 决策简报：harness 改进策略筛选（供人审拍板）

> 来源：`最终报告-harness改进策略总表.md`（180 条，Kimi K3 逐条核验）与 `strategies.csv`。
> 本简报只保留决策所需的一句话证据，完整证据链按 ID 查总表对应小节。

## 一、决策要点

1. **180 条里有约 40 条是"评测方法论"而非被测策略**——它们决定你的测试结论可不可信，应直接采纳为测试基建，不占测试名额。
2. **单项杠杆最大的是结构正确性而非聪明技巧**：S128（模型改文件、runner 从 git 导出 patch，同模型 19.3%→71.2%）。这类"写 diff 会错就别让模型写 diff"的条目直接采纳做基线。
3. **压缩是一族必测但预期分化的变量**：零 LLM 成本手段（清理过期工具结果、外置大输出）证据一致为正；LLM 摘要式压缩正负证据并存（S009：8 种压缩器无一显著提升质量），必须互为对照测。
4. **测试时扩展（并行采样+选优）与你的并行产线天然契合**，是复用现有基建就能吃到的收益（S092 官方 +6.9pp）；但选择器质量是关键变量，需单独测。
5. **多 agent 协同没有全领域优胜框架**（MASLab 横评），值得测的是具体机制（委派、图切分、冲突排程），不是"上不上多 agent"。
6. **负面清单价值很高**：纯语言自评反思、多 agent 辩论等流行做法在对照实验里不成立，默认不做可省大量机时。

## 五、第 3 档：暂缓（条件不成熟或非 harness 本体）

- S167/S168：自托管前缀缓存/缓存亲和路由——仅自托管推理时相关。
- S131：harness 自动演化（AHE）——等首批结论沉淀后再考虑。
- 需训练或数据积累：S008（Context Folding RL）、S013（CodeGrep RL）、S110（STAIR）、S180（历史蒸馏技能）。
- S035/S037：长上下文外部化、LHTB 长时域基准——换基准成本高，随二批再定。
- 技能工程细节（S027/S048/S050/S052）：等 S160 结论决定技能库是否值得投入。

## 六、负面清单：默认不做（对照实验不支持，或证据为负）

| ID | 做法 | 证据 |

## 七、需要你拍板的 4 个问题

1. **首批规模**：17 个实验族全上，还是先挑最快的 8 族（1/2/3/6/10/12/13/16）两周内出结论？
2. **基准组合**：回归集用 SWE-bench Verified 没争议；活水/外推集选哪个（SWE-bench-Live、Terminal-Bench 2.0、或自建私有题库）？
3. **多 agent 轴（第 2 档）**：与首批并行推进，还是等首批出结论再投入？其实现工作量约为首批的 3–5 倍。
4. **成本一票否决**：是否把"同等成本解决率"（S152/S170）设为策略入围的硬约束（即任何策略在等成本对比中不占优即淘汰）？
