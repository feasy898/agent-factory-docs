## 1. 背景与前提

我们运营一个「agent 黑灯工厂」：单体 agent 与多 agent 协同的编码 harness 已优化到位，下一阶段必须依靠真实生产任务持续改进。真实任务天然没有标准正确答案，无法用带 ground-truth 的基准自动判分。因此调研围绕四个问题展开：

1. **观测什么？**——在无标准答案的生产任务上，哪些信号值得采集、以什么粒度和采样率落盘；
2. **如何使用 trace？**——切片、配对、回放、复算的具体方法；
3. **如何形成改进提案？**——从 trace 到可执行改动的角色链、模板与校验；
4. **改进提案经过什么流程应用？**——防改坏、可回滚的门禁与灰度机制。

由于接下来会对多条改进策略做大量并行 A/B 测试，**每条策略的改进价值必须明确且可被证伪**：承诺的效应量、判定规则、证伪条件都要在测试前预登记。

**调研方法**：8 条候选策略（S1–S8），每条给出可证伪的价值主张、观测字段、trace 用法、提案链、应用流程、测试设计与成本估算，并附外部文献链接与本地代码/数据实读证据。两位评委逐条独立复核：外部链接用 curl/WebFetch 验证可达性与内容，本地引用逐行核对代码与数据（python3/sqlite/grep 实跑），并独立复算关键统计数字；每位评委输出得分（0–100）、证据核实结论（confirmed / partly / refuted）、主要缺陷（mainFlaw）与建议（adopt / test-first / deprioritize）。两点口径限制（审读意见补充，如实声明）：①**评分体系不可复算**——评分维度、权重与锚点未随证据 JSON 提供，两评委分数量纲未经校准（Kimi 42–62 vs Step-5 63–74，区间几乎不重叠），得分只应作每位评委内部的序位信号，平均分排名的限定见 §4.1；②**证据 JSON 无工作区存档**——策略与评委结论 JSON 是调研任务的输入材料、随任务下发，本次修订会话在工作区 grep 不到含 kimi/step 键的 JSON 文件，本报告所有分数与评委结论均转引自该 JSON，复核仲裁需回调研流程留存处取。

## 2. 核心认识

四问的答案在各策略间高度收敛，可归纳为以下总体性结论。

### 2.1 观测什么：四层观测 + 行级身份指纹

- **确定性结果行是主数据源**（每 run 一行：suite/task_id/profile/trial/reward/status/turns/tokens/耗时/gate 记账等），但二值 reward 统计功效太低——必须解析判分器输出的**分级连续量**（FAIL_TO_PASS 成功/失败数），实测某 fix1 单臂档案 67 行结果中 55 行可取（时点快照，口径见 §1.1），这是把"通过率"变成可判 5pp 效应的关键。
- **逐轮 transcript + 停止原因**（max_turns / tool_free_limit / budget_exhausted…）+ gate 记账（no_patch / test_edit）是把"失败"变成可归因对象的最小集合。本地已在 145 条有轨迹 run 的一次性分析集上建立了失败分类学（A 停滞 / B1 做对不会停 / B2 / C 环境受阻 / D 跑偏考古，口径见 §1.1），且可用正则预筛（考古模式命中 51/145 run、文档吸附 73/145）。
- **所有行必须携带身份与指纹**：run_id、task_key、profile、scaffold、判分器 eval_sha256、配置指纹（二进制/任务集快照/prompt pack/judge spec 各自 sha256）、cohort/release 标签。**缺任一项 → 不可归因，作废**。S4 与 S6 两条独立策略收敛到同一设计，说明这是结构性需求而非偏好。
- **新增观测落独立 sidecar**（资产账本、评审标注库、指纹字段），不动判分账本本体——本地判分账本是"声明不符即拒绝打开且不迁移"的指纹库，加列属于高风险动作。
- 采样纪律收敛为：确定性判分事实 100%；LLM judge/打标对参与臂 100%；人标按预算集中采样但**每批保留随机保底层**（用于发现当前信号描述不了的新失败模式）。

### 2.2 怎么用 trace：切片、配对、回放、复算

- **切片**：sqlite 只读连接 + JSONL 解析 + 正则预筛；失败分类的分层统计先于任何模型归因。
- **配对**：一切 A/B 以同 task_key 配对为前提。配对 + 每题 k 次重复，把 5pp 效应从"本地不可判定"变成"可判定"（见 §5 复算）。
- **回放**：优先 regrade——**重判分、不重跑 agent**（读落盘 trace 与产物，比重跑便宜 1–2 个数量级）；必须重跑 agent 时，须同题集、温度 0、同 scaffold、同判分二进制、结果目录代际隔离、**同日交错执行**（防 429 风暴等时段性供应商噪声制造伪差异）。
- **复算**：判分争议一律走清洁重判（全新容器 + 官方判分脚本），并以 eval_sha256 逐行对账判分器字节一致；A/B 两组判分二进制 sha256 不同 → 该轮作废。所有上报数字必须带可重跑命令，可被异族代理盲跑复现；模型证词不算证据。
- **反面教训（本地时点读数，非通用效应量）**：判分链缺陷会伪装成策略效应。实证一：fix1 step-5 单档案判分污染复核——78 行配对集干净重判净增 +8 题（+10.3pp，机制是 F→T 翻转与污染判分）；全集 107 行外推区间 +7.5～+11.2pp（含 28 个无 diff 不可判题，点估计 49.5%）。**这是单档案一次性复核读数，不能外推为未来 A/B 的通用修正量**，其正确用途是论证"判分侧缺陷足以淹没策略效应"这一风险。实证二：fix1 全量干净口径重判（1104 行）——共同已判集 1020 行中 F→T 43 行，fix1 D1 各臂干净通过率高于档案读数 +6～+37pp 不等；**fix2 A/B 的原口径 ±13.3pp 被判定为污染假象**（干净口径 glm-cp Δ=+7.1pp、m31f Δ=0.0pp）——判分缺陷不仅制造"不可判定"，还制造过**方向性假结论**。实证三：run 目录同名覆写 + 截断日志曾把真实通过记成失败（第一轮 344 行重判 343 行一致、1 例错判；该口径已被 1104 行全量重判取代）。**判分完整性审计是 trace 使用的第一优先级。**（各档案时点与关系见 §1.1。）

### 2.3 怎么形成提案：结构化、可证伪、防循环

- 共性角色链：**模型读切片产结构化提案（固定模板、缺字段拒收）→ 确定性校验器（G0）→ 人评 → 落为可 diff 的版本化资产**。提案必填 falsifier（什么观测判它无效）与反事实（不采纳会发生什么可观测失败）。
- **最大陷阱是协议重复**：本地最高频的失败模式（git 考古、文档吸附、无网重试下载、收尾缺失）已经写死进实例协议。把同类经验再做成资产/提示注入，只会涨 token 不涨分——S2 的两位评委都把这条列为头号净收益威胁，对策是提案必填 protocol_overlap 字段 + G0 确定性拒收。
- **反自偏好**：反思器、评委、打标模型必须与被测模型异族；同族自评只作对照臂、禁入判分池（自偏好现象有文献依据：[arXiv 2404.13076](https://arxiv.org/abs/2404.13076)，调研材料引用、未单独复核）。
- **评委共同打脸的三种"伪证伪"**（证伪条件设计前必须先问：零假设下它会不会自动成立？）：
  1. 金标来自策略自身产物 → 循环论证（S1 的反事实伪标注）；
  2. 入库筛选导致回归均值 → "未饱和"信号构造性成立（S7 的 H2）；
  3. 判否条件在温度 0 下 16–20% 逐题翻转噪声中必然触发 → "门有必要"单靠噪声即可成立（S3 的 H3）。

### 2.4 怎么应用：可比性 → 门禁 → 灰度 → 回滚

- **先判可比、再判胜负**：配置指纹不一致 → INCOMPARABLE，不出分、不计晋级。本地已有真实先例：带干净判分容器的 fix3 代二进制因污染可比性被明令禁止换入产线。
- 门禁链收敛形态：**确定性自检 → 回归集（含工程六门与判分不变性）→ 灰度阶梯（单条→组→全量，或 1%→5%→25%→100%）→ 联合单调晋级（新版本不劣于上一版且至少一项改善）→ 审计下限（约 10% 抽检由异族模型/人工复判，优化器不可触）**。
- 回滚一律配置级：git revert / 指针切回 / 单条 flag 关断，不重构建；被拒提案与退休资产留档不删（保留审计链）。
- **undecidable 是合法产出**：fix2 A/B 两档案（glm-cp 15 题池、m31f 11 对可配；按变体设计纪律两档案分别出矩阵、不合并）在原判分口径下置信区间宽达 70pp（m31f：Δ=+18.2pp，95% CI≈[−17.5,+53.8]，p=0.625）——任何合格评委都判不出结论；且后续全量干净重判证明该读数本身还是污染假象（干净口径 m31f Δ=0.0pp）。小样本与判分缺陷叠加时，把"不可判定"硬写成胜负会系统性制造假结论，把"不可判定"当"改进不成立"会扼杀慢见效的真实改进。正确动作：记 undecidable、按预登记功效扩样本、判分链先过逐字节重判。
- **一句话总纲**：改进价值链是「判分可信 → 比较可比 → 效应可判（功效）→ 归因可查（trace）→ 提案可证伪 → 应用可回滚」，六环任一断裂，上游全部作废。本地现状在第一、二环有已证实的伤口，所以**地基件优先于任何策略**。

### 3.1 S2 轨迹经验沉淀为可计数资产（平均 66.0，排名第 1）

**定位**：把生产 trace 蒸馏为带 helpful/harmful 与 hit/success 计数的 playbook/skill 资产注入同分布任务，使经验可计数归因、可单独启停、可按计数淘汰。

- **观测什么**：复用既有结果行与判分器内嵌的 f2p 分级字段；新增独立资产账本（asset / asset_usage / asset_eval 三表，append-only），不改动 harness 指纹库 schema；结果行加 assets 块（playbook 版本、注入位置、命中与注入 token）；资产生命周期事件走 trace normal lane。注入点放在每题重发的 instance 模板（抗长对话遗忘），不放一次性 system。
- **trace 用法**：python3 sqlite 只读切片 + 逐轮 transcript 按 A/B1/B2/C/D 分类切"最后一次编辑轮/测试轮/空轮"；正则筛 D 类考古候选；回放=同题集重跑且结果目录独立；任何 A/B 结论必须过清洁重判并逐行对账 eval_sha256；无 GT 的生产任务线用 Agent Workflow Memory 式 LLM judge（[arXiv 2409.07429](https://arxiv.org/abs/2409.07429)）。
- **提案形成**：Reflector→Curator→确定性合并器→人评。**硬约束（本地实读确认）**：ACE 参考实现只实现了 ADD 操作，UPDATE/MERGE/DELETE 是未完成的 TODO——因此删除语义由 `state='retired'` 承担、改写由"新 asset_id + version+1"承担，禁止依赖未实现的 op。归因用两级：词面匹配 + 模型自报编号（model_cited），**晋级只认 model_cited，淘汰用合并口径且需 ≥3 次命中**。提案模板固定字段含 protocol_overlap 与 falsifier，缺字段拒收。
- **应用流程**：G0 确定性自检（协议重复/私有信息/token 预算/优化集-评估集哈希零交集）→ G1 人评 → G2 回归集（30 题子集 + 工程六门 + 判分链字节不变）→ G3 灰度（单条→组≤8→全量，每条资产一个 flag）→ G4 联合单调 → G5 git 版本回滚 → G6 审计下限 10% → G7 记账。产物形态对齐 [Anthropic Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)（技能=文件夹，可独立启停与版本回滚）。
- **承诺价值**（未经验证，需测试确认）：注入组相对不注入组通过率提升 ≥5pp 且 token 增幅 ≤15%；低效条目（hit≥3 且 success/hit<0.5，规则取自 [MemP](https://arxiv.org/abs/2508.06433)）淘汰后质量不回退且 token 降 ≥5%。
- **证据**：[ACE（arXiv 2510.04618）](https://arxiv.org/abs/2510.04618)与 [GitHub 仓库](https://github.com/ace-agent/ace)（两评委均核实：AppWorld +10.6%、相对 GEPA 省 75.1% rollouts；本地克隆逐行核实 ADD-only 与计数格式。**口径更正**：某内部计划文档转述的"+11.9pp"无原文依据，以 +10.6% 为准）；[MemP（arXiv 2508.06433）](https://arxiv.org/abs/2508.06433)（核实；hit/success 淘汰规则只在代码中，摘要未载）；[Anthropic Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)（核实）；[Agent Workflow Memory（arXiv 2409.07429）](https://arxiv.org/abs/2409.07429)（核实）。
- **双评委结论**：
  - **Kimi 评委：62 分，partly**。本地引用全部对上；但外部证据全部来自 AppWorld/金融/ALFWorld 等场景，**没有一条证明 playbook 注入在 SWE-V 代码修复 + 已叠加强实例协议的场景下有净增益**；功效数字用近似式复算量级一致但数值不完全可复现（原值偏保守）。
  - **Step-5 评委：70 分，confirmed**。全部本地证据复现（含独立复算功效/MDE 逐项吻合）；工程可实施性高；扣分在价值可信度与测试设计缺陷。
  - **主要质疑（两位共识，如实呈现）**：①「每条资产边际价值可单独归因」**默认配置下不可证伪**——lexical 归因会把"提到但没用"计为命中，单条灰度（1 条×120 题×k=1）的 MDE 约 11–13pp，单条经验不可能有这么大效应，价值主张实际退化为**组级 A/B**；②实例协议已写死最高频失败模式，**净收益空间可能接近零**；③token 门限 ≤15% 的分母未定义；④"淘汰不回退"是等价性检验，n≤250 时无统计功效，实际判不了。
- **最终建议：test-first**。测试顺序：先只比两组（不注入 vs 注入），用 f2p 连续指标 + 每题 k≥3，**组级净增益成立之前不宣称逐条归因**；C 臂（计数淘汰）延后。最小达标配置已修订：原「n=120×k=5 即达标」与其 5pp 判定规则自相矛盾（该配置 MDE 5.7pp>5pp，n=250×k=3 的 5.1pp 同样不达标），三选一方案见 §5.2。

### 3.2 S3 轨迹反思驱动的自动优化与改进门（平均 63.5，排名第 2）

**定位**：用 GEPA 式反思驱动自动生成提示词/流程变体，候选只有通过逐样本 Pareto 前沿 + 确定性严格改进门才入池，被拒提案同样落盘可审计。

- **观测什么**：三层——优化器层（逐迭代 meta.json/逐样本分数表/组件全文快照/前后评估轨迹，目录一旦写入不可变，接受与被拒提案都落盘）、rollout 层（复用现有结果行 + transcript，每行钉死判分版本与镜像 digest）、验收层（留出集 100–300 题按 repo 切分、永不进反思；逐题配对差分矩阵）。
- **trace 用法**：sqlite 只读取 transcript，与结果行 join；反思数据选择器 = reward=false ∧ 停止原因 ∈ {max_turns, tool_free_limit, no_patch}（对应 B1/B2/C/D 类；A 类仅 1/60 不值得喂）；反思数据按 GEPA adapter schema 组装，单条反馈封顶约 4KB；**候选在同一样本集上重执行而非在日志上重放**；温度 0 + 种子化 RNG。
- **提案形成**：前沿档模型做反思 teacher，只在组件级文本上产出全文替换；提案必填 expected_failure_class（针对哪类失败）；每迭代 1 个反思提案 + 每 3 轮一次 merge 尝试。**实施第一步是把协议文本外置为版本化文本资产**，否则"数据化更新+指针回滚"无从谈起。
- **应用流程**：五级门——门1 确定性严格门（子样本总分严格大于才接受）→ 门2 留出验收（配对 McNemar p<0.05，前沿分数只做入围）→ 门3 回归集（含 Terminal-Bench 线不回退）→ 门4 canary 灰度（通过率 < 现任−5pp 或单任务成本 +30% 自动切回）→ 门5 manifest 指针回滚（零代码改动）。**全局硬护栏：判分器/镜像/数据集版本冻结并哈希入账**（本地判分污染史证明这是硬前提）。
- **承诺价值**（未经验证）：(1) 无门覆盖式更新（TextGrad 式直接覆写）产生逐样本退化而加门版不产生；(2) 加门版留出集通过率显著高于人工维护基线。**启动硬前提：存在可靠标量分数**——SWE-V 线满足，纯 LLM-rubric 产线不启动。
- **证据**：[GEPA（arXiv 2507.19457）](https://arxiv.org/abs/2507.19457)与 [GitHub](https://github.com/gepa-ai/gepa)（两评委核实：较 GRPO 平均 +6%/最高 +20%、rollout 少至 1/35；本地代码逐行命中，含一处诚实的自我纠错）；[TextGrad](https://github.com/zou-group/textgrad)（反面对照：无门覆写）；[DSPy MIPROv2](https://github.com/stanfordnlp/dspy)（单标量 metric 门槛 → 支撑"无标量分数不启动"）；[Anthropic：Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)；[MAST（arXiv 2503.13657）](https://arxiv.org/abs/2503.13657)（"可分类"≠"归因正确可驱动改进"，闭环改进是 future work）。同构旁证：GEPA 官方 gskill（仓库内 docs/guides/gskill，Mini-SWE-Agent 在 Jinja 55%→82%、Bleve 24%→93%）。
- **双评委结论**：
  - **Kimi 评委：58 分，confirmed**。机制成熟可直接复用、可实施性高；但 **H3（门有必要）在 16–20% 逐题翻转噪声下单靠重跑就会触发（100 题约 8–10 个逐题退化），无零假设对照臂则无论门有没有用都会"成立"**；"确定性严格门"名不副实（30–50 题二值子样本的 Σ 比较由抽签决定大半）；成本 $1K–3K 疑似只算了单臂。
  - **Step-5 评委：69 分，confirmed**。主终点决策规则未钉死且两个选项都不成立：门槛抬到 10pp 会把 GEPA 自报量级中真实 6pp 效应判成未改进（假阴性）；扩留出集到 250–300 题则**超出本地 120 题题库库存 1–2.5 倍**且成本未按达标配置诚实定价。另：repo 分层切分与"禁止同 repo 跨集"存在内部矛盾。
- **最终建议：test-first**。修正后测法：增加 A-vs-A 零假设对照臂；"真实退化"用 k≥3 多数票定义；主终点预登记 pass^3 重复（而非扩留出集），5pp 判不了就把门槛诚实抬到 ≥10pp 并写明假阴性风险；接受率 <10% 时走显式新臂，不静默放宽。

### 3.3 S4 无标准答案的评审门禁与评委校准（平均 63.0，排名第 3）

**定位**：给 judge 设四道资格门（零假设门/人标门/稳定门/决策效用门），不过门的 judge 不得参与 A/B 判分；**undecidable 是合法结论**，不得硬挑赢家。

- **观测什么**：五层标注——判分事实层（CODE，100%）；评委判定层（按 OpenInference annotations 规范落 annotation：score/label 含 unknown 出口/说明/annotator_kind/judge spec sha256 标识）；pairwise 配对层（order_shown 随机、swap_flip_rate、长度残差）；人标层（校准集 100% + 生产 5% 审计 + 低分分歧 100%）；派生指标层（accuracy、MCC、Krippendorff α、人-人一致率上限、CI 宽度、undecidable 标志、**判分链完整性**：log_parsed 失败率、eval_sha256 缺失率、run 目录覆写事件数）。
- **trace 用法**：切片用 sqlite 直读 + jq 读双轨日志 + sha256sum 对账；配对按 (task_id, profile, scaffold) 连接两臂，抽样与 seed 写进 pairing.json 保证可复算；**回放=regrade 不重跑 agent**（复用现有清洁重判工具的 staging/幂等/内存闸/manifest 范式）；判分链完整性抽 30 条已判 run 在干净容器重判，要求 resolved 字段逐字节一致；同题两臂判值不同时用 diff 指纹 + 判分日志指纹区分"判分链缺陷 vs 能力差异"。
- **提案形成**：Principal Domain Expert 写 rubric 与终审；影子模型做 critique shadowing；≥2 个异族分析模型读切片产提案；judge spec YAML（文件级 sha256 即回滚指针）+ PROPOSAL.md 固定字段（OBSERVED_SYMPTOM 须附 ≥3 个可复现证据与复算命令、FALSIFIER 必填）。**反泄漏纪律**：被测模型不得参与任何入池 judge 的 spec；提案生成者不得看到在位 judge 的历史结论标签。
- **应用流程**：G0 规格门 → G1 零假设门（克隆对非平局率=0）→ G2 人标门（accuracy 95% Wilson 下界 ≥0.75 且 MCC 下界 ≥0.40）→ G3 稳定门（顺序交换翻转率 ≤10%、长度控制残差 ≤2pp）→ G4 决策效用门（历史 A/B 重放出判否/判真结论）→ G5 回归门（逐字节重放）→ G6 canary（5% 影子判分两周一致率 ≥95% 才升位）→ G7 口径变更管理（judge/rubric 版本变更=强制对历史比较 regrade，禁止新旧混算，结论翻转须发更正）。
- **承诺价值**（未经验证）：三条可计算判否规则 + 一条正向证据条件（门禁曾把至少 1 个历史比较判为 undecidable 或翻转结论）。**本地锚点（修订版：须带档案、时点与判分口径限定）**：fix2 A/B 按变体设计 §4.3 纪律**两档案分别出矩阵、不做合并**——m31f 档案 15 题池中 11 对可配，原判分口径 Δ=+18.2pp、95% CI=[−17.5pp, +53.8pp]、McNemar 精确 p=0.625（调研会话读 /tmp 运行档案；工作区无副本，变更日志 2026-10-21 07:28 条目显示当时 fix2_result 仍为占位）——原口径下这类比较不可判定。**后续进展（2026-10-21 21:1x 全量干净口径重判）**：原口径 glm-cp −13.3pp / m31f ±13.3pp 双双被判定为污染假象，干净口径 glm-cp Δ=+7.1pp、m31f Δ=0.0pp——fix2 无跨档案一致增益。这把 S4 的价值从"避免硬挑赢家"升级为"判分污染会制造方向性假结论"；同时意味着本文初版把 11 对单档案读数写成不带档案限定的"fix1→fix2 的配对 A/B"属转述失真，已更正。
- **证据**：[OpenInference annotations 规范](https://github.com/Arize-ai/openinference)（两评委核实；注意策略原文给的是 [Phoenix](https://github.com/Arize-ai/phoenix) 仓库 URL，规范实际在 openinference 仓库——Kimi 指出的更正）；[Anthropic：Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)（grader 三分型、Unknown 出口、pass@k/pass^k）；[MT-Bench（arXiv 2306.05685）](https://arxiv.org/abs/2306.05685)（顺序交换去位置偏差）；[PPE（arXiv 2410.14872）](https://arxiv.org/abs/2410.14872)（论文属实，但 **Step-5 标注：摘要未载 accuracy/MCC 达标准入规则，该归属 unverified**）；[Dark Current（arXiv 2606.15610）](https://arxiv.org/abs/2606.15610)（克隆偏好 0/102 但效用下界未达 0.75——**Kimi 指出策略漏引同一摘要中"后续评估出现 2/102、低零值未获认证"的反证**）；[Nine Judges（arXiv 2605.29800）](https://arxiv.org/abs/2605.29800)（9 评委≈2 票信息量；**Kimi 只核实到标题，8–22pp 等数字按 Step-5 的逐字核实记录采信**）；[Evaluator Stress Test（arXiv 2507.05619）](https://arxiv.org/abs/2507.05619)；[Inspect AI](https://github.com/UKGovernmentBEIS/inspect_ai)。
- **双评委结论**：
  - **Kimi 评委：52 分，partly**。G4 核心证伪规则设计有误：胜率 CI 宽度主要由 n 决定，"不合格 judge CI < 合格 judge 2 倍"会对任何评委机械判否；"正向证据=判出 1 个 undecidable"在本地 n≈11–15 的历史比较上**靠样本量就能自动满足**——测试稳过、测不出门槛效力；G1 严格=0 阈值对抽样噪声脆弱（所引论文自己的后续数据即为反证）；**SWE-V 线本有确定性金标，四道 LLM 评委门眼下基本悬空**。
  - **Step-5 评委：74 分，confirmed**（本次调研最高单评委分）。证据逐条复算、本地 grounding 最强；但 **G4 在本地语料上不可执行**：全仓仅 2 个正式配对 A/B，重放总体需要新造；accuracy≥0.75/MCC≥0.40 门槛系外部引入未本地标定（按其自己的 Wilson 计算，校准集 300–500 条仅在 judge 真实准确率 ≥约 0.82 时才可能过门）。
  - **两位共识**：近期价值集中在两件便宜的事——undecidable 合法出口（预登记功效与 MDE）+ 判分链逐字节重判；四道 LLM 评委门等生产线真正引入 LLM judge 时再启用。
- **最终建议：test-first**（收敛到子集先行）。决策效用门的验证改在合成已知效应（注入已知 Δ 的对照）上测检出率与误判率（Kimi），或用 fix1/fix2 历史行回溯构造预登记配对扩充重放总体（Step-5）。

### 3.4 S6 生产灰度与冠军-挑战者门禁（平均 60.0，并列排名第 4）

**定位**：挑战者只有"预注册指标全过 + 配置指纹在受影响分量上逐项一致（否则 INCOMPARABLE）+ 统计功效达标"三条件同时满足才晋级冠军，越界自动回滚。

- **观测什么**：行级新增 release_id / cohort / ramp_stage / config_fingerprint（6 分量 sha256：二进制、任务集快照、prompt pack、skill pack、judge spec、harness spec）/ affected_metrics 映射 / error_class（对齐既有四失败码，infra/timeout 单列不计分母）；复用现有按臂越界告警阈值（run_failed >10%、零补丁/拦截 >30%、有判零通过、运行停滞 1800s）；每臂每周 30 行分层人工复核。
- **trace 用法**：**trace 与结果行必须带 release_id+cohort+指纹，缺任一该行不可归因、作废**（本地先例：热插拔变体存在 30s 抢跑窗口、代际混合只能靠行级标签剔除）；用 Merkle 根把每批 release 的判定行集合钉进发布记录（第三方可重算）；回放三式（判分链回放/指纹回放/阶梯回放）；**禁止 before/after 时间切分**（时段性事件会污染任一时间片），改同窗口并行。
- **提案形成**：变更单复用既有工单形态（ed25519 签名、后继工单 supersede 链）；预注册指标/方向/阈值/MDE/最小样本/观察窗全部进入签名载荷，事后追加指标必须开新单重走阶梯；**证据卡 ≥3 张**（task_id + 指纹分量 + 关键 span + 复算命令），缺卡驳回；判据外部注入、零内置魔数。
- **应用流程**：受理 → 指纹固化与可比性判定（受影响分量不一致直接 INCOMPARABLE，回同指纹重做对照）→ 数据面隔离（独立结果目录/二进制/调度四路径）→ 阶梯放量 1→5→25→100%（每阶按预注册 MDE 决定停留期）→ 越界自动暂停（fail-closed）→ 晋级（旧冠军标签不删可回切）→ 每周复核；**同一时刻只允许一个 challenger 在阶梯上**；回滚=切指派版本标签 + 原子换名 + sha 校验 + 回滚后 30 分钟指纹对账告警。
- **承诺价值**（未经验证）：四条可计数判否规则——H1 劣化臂漏放率 ≤5%；H2 不可比臂被判"提升"次数=0；H3 无关差异臂不得被判 INCOMPARABLE（防过度保守）；H4 总体假阳性率 ≤2%。
- **证据**：[Google SRE Workbook：Canarying Releases](https://sre.google/workbook/canarying-releases/)（两评委核实：canary/control 双群组、指标须可归因、禁 before/after、同时只跑一个 canary、逐级晋级；Step-5 注"配置与二进制分离打包"属轻度转述）；[SRE Book：Monitoring Distributed Systems](https://sre.google/sre-book/monitoring-distributed-systems/)；[LangSmith Observability](https://docs.langchain.com/langsmith/observability-concepts)（**Step-5：所引页面未载 prompt 版本化机制，unverified**）；[Braintrust SDK](https://github.com/braintrustdata/braintrust-sdk-python)；[τ²-bench](https://github.com/sierra-research/tau2-bench)（**评委分歧如实记录**：Kimi 在其 glossary.md 逐字核实了 SHA-256 指纹与 error_trials 机制；Step-5 在策略所引页面未找到、标 unverified）；[Kayenta](https://github.com/spinnaker/kayenta)（**Step-5 注：仓库已 archive**；其 critical/non-critical 阈值分级与"baseline 缺失判不可比"语义仍可借用）；[Flagger](https://github.com/fluxcd/flagger)。
- **双评委结论**：
  - **Kimi 评委：50 分，confirmed**。**本厂没有生产流量，只有 bench 臂**（看板累计 737 行、各臂 4–64 行——**时点读数**：调研会话 737、评审会话 741、修订会话 742，见 §1.1）；每臂 2000 行只能靠同批题重复约 17 次凑数，行不独立，功效被高估；按实测单 run 墙钟与总并发估算 4 臂 ×2000 行 ×14 天约需 **90 天**墙钟而非"周级"；H2/H3 由构造保证成立（指纹哈希比较、人工写的 affected_metrics 映射），H1 漏放率不是行级量，H4 需几百次独立比较——**门禁判别力在这套设计下无法被证伪**；建议改离线 bootstrap 模拟验证 + 按题聚类配对设计。
  - **Step-5 评委：70 分，confirmed**。证据与本地 grounding 五条中最扎实，设计有最好的双向证伪结构；但 **cost 段有 14 倍乘法错误**（"4 臂×2000×14 天≈11.2 万 run"把观察窗又乘了一遍，正确约 8000 run）；5% canary 凑满 2000 行需 400+ 天，与本地产量差 1–2 个数量级；6 臂并行违背其自设"单 canary"纪律；在生产流量故意投放已知劣化臂的审批与影响半径未论证。**墙钟"矛盾"已由本次修订用算式裁决：以单 run 墙钟 ~1200 s、满负荷并发 17 计，Kimi 的 90 天恰为按策略原错误数 112,000 run 推算的值（实算 91.5 天），Step-5 的 6.5 天恰为更正后 8,000 run 的值（实算 6.5 天）——分歧完全由 run 总数口径（策略的 14× 乘法错误）解释，与并发假设无关；本文初版"分歧源于并发假设不同"的猜测无据，已更正。算式与输入见 §5.3。**
  - **两位共识**：指纹 / INCOMPARABLE / error_trials 分母纪律**价值高、实现便宜、本地已有 fix3 禁入先例，可先落地**；冠军-挑战者全套验证在本厂流量下跑不起来，改离线模拟 + 历史行回溯验证。
- **最终建议：test-first**（纪律子集立即落地；完整门禁的验证改离线 bootstrap：在已有历史结果上注入 ±Δ 偏移重采样，估漏放率/假阳性/过度保守率）。

### 3.5 S7 真实流量滚动回归任务集（平均 60.0，并列排名第 4）

**定位**：从生产 trace 持续滚动生成回归任务（oracle/nop/cheat 三门禁入库），manifest 版本化 + regrade，为"改进是否可复现、是否饱和"提供滚动标尺。

- **观测什么**：任务实体（全量 sha256 指纹 manifest、FAIL_TO_PASS/PASS_TO_PASS 契约、难度按 solver 反向定义、provenance 回链、guards_against 必填）；三门禁记录（参考解满分/空操作零分/对抗 reward-hack 探针 + LLM 读轨迹判作弊）；饱和与污染哨兵（新-旧通过率矩阵、canary 字符串命中、10% 私有 holdout 永不进迭代循环、regrade 记录）。
- **trace 用法**：DuckDB 按分数分位/离群度分层抽样（低分 40%/异常高分 10%/离群 20%/随机保底 30%——**异常高分专门抓 reward-hack 与判分漏洞**）；task_key 回链来源 trace；verifier 容器化后跑三道门禁；判分器变更时对已录 trial 用新 verifier 重打分、不重跑 agent（Harbor regrade 语义），按 Major/Minor/Patch 声明哪些历史分数失效（注：该版本分类为自建设计，文献未核实到）。
- **提案形成**：生成模型与复核模型异源；每条任务必写 guards_against（防住哪类历史缺陷），无对应缺陷类不入集；人只做种子任务与每批 10–20 条抽检。
- **应用流程**：三门禁全过 + 人工抽检 → 入库并 bump taskset 版本；坏任务 retire 不删证据；周节奏换血 10–20%；饱和警报（新-旧差 <5pp 连续两周）触发集中换血；多策略并行时按 (strategy_id × taskset_version × bucket) 分离统计。
- **承诺价值**（未经验证）：4 周窗口内对**同期新上报**人工缺陷取得 ≥80% 稳定复现覆盖率（3 次重跑 ≥2 次复现），且未饱和（新任务通过率比旧任务低 ≥10pp）；两条同时不达标即证伪。
- **证据**：[SWE-smith](https://github.com/SWE-bench/SWE-smith)（核实；Step-5 注：策略引用的常量行号属实但与判分契约主张关系较弱）；[Terminal-Bench](https://www.tbench.ai) 与其[任务审查自动化文档](https://github.com/harbor-framework/terminal-bench/blob/main/docs/TASK_REVIEW_AUTOMATION.md)（461 行逐字核实三门禁与 /regrade）；[Harbor regrade](https://docs.harborframework.com/jobs/regrade)（"重打分不重跑 agent"原文核实）；[Arena-Hard/BenchBuilder（arXiv 2406.11939）](https://arxiv.org/abs/2406.11939)；[SWE-rebench（arXiv 2505.20411）](https://arxiv.org/abs/2505.20411)与 [swe-rebench.com](https://swe-rebench.com)（NeurIPS 2025，21k+ 持续去污染任务）；[SWE-bench 假阳性研究（arXiv 2503.15223）](https://arxiv.org/abs/2503.15223)（约 7.8% patch 假阳性，核实）；OpenAI 退役 SWE-bench Verified 一事**仅有二手报道，一手页不可读，[swebench.com/verified.html](https://www.swebench.com/verified.html) 经 grep 核实无任何退役/污染内容**——百分比仅作方向性警示，不作定量依据（策略自己已诚实标注）。
- **双评委结论**：
  - **Kimi 评委：48 分，confirmed**。**H1 的输入在本厂不存在**：没有缺陷上报流与生产流量，覆盖率主指标测不了、只能无限"延长窗口"；H2（未饱和）由构造保证成立——入库时按"5 次通过率∈(0,50%)"筛选，天然选中 solver 运气不好的题，复测必回归均值；覆盖率口径不清（category 匹配 ≠ 复现；缺陷与任务共享同窗口 trace 有泄漏）。
  - **Step-5 评委：72 分，confirmed**。覆盖率 80%±8pp 需 4 周约 96 条人工上报（≈24 条/周），是**未验证的运营假设**；"不足则延长窗口"一开，4 周时间盒失效，承诺无法被计划证伪只能被无限推迟；H2 可被"挖掘越来越偏门的失败模式"博弈；覆盖率与上报共享 trace 来源存在循环。
- **最终建议：test-first，但排后（前提未备）**。先决条件二选一：建立 ≥24 条/周的缺陷上报流；或改接 [SWE-rebench](https://swe-rebench.com) 已工程化流水线。未饱和判定改用留出复测（新题入库后用全新 k 次尝试重估通过率再与旧题比），消除回归均值偏差。

### 3.6 S8 运行时 critic 与关键步重试（平均 57.5，排名第 6）

**定位**：运行时 critic 定位关键错误步，从该状态局部重试（预算封顶），对照解耦式"反思后整轮重来"，挽回更多成功且单位 token 更省。

- **观测什么**：结果行新增 first_pass_reward / final_reward 两列（**首次与最终通过率分列是预注册义务**——工厂曾专门关闭 gate 反馈重试以消除免费修复轮虚高，S8 不得把虚高偷运回来）；critic 事件词表（定位/分叉/结局/退路整轮重来/成功任务零触发计数）；**每轮工作区状态指纹**（git diff 哈希 + HEAD + untracked 清单）——本地 sandbox 无快照能力（grep 实证零命中），指纹+命令重放是唯一可行路线。
- **trace 用法**：逐轮抽 Transition Unit 组关键转移图；失败集按本地分类学过滤（C 类环境受阻排除出重试臂，主战场是 B1 收尾失败与 D 跑偏，各约 32%）；定位器输出 top-k + 置信度（**step 级精确归因文献最优仅约 14.2%**——[Who&When](https://arxiv.org/abs/2505.00212)；[AgentDebugX](https://arxiv.org/abs/2607.18754) 自报 28.8%）；前缀命令重放 + 逐轮指纹保真校验，不匹配走整轮重来退路并单独计量。
- **提案形成**：critic 产三段式干预卡片（根因定位含可核查的原文引用 / 最小干预动作 / 可判定的恢复谓词）；**卡片只有确定性部分被执行层消费**，反思文本仅供审计与对照臂——防止"闭环优势"实为提示工程差异；人工周节奏 approve/reject，卡片固化为版本化规则集。
- **应用流程**：门1 离线重放验证（保真率 ≥90% 才放行）→ 门2 canary 双绊线（最终通过率下降或首过率降 >3pp 自动关断）→ 门3 两层护栏（单动作内确定性 deny 复用现有 gate 检测器；关系型约束跨执行比对——依据 [Local Allow, Global Deny（arXiv 2610.27620）](https://arxiv.org/abs/2610.27620)的 2-safety 不可能性结论，per-action 监控数学上检不出关系型违规）→ 门4 配置开关回滚（critic.enabled=false，零代码路径改动）。
- **承诺价值**（未经验证）：固定预算（每任务 ≤2 次额外重跑、额外 token ≤30%）下，闭环式挽回成功数 ≥ 解耦式 2 倍且单位 token 挽回更高；三条预注册排除条件（首过率并列报告 / 退路分支单独计量 / 对照臂获同量级定位信息）。
- **证据**：[AgentDebugX（arXiv 2607.18754）](https://arxiv.org/abs/2607.18754)（13/73 vs 解耦基线 4–6/73、55.8%→63.6%，核实）；[AgentTether（arXiv 2607.06273）](https://arxiv.org/abs/2607.06273)（核实）；[PivoARL（arXiv 2607.03702）](https://arxiv.org/abs/2607.03702)（核实；**"交互轮次降 42%"在摘要未命中，Kimi 标 unverified**）；[Reflexion（arXiv 2303.11366）](https://arxiv.org/abs/2303.11366)（解耦式对照臂思想源头）；[Local Allow, Global Deny（arXiv 2610.27620）](https://arxiv.org/abs/2610.27620)（逐字核实）。
- **双评委结论**：
  - **Kimi 评委：45 分，confirmed**。**判分 oracle 泄漏是致命伤**：critic 在 reward=false 时触发、且被设计为读取 f2p/p2p 失败 diff——等于把 SWE-V 隐藏测试结论喂给重试环，量出的"挽回数"主要是 oracle 反馈的作用；生产上这两个信号都不存在，价值搬不过去。"≥2 倍"目标引自基线未获定位信息的非对等比较，而 S8 自己要求对照臂获同量级信息——比较对象已变，2 倍无先验依据。样本量设计自相矛盾（traceUse 说四臂配对、testDesign 却按独立四臂算功效）。
  - **Step-5 评委：70 分，confirmed**。三条预注册排除条件是全部策略中最好的反虚高设计；但 ≥2 倍阈值与自设公平性控制互相矛盾（"相同诊断下局部重试 vs 整轮重来"的预期比值在所有引用文献中无测量、大概率显著小于 2，**阈值拍错会把有效机制判死**）；确认性检验需约 258 条/臂（n=75 时功效仅 0.32），本地失败流约 60 条/批且要与其他策略争抢；**"judge_mode 配置先例"经查本地 harness 全部源码零命中——refuted，如实记录**。
- **最终建议：test-first（修正后测）**。修正三件：①触发与反馈改用部署时可得信号（agent 自写的复现脚本、已有测试结果、gate 记账、停止原因），隐藏判分只用于最终计分；②先离线用现有 145 条已分类 run 量定位 top-k 命中率，达标再投前缀重放器工程（成本最大件）；③主判定降为方向性 + 95% CI 或序贯累积，放弃 2 倍硬阈值；④对照臂优先考虑直接接入 [AgentDebugX 开源工具包](https://arxiv.org/abs/2607.18754)而非自建。

### 3.7 S5 隐式反馈驱动的主动学习评审（平均 56.5，排名第 7；两位评委建议分歧）

**定位**：把用户中断/拒绝/永久放行等隐式行为落成闭集标签，用主动学习把有限人审预算集中到高信息量样本。

- **观测什么**：Claude Code OTel 事件的字段级依据（tool_decision / tool_result / feedback_survey，闭集枚举、版本门槛、属性超限静默丢字段等坑全部核实）；本地 harness 的等价词表（gate 记账 / 停止原因 / 四失败码 / 人工接管 / 修订 diff）；独立标签库（三档 outcome + 失败模式多标签 + 双标留痕）；**每批 20% 随机保底层**。
- **trace 用法**：tool_use_id / prompt.id / session.id 三级 join 还原"护栏在哪拦、用户在哪改主意"；按 source 分层取样（user_reject / user_abort 为负样本候选、user_permanent 为强正、config 层只作对照）；离群切片（分位数、命令序列 n-gram 聚类、重试计数）；回放只做两件事——离线 judge 一致性、选样策略在已标注池上的重采样模拟。
- **提案形成**：聚类→候选评审清单（附选样理由）→**双人盲标（评审员不可见隐式标签与臂身份）**→失败分类学版本化（模式可合并拆分但保留 lineage）→提案模板（期望行为必须落到二值判据或确定性 guardrail，falsifier 必填）。
- **应用流程**：schema 自检 → 标签集三态冻结（draft→frozen→retired）→ 发布门（AUC 95% CI 下界达标才发布，不达标缩范围）→ 评审门（含与实例协议的重复检查）→ 回归 → 灰度（单条 guardrail 10%→25%→100%，误拦率与完成率双达标才升阶）→ 漂移监控自动降级 → 回滚 → 审计（保底层由未参与选样的评审员审，独立上报新模式发现数）。
- **承诺价值**（未经验证）：同覆盖度下人审样本量降 ≥50%（重采样模拟 R≤0.5 且 CI 上界 <0.5）；隐式标签对人工 outcome 的 AUC ≥0.7（95% CI 下界，盲标）；**硬前提：合格总体与信号密度**（eligible <10% 或负信号 <1% 直接判否）。
- **证据**：[Claude Code 监控文档](https://code.claude.com/docs/en/monitoring-usage.md)（两评委逐行核实，含对原稿的三处字段级纠错）；[Claude Code hooks](https://code.claude.com/docs/en/hooks.md)（核实）；[Hamel Husain & Shreya Shankar：AI Evals FAQ](https://hamel.dev/blog/posts/evals-faq/how-can-i-efficiently-sample-production-traces-for-review.html)（核实；**策略所引"每周 10–20 条"等三组量化数字在原文 0 命中——只能采信定性结论，量化门槛以自算为准**）；[RELIEF（arXiv 2610.26636）](https://arxiv.org/abs/2610.26636)（核实：反馈有效性随底座模型能力而变 → A/B 须按底座分层）。
- **双评委结论**：
  - **Kimi 评委：42 分，confirmed，建议 deprioritize**。**前提在本厂产线不成立**：本地 harness 单工具 bash、无权限提示交互，tool_decision / user_reject / user_abort 信号根本不存在；本地"等价词表"全是系统确定性结局，拿结局预测结局接近同义反复（是否存在跑 Claude Code 的生产线：材料未给出，unverified）；覆盖率主判定有偏（金标分母混入定向臂发现，R 天然偏向定向）；门槛被悄悄放宽（valueClaim 写 CI 下界 ≥0.7，判定却改成点估计 ≥0.70 且下界 ≥0.65）。
  - **Step-5 评委：71 分，confirmed，建议 test-first**。证据纪律为五条中最好、字段级纠错全部正确、统计可复现；但同样确认**本地信号链基本为空**，自设的 P0 门（eligible<10% 判否）很可能直接触发；更优路径是先把本地 stop policy/gate 记账升级为 tool_decision 式事件（decision/source 闭集 + 版本标记），先补信号源再上主动学习。
  - **两位无分歧的事实**：方法论本身（随机保底 + 盲标 + 覆盖率为王 + 三条硬判否）是好的，问题只在信号源不存在。
- **最终建议：deprioritize**（取两评委中更保守者；分歧如实记录：Kimi=deprioritize / Step-5=test-first）。保留两件事：成本极低的 P0 信号密度前置统计（按策略自己的规则判），与"随机保底 + 盲标"方法论（任何策略的人审环节都用得上）。

### 3.8 S1 反事实回放伪标注的失败归因（平均 54.0，排名第 8）

**定位**：用程序化故障注入 + 决策回滚 + 重放构造可判定的伪标注，把"这次为什么失败"变成可打分的 (agent, step) 二元组。

- **观测什么**：四层——轨迹事件层（Who&When 式二元组契约）、注入与重放层（7 种故障类型、重放结局 3 次一致性、阳/阴对照校准）、工具级错误聚合、跨 provider 稳定任务键；失败 trace 100% 入归因队列，成功 trace 10% 留对照（防把成功误判出失败）。
- **trace 用法**：DuckDB 单文件索引 + span 树重建 step 切片；同 task_key 跨臂配对；从快照恢复会话/环境、注入受控故障、重放至终止、取"首个分歧 span"为根因候选；每批注入跑阳/阴对照，不达标整批伪标注作废。
- **提案形成**：规则引擎产不可被模型推翻的机器判定链；异源归因模型只读三个切片（step 切片/注入点前后 diff/错误聚合表）写固定 JSON 模板（含 MAST 三大类失败模式标签，未覆盖强制入 other 并触发分类学扩展评审）；人每周裁 30 条 + 维护 50 条人工上界集。
- **应用流程**：评审关（修复 PR 附复现脚本 + 人机双签，diff 只准动归因指向的层）→ 回归关（不可变回归集 + 冻结回放集降幅 >1pp 拒）→ canary 5%×3 天（任一恶化 >2σ 自动回滚）→ git revert 回滚 → 被拒提案永久留痕 → (strategy_id × bucket) 分离统计。
- **承诺价值**（未经验证）：反事实回放归因的 step 精确命中率比 LLM-judge 直接归因高 ≥15pp（bootstrap CI 不含 0），agent 命中率不低于对照 0.9 倍，归因后定向修复挽回率高 ≥5pp。
- **证据**：[AgenTracer（arXiv 2509.03312）](https://arxiv.org/abs/2509.03312)（核实：SOTA 推理 LLM 长轨迹归因准确率普遍 <10%；但其被验证形态是**用伪标注训练 8B 小模型**，非推理期直接读 diff）；[Who&When（arXiv 2505.00212）](https://arxiv.org/abs/2505.00212)（53.5%/14.2% 与摘要逐字一致；本地 184 条标签分布实跑吻合；**"ICML 2025 openreview"出处 Step-5 未核实到、只见 CoRR 记录——refuted**）；[AgentDebug（arXiv 2509.25370）](https://arxiv.org/abs/2509.25370)（核实）；[AgentDebugX（arXiv 2607.18754）](https://arxiv.org/abs/2607.18754)（核实）；[MAST（arXiv 2503.13657）](https://arxiv.org/abs/2503.13657)（核实）。
- **双评委结论**：
  - **Kimi 评委：45 分，partly**。**测试无法证伪**：H1 要在无 GT 的生产失败 trace 上算命中率，但只给 C 臂 50 条人标——要么用 B 自己的伪标签当金标（循环论证），要么用注入位置当金标而 B 恰在同一注入空间里搜索（结构占优），两种情况下 ≥15pp 都不可证伪；文献只支撑"机制存在且有用"，不支撑推理期 +15pp；四篇证据全来自多 agent 设定，迁移到单 agent bash harness 未验证；容器内状态快照/恢复的工程量明显低估。
  - **Step-5 评委：63 分，confirmed**。证据本身全核实；但**标签泄漏构造性满足**：金标（注入位置）落库、且归因模型的输入之二就是"注入点前后的 span diff"——答案在输入里，H1 测的是"能否找到被告知的注入点"而非"能否归因原始失败"；人标 C 臂 n=50 使去相关检验不可判定，且规则③把"超过人类上限"这一泄漏红灯误释为"接近上限"；单 agent 域 mistake_agent 指标退化、H2 形同虚设；缺同时段重放对照（重放期"恢复"可能只是基建改善）。
- **最终建议：test-first，排最后**。前置修正（采纳两评委替代方案）：先在 [Who&When](https://arxiv.org/abs/2505.00212) 现成 184 条金标上离线比较归因方法；A' 臂直接用现成的 AgenTracer-8B；SWE-V 场景改用**补丁级反事实**（按 hunk 消融/回退 agent.diff + 官方判分脚本重判 f2p）替代会话级状态快照——便宜一个量级且有真判定。

## 5. 并行测试设计要点（可直接照办的协议骨架）

> **再次声明：以下假设全部未经验证，判定规则是预登记的证伪条件，不是预期结论。**

### 5.1 所有策略共用的协议骨架

1. **版本冻结入账**：判分二进制 sha256、镜像 digest、题集快照、prompt/skill pack、judge spec。A/B 两组判分二进制 sha256 不同 → 该轮作废。
2. **配对与执行纪律**：同 task_key 配对、同题集、温度 0、同 scaffold、同判分二进制；**同日交错执行**（防 429 风暴等时段性供应商噪声）；结果目录代际隔离，禁止覆写。
3. **主指标**：确定性判分（reward 与 f2p 连续量）为主指标，LLM rubric 只作次指标；首过率与最终通过率分列（防重试洗白）。
4. **功效预登记**（本次撰写会话 python3 复算，假设：配对设计、每题单次 p=0.5、组间按题配对相关 0.5；McNemar 用翻转率 0.20 的精确近似）：
   - 每题 k 次重复配对设计的 MDE：n=120 时 k=1→**12.8pp**、k=3→**7.4pp**、k=5→**5.7pp**、k=10→**4.0pp**；n=250/k=3→**5.1pp**；n=500/k=3→**3.6pp**。（与策略自报值逐项一致。）修订补算：**n=120×k=7→4.8pp**、**n=300×k=3→4.7pp**——题库仅 120 题，n≥250 的行须先扩池才存在。
   - 配对 McNemar（n=120、翻转率 0.20、单侧 α=0.05）：5pp 功效 0.27、10pp 0.77、12.5pp 0.93；5pp 达 0.80 功效约需 n≈500（策略自报 0.23/0.69/0.86、n≥630——比本次复算更保守，方向一致，**采信保守值**）。
   - 两独立比例（S6 口径）：Δ=5pp 需约 **1560/臂**、Δ=3pp 需约 **4350/臂**；n=60/臂时 MDE≈**24pp**、n=2000/臂时 ≈**4.4pp**。
5. **undecidable 桶**：CI 含 0 或功效不达标 → 记"未判定"，扩样本重判；**"未判定"≠"无效"**；禁止事后挑子集收敛，禁止把 undecidable 当失败（会系统性淘汰慢见效的真实改进）。
6. **分母纪律**：infra/timeout 类 error_trials 单列不计入分母；两臂 error_trials 占比差 >5pp 该比较作废重采。**依据更正（初版把 10.3pp 归因写错，审读意见指出）**：+10.3pp 是 fix1 step-5 在 78 行配对集上干净重判的净增（42/78→50/78，机制为 F→T 翻转与污染判分），**不是**"null 计负"；null 计负的真实量级见判分污染复核-裁决.md 的分母口径对照——同一批数据在"共同已判集"分母下与对照差距 11.4pp，在"未判=负"分母下为 30.0pp：**分母选择本身可摆动结论约 19pp，这才是分母纪律的实证动机**（档案与时点见 §1.1）。
7. **泄漏与循环检查**：优化集/评估集题号哈希零交集（每轮 A/B 前跑交集检查，违例作废）；judge/reflector/打标模型与被测模型异族；人标盲（不可见隐式标签与臂身份）；**金标不得来自被测策略自身产物**。
8. **可复算**：每个上报数字带可重跑命令；异族代理盲跑复现；结论因 regrade 翻转须发更正并登记变更日志。

### 5.3 墙钟与排期算式（修订新增，回答"要跑多少天"）

**算式：天数 = run 数 × 单 run 墙钟(s) ÷（可用并发 × 86400）**。输入取看板时点读数：fix1 各臂单 run 墙钟 0.87–1.51 Ms（约 15–25 分钟，中值取 1200 s）；满负荷并发 17（anolis 14 + local 3，仅当不与主线共用时成立）。

| 计算 | run 数 | 满负荷天数（中值输入） | 说明 |
|---|---|---|---|
| S6 全套（策略原错误数） | 112,000 | **≈91.5 天** | Kimi 评委"约 90 天"的精确来源——run 数本身含 14× 乘法错误 |
| S6 全套（更正后） | 8,000 | **≈6.5 天** | Step-5 评委"6.5 天"的精确来源；两人分歧由此完全解释，与并发假设无关 |
| S2 选项②（k=5，2 组） | 1,200 | ≈1.0 天（按 0.87–1.51 Ms 输入为 0.71–1.23 天） | 产线共用按 50% 折算 ≈1.4–2.5 天 |
| S2 选项①（k=7，2 组） | 1,680 | ≈1.4 天（区间 1.00–1.73 天） | 产线共用按 50% 折算 ≈2–3.5 天 |

三点注意：①以上是纯算力墙钟，未含判分容器排队、429 风暴停等与"同日交错"纪律的强制空闲；②**"90 天 vs 6.5 天"都不是 S2 的排期依据**——它们对应 S6 全套验证的 run 数，S2 按 1,200–1,680 run 口径排期（1–2 天满负荷）；③产线共用比例是运营决策输入，本文给算式不给拍板。

## 6. 落选但值得关注的方向

8 条策略无一被判"证据造假"或整体否决（最低分 S1 也获 test-first），**但 S5 的完整方案被 Kimi 评审判 deprioritize 且本报告采纳为最终建议——这是降级，不是通过**。本节列被否决/降级的**局部主张**、评委指出的 **refuted/unverified 证据**（如实标注，不作美化），以及值得单独立项的替代方向。

**被评委否决或降级的局部主张：**
- **S1 的会话级状态快照重放**：工程量被低估、单 agent 域 mistake_agent 指标退化、金标循环——改为补丁级反事实（hunk 消融 + 官方重判）后再议。
- **S5 的隐式反馈 AUC 主张**：本地信号链为空（单工具 bash 无权限交互），完整方案 deprioritize；方法论子集（随机保底+盲标）保留。
- **S8 的"≥2 倍"硬阈值与判分 oracle 反馈**：前者与公平性控制矛盾、后者是隐藏测试泄漏——均不进预登记。

- [JudgeBench（arXiv 2410.12784）](https://arxiv.org/abs/2410.12784)：用客观正确性金标测评估器——SWE-V 线应直接用 reward/f2p 当金标校准评委，不必另做人标集。
- 序贯/随时有效检验（SPRT 一线）：小样本、跨批次累积证据、peeking-safe——缓解本地题库与失败流都太小的问题（两评委均提）。
- [AgentDebugX 开源工具包](https://arxiv.org/abs/2607.18754)：已工程化的 Detect→Attribute→Recover→Rerun 闭环，作 S8 的 C 臂可直接省 3–5 人周自建。
- [SWE-rebench](https://swe-rebench.com)：已工程化的持续去污染任务源，可替代 S7 自建管线的大部分工作。
- 本地词表升级：把 af-harness 的 stop policy/gate 记账改造成 tool_decision 式事件（decision/source 闭集 + 版本标记）——S5 在本地启动的先决条件。
