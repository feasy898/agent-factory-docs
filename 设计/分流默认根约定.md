## 2. /tmp 白名单（AGENT.md 硬纪律 7 同文）

/tmp（tmpfs 7.5G+usrquota）只允许三类：
1. **工厂运行时件**：调度器三件套/图（/tmp/factory*）、mcode-dispatch state 与
   heartbeat、/tmp/swev-s1 任务包、判分中间件、日志——由三道闸守护（factory-sched
   tmpfs_gate <2252MiB 拦新臂、mcode-dispatch probe_tmpfs <2.2G 拦新判分、watch A4L
   <2662MiB amber 告警）；
2. **在跑臂 out**：/tmp/bench-*（产线结果，P1-4 归档器上线前的唯一落点，只读纪律
   见各研究组地图）；
3. **<50MB 短命件**：探针、快照临时目录、单测沙箱——用完即删。

四类之外（构建 target、工作树、观测数据、归档、任何 GB 级产物）一律落 §1 默认根；
写进 /tmp 即违约——03:34 事故的爆炸半径（afbuild-obs 848M 等）正属此类。

## 3. worktree 规程

- **既有 /tmp 工作树续用至分支收口，不强迁**（在飞不动）：`git -C af worktree list`
  现役 3 个 /tmp 树——/tmp/af-wt-align-r2（fix4-align-r2@936fa48）、
  /tmp/af-wt-align2（fix4-align2@0dd1a23）、/tmp/af-wt-obs（fix4-observability@d73338e），
  均稀疏检出 3.5-5.1M；`git -C af worktree list --porcelain` 实测**无一加锁**，
  move 通道可用。
- **空闲腾挪用 move**（保分支链接）：`git -C af worktree move /tmp/af-wt-<名> ~/workspace/af-wt-<名>`。
  move 只改注册路径，分支检出关系与 gitfile 不变——机械验证（一次性迷你仓，
  已清理）：move 后 `worktree list` 仍显示 `[feat-x]`、.git gitfile 指向同一管理目录。
- **严禁对已检出分支再 add**：`git worktree add <路径> -b <分支>` 对已存在分支报
  `fatal: 一个名为 'X' 的分支已经存在`；`git worktree add <路径> <已检出分支>` 报
  already checked out 拒绝——两种形态实测均**不创建目录**（空跑即败）。新工作树
  一律用未被任何树检出的新分支名，或先收口旧分支。
- **回滚一行 = move 反向**：`git -C af worktree move ~/workspace/af-wt-<名> /tmp/af-wt-<名>`。
- 迁移后构建注意：cargo target 不随树走，本就独立在 `~/afbuild-<名>`——构建一律
  `cargo build --target-dir ~/afbuild-<名>` 显式指定，绝不落回树内或 /tmp。
