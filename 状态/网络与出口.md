| 开机自启 | `~/.config/systemd/user/mihomo.service`（enabled） |

**2026-10-21 实测结论：订阅已恢复，可用。** 排查过程与结论：

- 最初症状：39 节点中 12 死、27 标 alive 但真实出网全 000/502。根因有二：①占着 7890/9090 的是 07:27 手工 `nohup` 起的**游离进程**（systemd 报 inactive），它的出口停在 README 标注不稳定的"香港家宽"线；②被它挡住的 `systemctl --user start` 全部静默失败。
- 处置：终止游离进程，改由 systemd 统一托管（`kill` 旧 pid → `systemctl --user start`，MainPID 1977094），强制全节点健康检查后 **35/39 存活**，切 `AUTO-港美` 组。
- 恢复后实测：`ip-api` → 香港 `103.17.98.26`（ISP Suibian Network LLC）；github / google / huggingface 全 200；`api.x.ai` 421（缺 key 的正常响应=可达）；`registry-1.docker.io/v2` 401（未带认证的正常响应=可达）；三次连续 github 请求 200，耗时 1.18–1.20s 稳定。
- **桌面系统代理未改动**（GNOME mode 仍为 `none`，未执行 `proxy-on.sh`），只有显式指向 `127.0.0.1:7890` 的程序走隧道。

**两个运维坑（已踩）**：
1. `config.yaml` 是 `allow-lan: false`，**只服务 127.0.0.1**。要让 anolis 用上它，必须改 `allow-lan` + 绑 tailnet 地址并自建访问控制，否则等于把个人订阅敞给整个 tailnet。
2. **systemd 与实际运行状态可能不一致**：2026-10-21 排查时发现 systemd 报 `inactive`，但有一个 07:27 由手工 `nohup` 起的游离进程占着 7890/9090，导致任何 `systemctl --user start` 都静默绑不上端口、流量却仍走旧进程。排查前先 `ss -tlnp | grep -E "7890|9090"` 确认端口归属。**该坑已消解**：2026-10-21 已终止游离进程，代理现由 systemd 唯一托管（开机自启 enabled）。
