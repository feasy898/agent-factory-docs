## 二、MiniMax 通道（已闭环验证）

### 端点与凭证
- 模型调用：`https://agent.minimaxi.com/mavis/api/v1/llm/v1/messages`，Anthropic Messages 协议，`Authorization: Bearer <accessToken>` + `User-Agent: MiniMaxCode`（UA 实测可任意）。
- OAuth 凭证：`anolis:~/.minimax/auth/prod/cn/mcode-public/auth.json`（accessToken 60 字符 mmoat_ 前缀，1 小时有效；refreshToken mmort_ 前缀，刷新时双 token 一起轮换）。
- **续期（抓包实证，非文档）**：`POST https://account.minimax.cn/oauth2/token`，form 体 `grant_type=refresh_token&refresh_token=<RT>&client_id=mcode-public` → 新双 token。已固化为 `tools/mcode-token.py`（get/refresh/expiry 三命令，剩余 <10 分钟自动刷新，明文只进管道）。
- 用量查询：`GET https://www.minimaxi.com/v1/api/openplatform/coding_plan/remains`，Bearer + 任意 UA 即可（无需签名）。返回 5 小时窗/周窗的 remaining_percent 与 usage_count。

### 免费实测证据（2026-10-20 01:19-01:45，anolis）
| 时间 | 调用 | 结果 |
|---|---|---|
| 01:19 B0 | 基线读数 | general 5h=99% 周=73% iu=0 wu=0 |
| 01:19 | mavis+mcode UA，m3.1flash，4000 output tokens | B1 读数无变化 |
| 01:20 | mavis+**通用 curl UA**，m3.1flash，3999 output tokens | B2 读数无变化 → **客户端识别不参与** |
| 01:25 | mavis+mcode UA，**MiniMax-M3**，1168 output tokens | M1 读数无变化 |
| 01:45 | 延迟 20 分钟复核 | 仍 iu=0/wu=0（video 条目有计数 iu=5/wu=35 → 计数器本身工作正常） |

解读：文本模型经 mavis+OAuth 不计任何可见配额（m3.1flash 确认免费；M3 小额测试也未入账，但 M3 的 5 小时窗限制仍需尊重）。用户此前"别的 harness 调用也收费"的观察，来源应是别的 harness 走 `api.minimaxi.com/anthropic` + sk-cp API key 的计费路径——**路径不同，不是客户端识别**。

### 签名请求体系（已逆向，备用）
账户类接口（user/info、matrix/* 等）需要完整签名：query 带 device_platform=mcode&biz_id=3&app_id=3001&version_code=22201&unix=<毫秒>&timezone_offset=28800&sys_language=zh&lang=zh&device_id=0&os_name=linux&browser_name=mcode&user_id=<id>&client=mcode；头 `yy=md5(encodeURIComponent(path?query)+"_"+body-or-"{}"+md5(str(nowMs))+"ooui")`、`x-timestamp=<秒>`、`x-signature=md5(<秒>+"I*7Cf%WZ#S&%1RlZJ&C2"+body)`。**公式已与真实抓包样本逐字节核对一致**。realUserID=557003364180488194。模型调用与 remains 查询不需要签名。

## 三、GLM 通道（机制已定位，终验进行中）

### zcode 的真实调用路径（运行时配置实证）
`~/.zcode/v2/runtime/provider/linux-x86_64/*/endpoint-*/zcode-builtin.json`：
- `bigmodel-api` 模板（= BigModel Coding Plan，本账户唯一 entitled 的 plan）：`https://open.bigmodel.cn/api/anthropic`，anthropic-messages，access=zhipu-coding-plan-api-key，模型 GLM-5.3 / GLM-5.3-Flash。
- `bigmodel-standard-api`（普通按量 key）：`https://open.bigmodel.cn/api/paas/v4`。
- CodingPlan key 存放：openBao `kv/company/LLM-upstream/Zhipu/zhipu-bigmodel-CodingPlan-1`（字段 api_key/base_url）。credentials.json 里的两把旧 key 已失效（401），勿用。

### 用量统计 API（GUI"个人套餐"同源，直接可查）
Base：`https://open.bigmodel.cn/api/monitor`（bigmodel.cn 同路径亦可），`Authorization: Bearer <CodingPlan key>`：
- `GET /usage/quota/limit` → 配额快照：5 小时池 28000 积分、周池 140000 积分（level=max），currentValue/remaining/nextResetTime。
- `GET /credit-usage/activity?type=1&startTime=...&endTime=...` → 按日汇总：totalCredits（4 位小数）、totalTokens、mcpCalls。
- 2026-10-20 基线（全部来自 zcode，含折扣）：**249.4412 积分 / 7,424,974 tokens**。

### 终验（2026-10-20 02:23 闭环）：与 zcode 同池同率
- 隔离直调（anthropic 路径，当时唯一在途 GLM 消耗）：25 输入（无缓存）+1500 输出 = 1525 tokens，入账 **Δ0.6028 积分、Δ1525 tokens**（逐 token 对齐）。
- 按刊例价（输入 ¥0.8/M、输出 ¥2.8/M，发布 5 折已结束）应为 ¥0.00422 → 隐含 **¥0.0070/积分**；即直调按刊例计费、无附加、无惩罚。
- 同日 zcode 侧 249.44 积分/7.42M tokens（混合缓存流量）反推 ≈¥0.235/M，与刊例组成一致 → **zcode 与直调同池同率**；"2/3 折"是套餐积分价相对按量现金价的结构性优惠，随 key+端点走，自研 harness 照用即享。
- 旁证异常：`/api/paas/v4` 路径用同一 key 的 3 次调用（4080 tokens）40+ 分钟未入账——该路径疑似不计费，但其非 zcode 官方路径，harness 统一走 anthropic 路径，不用此异常。
- 用量 API 延迟特征：计费管道 10-15 分钟批量入账，日汇总接口实时性差，做差分实验必须隔离在途消耗。
